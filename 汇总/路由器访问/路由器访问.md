# 路由器访问 · LuCI 页面开发提示词

> 本文档是 openNDS LuCI 插件中「路由器访问」页面的完整开发规格。同目录 `路由器访问.html` 是**界面事实源**：界面形态（有哪些控件、按钮、文案怎么写）以它为准；功能行为、数据来源、边界条件、异常处理以本文档为准，演示里的模拟数据不代表真实取值。

## 1. 任务总述与页面定位

开发「路由器访问」页面，管理 openNDS 唯一一组「客户端能访问路由器哪些服务」的配置，包含两个功能：

1. **接管**：单个复选框，落 `users_to_router_passthrough`。
2. **开放端口**：维护 `list users_to_router` 列表，界面用一套简写语法输入，落盘时展开成 openNDS 原生规则。

**语义（必须写进代码注释，也是界面文案的依据）**

| 取值 | 行为 |
|---|---|
| 未设置 / `0` | 默认。openNDS 用自己 nftables 链（`ndsRTR`）裁决客户端→路由器的访问，链末尾是 `reject`，只放行内置 essentials + 列表条目 |
| `1` | 「关闭接管」。规则不再由 openNDS 裁决，最终判定交给系统防火墙 fw4 |

上游原文（`docs/source/config_access.rst` L193–215 / 渲染页 `config_access.html#users-to-router-passthrough`）：

> By default the user to router access rules are **not** passed through to the system firewall for additional processing.
> **WARNING**: Do not enable unless you know what you are doing. *Enabling passthrough may well soft brick your router, particularly if openNDS is bound to a guest network.*

**内置 essentials（代码写死，不可删、不可改）**：`allow udp port 53`、`allow udp port 67`、`allow tcp port 22`、`allow tcp port 443`。
`libopennds.sh:1779` 把这四条强制拼在规则集最前，用户重复填写会被去重。注意 DNS 只内置了 **udp 53**，没有 tcp 53。
**本页界面不展示这 4 条**（决策 #11）：它们由 openNDS 无条件放行，没有展示、开关或删除的意义。

**本页直接改 openNDS 原生配置 `/etc/config/opennds`**（插件里另有豁免页写 `trustedmac`/`preemptivemac`、WalledGarden 页写 `preauthenticated_users` 等、区域识别页写 `login_option_enabled`/`themespec_path`，四页各管各的键，见 §6 集成说明）。本页只允许碰 `opennds.@opennds[0]` 的两个键：`users_to_router_passthrough`、`users_to_router`。**不得**新建 section、不得重写整个 `/etc/config/opennds` 文件。

**交付文件**：

```
htdocs/luci-static/resources/view/opennds_cpd/router.js   # 本页 JS 视图
usr/lib/opennds/opennds-cpd-api.sh                          # 全插件唯一后端脚本（rpcd file.exec，输出 JSON）
```

## 2. 已确认决策表（不要再问，直接照做）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 配置位置 | 直接写 `/etc/config/opennds` 的 `@opennds[0]`，**不**新建插件自有 config |
| 2 | 接管 ↔ uci 映射 | 未勾选「关闭接管」→ `users_to_router_passthrough='0'`；勾选 → `'1'`。**显式写值**（不删 option）；读取时 option 缺失按 `0` 处理 |
| 3 | 交互粒度 | 勾选/取消勾选**只是界面选择**，不写任何配置；端口编辑器里的「保存」也只改前端状态。**只有底部「应用」**才写配置文件并重启 openNDS |
| 4 | 端口输入语法 | 简写三形态（见 §5.1）：`端口` / `协议 端口` / `IP`。**`端口 IP`、`协议 端口 IP` 一律拒绝**——源码把 `from` 后面的端口当成**源端口**（§5.2 实测），这种条目放行的不是用户想开的那个目的端口 |
| 5 | 裸端口 | `4433` 由**插件**展开成 `allow tcp port 4433` + `allow udp port 4433` 再写 uci。**绝不能把裸端口原样写进 uci**：openNDS 解析时 `proto` 为空会把 `portnum` 一起清掉，最终生成一条没有任何匹配条件的 `counter accept`，等于对路由器**全部端口全放行**（含 LuCI 80、SSH 22） |
| 6 | 协议位 | 只认 `tcp` / `udp`（大小写不敏感）。占位符里的 `tcp/udp 4267` 是**说明性写法**，意思是"想给端口带 tcp 就写 `tcp 4267`，想带 udp 就写 `udp 4267`"，它不是可输入语法；用户真写了 `tcp/udp …` → 报格式错误 |
| 7 | 端口范围 / CIDR / IPv6 | **不做**。`2000-2026` 按格式错误拒绝（决策记录：曾讨论展开方案，最终放弃） |
| 8 | 条数上限 | **不设阈值**。无范围语法后 1 行最多展开 2 条，条数天然由输入长度约束；仅保留 §6.1 的 64KB 传输上限作安全兜底 |
| 9 | 展示内容 | 本会话内显示**用户原文**（逐行原样，不排序、不归一化）；**重新打开页面**时显示由 uci 反解析生成的文本（反解析做折叠，见 §5.5）。前者是"写什么显示什么"，后者保证刷新后看到的是真实生效配置 |
| 10 | 数据存储 | **唯一数据源是 `/etc/config/opennds` 的 `list users_to_router`**。不另存原文、不建 `.portal_map` 之类的旁挂文件：避免用户在 SSH 或别处改配置后本页显示与实际不一致 |
| 11 | 内置 essentials | **界面不展示**。用户输入与内置 4 条完全相同的条目 → **静默丢弃**，不写入 uci，不报错 |
| 12 | 反解析不出来的条目 | **不做「保留规则」只读块**。原样作为一行放进文本框显示；用户点「保存」或「应用」时按格式错误整次拒绝，提示「第 N 行格式不正确」，由用户决定删掉还是改对 |
| 13 | 非法行 | **整次拒绝**：任何一行不合法则本次保存/应用失败，toast 指出「第 N 行：原因」并把光标定位到该行；不落任何部分结果 |
| 14 | 关闭接管的确认 | **不弹二次确认**。勾选本身无副作用，不点「应用」什么都不发生；靠 §3.2 的 note 提示即可 |
| 15 | 接管 ↔ 端口区 | **不联动**（不置灰、不禁用、不加警示条）。配置注释只有"不传给系统防火墙"一句间接依据，未直说列表失效，界面不擅自表态 |
| 16 | 保存粒度 | 编辑器内「保存」只改前端状态（回展示态）；**只有底部「应用」才写 uci 并重启** |
| 17 | 「应用」语义 | 写 uci → `uci commit opennds` → `/etc/init.d/opennds restart`。与其它页面一致。⚠️ 若 openNDS 处于停用状态（`enabled=0`），先按《整包集成与打包.md》§11.1 弹确认，确认后再顺手 `enabled=1` 并重启 |

## 5. 解析 / 生成规格（本页核心，必须严格照做）

### 5.1 输入语法（逐行；大小写不敏感；多个空格/Tab 视为一个分隔符）

```
line  := port                   # 裸端口（= tcp + udp）   例：4433
       | proto SP port          # 显式协议             例：tcp 3389 / udp 2653
       | ip                     # 整机放行             例：192.168.1.1
proto := "tcp" | "udp"
port  := 1..65535 的十进制整数（去前导零后比较）
ip    := 点分四段 IPv4，每段 0..255
```

- **不写协议 = tcp + udp 都要**。
- 明确**不支持**：`tcp/udp`（占位符只是说明性写法）、`tcp+udp`、`both`、`all`、端口段（`8000-8100`）、CIDR（`192.168.1.0/24`）、IPv6、多端口一行（`tcp 443 445`）。
- 明确**不支持「端口 + IP」组合**（`4433 192.168.1.1`、`tcp 3654 192.168.1.1`）：演示占位符里有这一行，但源码 `create_client_ruleset()` 在 `to_from="from"` 分支里把端口映射成 **`sport`**，实际生成的是 `ip saddr <IP> tcp sport <端口>`——匹配源端口而不是目的端口，用户想开的端口根本没开。插件侧必须直接拒绝这种输入，**不许**照演示示例收下再写入（它会变成一个看似成功、实际无效的条目）。要限定某台设备，只写 IP（`allow all from <IP>`，全端口）；要限端口，只写端口/`协议 端口`（对所有客户端生效）。
- 空行忽略；行首尾空白 trim；`\r\n` 与 `\n` 都接受；行尾多余空格不报错。
- 全角空格、全角数字视为非法字符，报格式错误（不做静默转换）。

### 5.2 展开规则（简写 → uci 条目）

| 输入 | 展开 |
|---|---|
| `4433` | `allow tcp port 4433` + `allow udp port 4433` |
| `tcp 3389` | `allow tcp port 3389` |
| `udp 2653` | `allow udp port 2653` |
| `192.168.1.1` | `allow all from 192.168.1.1` |

> **两条红线**（都是 `create_client_ruleset()` 的实际行为，已用解析模拟验证）：
> 1. **裸端口/无协议条目绝不能写进 uci**：`allow 4433`、`allow port 4433` 解析出的 `proto` 为空，
>    随后的清理分支把 `portnum` 一并清空，最终 `nft add rule ip nds_filter ndsRTR counter accept`——
>    没有任何匹配条件，**所有客户端到路由器的所有端口全放行**。插件只写带 `tcp`/`udp`
>    的端口条目，或带明确目标的 `allow all from <IP>`（它有 `ip saddr`，不是全放行）；
>    绝不写裸端口。
> 2. **带 `from` 的端口条目不要写**：`allow tcp port 30000 from 192.168.1.11` 生成
>    `ip saddr 192.168.1.11 tcp sport 30000`，匹配的是源端口。虽然上游配置注释里就有这行示例，
>    但它并不实现"只放行该 IP 的目的端口 30000"。

顺序：按输入行顺序写入 uci list（`uci add_list` 的追加顺序即规则顺序，openNDS 按 list 顺序建链）；一行展开多条时，tcp 在 udp 前。

> `allow all from IP` 是**该 IP 全协议全端口**直达路由器（含 LUCI、SSH 及任何监听服务），比端口行宽得多。上游配置注释里有此示例、`create_client_ruleset()` 也支持，但**官方文档正文未收录**，属 undocumented 写法，升级 openNDS 时需回归验证。

### 5.3 校验与错误文案（整次拒绝，返回全部错误行，前端展示第一条并定位）

| 情况 | 提示（拼成「第 N 行：…」） |
|---|---|
| 分词结果不是 1 / 2 / 3 段，或段位无法识别 | 「格式不正确，支持 `端口`、`协议 端口`、`IP`」 |
| 端口后又跟了 IP（`4433 192.168.1.1`、`tcp 3654 192.168.1.1`） | 「暂不支持同时限定端口和来源 IP：要限定设备请只写 IP，要限定端口请只写端口」 |
| 首段是协议名但缺端口 | 「`tcp` / `udp` 后必须跟端口号」 |
| 协议不认识（`tcp/udp`、`all`、`both`、`TCP+UDP`…） | 「协议只能是 tcp 或 udp；两个协议都要请直接写端口号」 |
| 端口非纯数字 | 「端口必须是数字」 |
| 端口越界（`0`、`70000`） | 「端口必须在 1-65535 之间」 |
| 带范围（`2000-2026`） | 「不支持端口范围，请写单个端口」 |
| IP 段数/数值非法 | 「IP 地址格式不正确」 |
| 该行展开后全部与内置 essentials 重复 | 不是错误 → 静默丢弃（§5.4） |
| 端口与内置端口的**前缀**相同（`tcp 2` / `tcp 4` / `tcp 44` / `udp 5` / `udp 6`） | 「端口 N 是内置放行端口（443/22/53/67）的前缀，openNDS 去重时会把它当成重复条目丢掉，请改用其它端口」 |

### 5.4 去重与 essentials 过滤

- 展开后的规则字符串**完全等于**内置 4 条之一（`allow udp port 53` / `allow udp port 67` / `allow tcp port 22` / `allow tcp port 443`）→ 丢弃，不写 uci，不提示。
  - 例：`tcp 22` → 丢弃；`443` → `allow tcp port 443` 丢弃、`allow udp port 443` 保留（回读后显示为 `udp 443`，属预期行为，见 §5.5 说明）。
- 展开结果之间重复 → 保留首次出现，后面丢弃。
- **不要**做子串/模糊去重（openNDS 自身用 `grep` 子串去重，存在 `allow udp port 5` 被 `allow udp port 53` 误吞的历史行为）；本页只做精确匹配。
- ⚠️ **子串误吞会在 openNDS 那侧发生，插件拦不住，只能提前拒绝**：`create_client_ruleset()` 的去重是
  `echo "$essentials" | grep "$rule"`，pattern 是整条规则。于是端口号只要是内置端口的**前缀**，
  这条规则就会被当成重复而丢掉（已实测）：`tcp 2`、`tcp 4`、`tcp 44`、`udp 5`、`udp 6` 写进 uci 后
  在 `ndsRTR` 链里根本不会出现，用户看到"保存成功、端口没开"。所以 validate 阶段对
  `tcp 2 / tcp 4 / tcp 44 / udp 5 / udp 6` 直接报错（文案见 §5.3），不要静默写进去。

### 5.5 反解析（uci 原生条目 → 简写，用于页面首次加载）

按 uci list 顺序处理每条值（先 trim），逐条判断：

1. 等于内置 4 条之一 → **丢弃**（由 openNDS 无条件放行，界面不展示）。
2. `allow tcp port N` → 记作 (tcp, N)；`allow udp port N` → 记作 (udp, N)。**带 `from` 的端口条目不算在内**，走第 5 条。
3. `allow all from IP` → 输出一行 `IP`。
4. **折叠**：同端口、都无 IP 的 tcp 与 udp 两条 → 合并成**裸端口**写法，占二者中先出现那条的位置（`tcp N` + `udp N` → `N`）；只有单协议则输出 `tcp N` / `udp N`。
5. 其它任何写法（`block …`、`passthrough …`、`allow all` 无 from、带 `to`、**带 `from` 的端口条目**、端口段、CIDR 等）→ **原样作为一行文本输出**（决策 #12：不丢、不拦，用户保存时会被 §5.3 判为格式错误；带 `from` 的端口条目就是"暂不支持同时限定端口和来源 IP"）。

**折叠的语义依据**：裸端口与"tcp+udp 两条"是同一个意思，所以 `4267` 存进去两条、读出来还是 `4267`，往返稳定。用户写 `tcp 4267` + `udp 4267` 两行，刷新后会合并成 `4267` 一行——这是同一含义的规范写法，不算篡改输入。

**示例（本机现状）**：`allow tcp port 7892`、`allow tcp port 80` → 文本框显示
```
tcp 7892
tcp 80
```

### 5.6 应用时的写回

```
新 list = 按行展开(用户原文，已通过校验) 依次 add_list
```

- 先 `uci delete opennds.@opennds[0].users_to_router`，再逐条 `uci add_list opennds.@opennds[0].users_to_router='<规则>'`。
- **禁止**用 `uci set opennds.@opennds[0].users_to_router='...'` 一把写（会把 list 降级成单值，静默丢规则）。
- `users_to_router_passthrough` 始终显式写 `0` / `1`。
- 最后 `uci commit opennds`。

## 6. 后端 API 约定（`opennds-cpd-api.sh router …`）

rpcd `file.exec` 调用，调用形式 `opennds-cpd-api.sh router <子命令> [参数…]`（本页 page 名固定为 `router`）；stdout 只输出 JSON（日志走 stderr / `logger`）；错误统一 `{"ok":0,"error":"…"}`（信封见《整包集成与打包.md》§12）。

| 子命令 | 参数 | 返回 | 行为 |
|---|---|---|---|
| `status` | — | `{"ok":1,"enabled":1,"passthrough":0,"text":"tcp 7892\ntcp 80","fw4":1}` | 读 uci + §5.5 反解析；`text` 为多行文本（JSON 内 `\n` 转义） |
| `validate` | `text_b64=<base64(原文)>` | `{"ok":1,"rules":["allow tcp port 4433",…],"count":N}` 或 `{"ok":0,"errors":[{"line":3,"msg":"端口必须在 1-65535 之间"}]}` | §5.1–5.4 全部校验，不写任何东西 |
| `apply` | `text_b64=<base64(原文)> passthrough=<0\|1>`（两个独立参数，不要拼成一个 `a=…&b=…` 的串，口径见《整包集成与打包.md》§12） | `{"ok":1,"restarted":1,"rules":N}` 或带 `"warnings":[…]`（`passthrough=1` 且列表非空时）或 `{"ok":0,"errors":[…]}` 或 `{"ok":0,"error":"…"}` | 先 validate（有错直接返回 errors，不落盘）→ 备份 → 写 uci → commit → 重启 → 校验进程 |

### 6.1 传输编码
textarea 内容可能含换行与中文，**不要**直接塞进 argv。统一前端 `btoa(unescape(encodeURIComponent(text)))` → 后端 `printf '%s' "$v" | base64 -d`（无 `base64` 时依次尝试 `openssl base64 -d`、`uudecode`，都无则 `{"ok":0,"error":"缺少 base64 工具"}`）。
解码后文本长度上限 **64KB**（超出返回 `{"ok":0,"error":"内容过长"}`）——这是传输层安全兜底，不是业务上的条数限制（决策 #8）。

### 6.2 写配置与失败处理
1. `mkdir -p /tmp/zone-router`；按《整包集成与打包.md》§11.3 的模板取锁（`exec 9>锁文件` + `flock -n 9`，**不是** `flock -n /path/to/lock`——那种写法没有持锁进程，锁等于没加），锁的 fd 9 在调用 `ndsctl` / init 脚本时用 `9>&-` 关掉。
2. `cp /etc/config/opennds /tmp/zone-router/opennds.bak`。
3. 写 uci；任一步返回非 0 → **先 `uci revert opennds` 丢掉本次暂存的改动**（`uci set` / `uci delete` 只写进
   `/tmp/.uci` 的增量，`/etc/config/opennds` 此时还没动；不 revert 就去 commit，等于把半成品增量
   重新写回刚还原的文件，回滚白做）→ 再用 `cp /tmp/zone-router/opennds.bak /etc/config/opennds` 把文件放回原位
   （防的是 commit 本身写坏）→ **还原之后不要再 `uci commit`** → `{"ok":0,"error":"写入配置失败，已回滚"}`。
4. `/etc/init.d/opennds restart`；随后最多 15 秒轮询（30 次 × 0.5 秒），**`pidof opennds` 有值且 `ndsctl status` 能成功**才算就绪。
5. 重启失败/未起来 → `{"ok":0,"error":"配置已写入，但 openNDS 未能启动，请检查日志"}`（**不回滚**：回滚可能让用户失去刚配好的规则，且现场要留作排查）。

### 6.3 并发
- 与其它页面共用 `/var/lock/opennds-cpd.lock`：`exec 9>/var/lock/opennds-cpd.lock` + `flock -n 9`（模板见《整包集成与打包.md》§11.3）。
- 抢不到就立即返回 `{"ok":0,"busy":1,"page":"router"}`，前端提示「等待上一步完成，请稍候重试」，**不排队、不阻塞**。另一页正在重启时同样如此——**不允许**改成 `flock -w` 阻塞等待：重启动辄十几秒，浏览器侧会一直挂着没有反馈，用户会反复点击。

### 6.4 环境兼容
- `type fw4` 不存在（fw3/iptables 系统）→ `status` 返回 `"fw4":0`，前端在「开放端口」说明下插一条警告：
  「当前系统未使用 fw4（nftables），openNDS 不支持 users_to_router 规则，本页配置不会生效。」——**仅提示，不禁用**（配置仍可保存）。
- `uci` 不存在或 `opennds` 配置缺失 → `{"ok":0,"error":"未找到 openNDS 配置"}`。
- `opennds.@opennds[0]` 不存在 → 同上错误，**不要**自动创建 section。

## 7. 实现质量要求

- **POSIX sh / busybox**：只用 ash 兼容语法；管道内 `while` 是子 shell（计数/拼串要用 `$(…)` 或临时文件回传）；`$'\n'` 不可用；`tr` 不支持 `\xNN`。
- **端口校验**：先用字符白名单（`case "$p" in *[!0-9]*) …`）再比较大小；**必须先去掉前导零**再按十进制比较，否则 ash 的 `$((0443))` 会当八进制算成 291。
- **安全**：不要 `eval` 拼接用户输入；`add_list` 前对单引号做转义；IP 只允许 `[0-9.]`；`text_b64` 先做长度检查再解码。
- **规范**：所有 `uci` 调用带 `-q` 并逐条判断 `$?`；只碰 `@opennds[0]` 的 `users_to_router` / `users_to_router_passthrough`，不改其它 option，不 `uci reorder` / `uci rename`。
- **冒烟测试清单**（交付前用 uci 桩 + 假 `init.d/opennds` 验证）：
  1. `4433` → `allow tcp port 4433` + `allow udp port 4433`；**断言 uci 里没有任何一条缺 `tcp`/`udp` 的裸端口条目**（那是全放行）；
  2. `tcp 3389` / `udp 2653` 各出一条；
  3. `192.168.1.1` → `allow all from 192.168.1.1`；
  4. `4433 192.168.1.1` / `tcp 3654 192.168.1.1` → **整次拒绝**，提示「暂不支持同时限定端口和来源 IP」；
  5. `tcp 22` / `udp 53` / `443` 中的 tcp 部分被静默丢弃；
  6. `tcp/udp 4267` / `2000-2026` / `tcp 70000` / `1.2.3` / `abc` 全部整次拒绝且 `line` 正确；
  7. 重复行只留一条；`tcp 2` / `tcp 4` / `tcp 44` / `udp 5` / `udp 6` 被 validate 拒绝（openNDS 前缀去重会吞掉它们）；
  8. 空文本 + passthrough=0 → `users_to_router` 被清空、无残留；
  9. 反解析：`allow tcp port 80` → `tcp 80`；`allow all from 1.2.3.4` → `1.2.3.4`；`allow tcp port 4267` + `allow udp port 4267` → `4267`；
  10. 反解析：`block tcp port 80` → 显示原文 → 保存被拒且报该行；历史配置里遗留的 `... from <IP>` 条目同样原文显示、保存时按"暂不支持"拒绝；
  11. uci 写入失败 → 回滚后配置内容与操作前逐字节一致；
  12. 重启后 `pidof opennds` 有值**且** `ndsctl status` 成功才返回 ok（只看 `pidof` 会把刚拉起来就退出的进程当成功）。

## 8. 集成说明（与其它页面合并成完整插件）

1. **rpcd 模式统一**：所有页面后端都是 `file.exec` + JSON；本页沿用同一套 `rc` 包装与错误格式。
2. **菜单 / ACL 合并**：「路由器访问」作为独立菜单项并入 `luci-app-opennds-cpd.json`；ACL 需含 `/etc/config/opennds` 读写、`opennds-cpd-api.sh` exec。锁文件**不需要**单独的 ACL 条目——脚本以 root 身份在内部持有它（《整包集成与打包.md》§4）。另需全包只保留一个后端脚本，本页 page 名为 `router`。
3. **与区域识别页的配置写冲突**：两页都写 `/etc/config/opennds`，但键不重叠（本页 `users_to_router*`，区域识别 `login_option_enabled` / `themespec_path`）。各页各自 apply、各自重启，**不做**全局合并应用，但都用 flock 保证不并发重启。
4. **与豁免 / 黑名单无耦合**：豁免（`trustedmac` / `preemptivemac`）管"跳过认证"，本页管"认证后能不能访问路由器端口"；黑名单管"永不认证"。三套机制互不影响，不写任何跨页钩子。
5. **「应用」语义**：各页点应用 = 写配置 + commit，**是否重启按操作类型决定**（重启会踢掉全站在线客户端）：必须重启的是改全局参数、改已在线客户端的 per-client 限制、**拉黑**（名单变更后要重建 nft 链）；不必重启的是增删 `trustedmac` / `preemptivemac`、门户选择。**本页必须重启**：`users_to_router` 只在启动时用来建 nft 链，运行时不重读。
6. **与分发脚本无关**：本页不影响登录模式 3 的门户选择，`theme_zone_detect.sh` 无需任何改动。
7. **保存/应用 全局红线（防"重启被动生效"漏洞）**：任何页面的「保存」都不得写入会被 openNDS 或分发脚本运行时读取的配置（`/etc/config/opennds`、`zone_blacklist`）。允许写的只有两类：① 纯暂存缓存 `zone_detect`（无运行时读取者，生效完全依赖「应用」阶段的写正式配置动作）；② 前端内存快照（不碰文件）。本页「保存」只改前端状态属 ②，opennds 正式配置只在「应用」写。任何绕过「应用」直接写正式配置的路径都视为实现错误——否则用户保存后未应用就断电/重启，配置会在开机时被动生效。
