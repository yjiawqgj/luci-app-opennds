# 客户端黑名单 · LuCI 页面开发提示词

> 本文档是 openNDS LuCI 插件中「客户端黑名单」页面的完整开发规格。同目录 `客户端黑名单.html` 是**界面事实源**：界面形态（有哪些控件、按钮、文案怎么写）以它为准；功能行为、数据来源、边界条件、异常处理以本文档为准，演示里的模拟数据不代表真实取值。


> 与《区域识别.md》《OpenNDS概览.md》《客户端会话管理.md》《客户端豁免管理.md》同属一个插件包，后续把所有提示词 + 演示 HTML 一起交给开发者整包开发。合并约定见文末「集成说明」。

## 1. 任务总述与页面定位

开发「客户端黑名单」页面，包含两个独立功能：

1. **客户端黑名单**：维护禁止上网的客户端 MAC 名单。被拉黑的客户端**无法通过认证上网**，访问网络时看到的是本页第二区块选择的「黑名单门户」（如"您已被禁止访问"提示页），而不是正常认证门户。
2. **黑名单门户**：管理出示给被拉黑客户端的专用门户脚本——上传、查看已上传、下拉选择、应用。

**关键前提（决定实现方式）**：openNDS **没有**按 MAC 的**持久**黑名单——配置里只有 FQDN/端口维度的 `blocklist_fqdn_list`；9.x 的 `ndsctl block` 只往进程内存里的 blocked 名单加一条并当场插 nft 规则（重启即失效，也不会让分发脚本改出示黑名单门户，10.x 已删除该命令）。因此黑名单由插件自建：

- **拦截机制**：被拉黑 MAC 一律不允许进入已认证状态——应用黑名单时对其已认证会话执行 `ndsctl deauth <mac>` 踢下线，**本次确有新增 MAC 时**再重启 openNDS（可信任客户端的状态机拒绝 deauth，只有重启能把它们清出去；普通客户端 deauth 就够了，不必为了一条新记录让全站掉线）；此后该客户端回到未认证状态，被 openNDS 自身防火墙挡在门外（**除 Walled Garden 放行的目标外**无法上外网，只能触达网关/门户），门户请求由分发脚本出示黑名单门户。**不需要**插件自建 nft 规则（`zone_blacklist` 只被分发脚本读，不产生任何 nft 规则）。
  - ⚠️ **与 Walled Garden 的关系（别写成"彻底断网"）**：`preauthenticated_users` 生成的是 `ndsNET` 链上的 `accept` 规则，它只看"未认证"这个状态，**不看 MAC 在不在黑名单**。所以被拉黑的设备仍能访问 Walled Garden 里放行的域名/端口。拉黑拦的是"认证"和"门户出示"，不是这三层 nft 放行。三套机制互不挂钩（《WalledGarden.md》决策 #5 同口径）。
- **必须做互斥清理（否则整套机制形同虚设）**：拉黑时要把该 MAC 从
  `trustedmac` 和 `preemptivemac` 两个名单里一起摘掉，并 `ndsctl untrust`。
  否则 `trustedmac` 里的客户端 openNDS 直接放行、`preemptivemac` 里的客户端
  接入即自动登录——它们在 `ndsctl` 里根本不会出现在"未认证"状态，
  黑名单就只能拦住"从没被豁免过"的客户端。
- **存储**：插件自有配置 `/etc/config/zone_blacklist`（openNDS 原生配置无处可放）。
- **只在区域模式（`login_option_enabled='3'`）下才生效**：分发脚本是被 themespec 机制调用的，
  如果「区域识别」页把模式切回"全局"（`login_option_enabled='1'`），openNDS 改用自带页面，
  根本不经过我们的脚本。自带页面是 `theme_click-to-continue-basic.sh`——一个"点一下就认证"
  的页面（源码注释原话 `no client validation`），**谁能自己点过去**。所以**全局模式下黑名单
  完全不生效**：拉黑只剩"从 `trustedmac` / `preemptivemac` 摘除 + 当次 `deauth`"这点即时效果，
  客户端点一次 Continue 就有网了。本页不需要为此做特殊处理，但**不要在文案里承诺"拉黑一定
  拦得住"、"一定会显示黑名单门户"**——要承诺就加条件：仅"区域"模式下成立。想在全局模式下
  也真按 MAC 拦住，只能靠系统防火墙之类的外部手段，本插件不提供。

**交付文件**（包名 `luci-app-opennds-cpd`，全插件共用一个后端脚本）：

```
htdocs/luci-static/resources/view/opennds_cpd/blacklist.js   # 本页 JS 视图
usr/lib/opennds/opennds-cpd-api.sh                             # 全插件唯一后端脚本（rpcd file.exec，输出 JSON）
```

## 2. 已确认决策表（不要再问，直接照做）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 黑名单存储 | 插件自有 `/etc/config/zone_blacklist`（`config main 'main'`，`list mac '…'`），openNDS 原生无此能力 |
| 2 | 拦截机制 | 黑名单 MAC 永不认证：应用时 `ndsctl deauth` 踢掉已认证会话；后续由分发脚本在门户请求时识别（见集成说明），不出示区域门户、只出示黑名单门户。不建 nft 规则。**同时必须把该 MAC 从 `trustedmac` / `preemptivemac` 摘掉并 `ndsctl untrust`**——这两个名单的优先级高于黑名单，不清理的话被拉黑的客户端会继续被自动放行 |
| 3 | 黑名单编辑模式 | **前端整份编辑**：点「编辑」进 textarea，预填当前全部内容。但**落盘不是整份重写**——应用时前端算 `add` / `remove` 两个差集交给后端，后端只按 MAC 增删，不动其它条目（规则见《整包集成与打包.md》§11.2）。理由是概览页也会单点拉黑，整份重写会把那边刚加的冲掉 |
| 4 | MAC 校验归一化 | 逐行校验，非法 MAC 拒绝并提示；**存盘统一小写冒号分隔**（与 `trustedmac` / `preemptivemac` 同一口径，见《整包集成与打包.md》§11.4——概览页拉黑也写同一个文件，两边大小写不一致会导致同一条被当成两条）；界面按演示显示大写（展示层转，不影响落盘）；去重按归一化后的值；短横线分隔也接受并转成冒号；空行忽略；**全部为空不发请求**——照演示拦下并提示「请先填写客户端 MAC 地址」，所以本页 UI 不会清空名单（要清空只能逐条删，后端 `clear=1` 只留给接口层显式调用，见 §5） |
| 5 | 黑名单「应用」生效 | 写 uci → 摘两份名单 → 清预认证队列残留 → `ndsctl untrust` / `deauth` → **新增了 MAC 才重启 openNDS**。重启让主进程重新读取 `trustedmac` / `preemptivemac`、重建 nft 链，代价是已认证客户端被 `shutdown_deauth` 踢下线、随后按 `authlog.log` 剩余时长恢复（全站短暂断线，属既定行为）。**只删除（解除拉黑）不重启**：`zone_blacklist` 是分发脚本每次请求现读的，删掉条目门户立刻恢复，重启只会白踢一次全站。⚠️ 若 openNDS 处于停用状态（`enabled=0`），拉黑写进去也不生效，必须先按《整包集成与打包.md》§11.1 弹确认（取消则整单中止） |
| 6 | 门户文件存放 | `/usr/lib/opennds/cpd/blacklist/`，上传的脚本/文件夹直接按原名存放，**不做**区域识别页那套"+1 改名映射"。⚠️ 因为不做改名，门户库里**不要出现名为 `default.sh` 的文件**：分发脚本的查找链在 `<名>.sh` / `<名>/theme.sh` 都落空后，会先取 `<门户库>/default.sh` 再退到 `cpd/default/blacklist/default.sh`——放一个 `default.sh` 进去等于给所有未命中的选择项偷偷换了兜底页。想改兜底请去「openNDS 设置」页的「黑名单」tab 上传类型默认门户。**这条必须由代码兜住，不能只写在文档里**：① 上传时文件名叫 `default.sh` → 拒绝并提示「不能上传名为 default.sh 的脚本，兜底门户请到「openNDS 设置」页的「黑名单」tab 上传」；② 扫描门户列表时**跳过** `default.sh` 与名为 `default` 的文件夹（后者会被查找链的 `""\|default` 分支当成兜底入口，选中等于什么都没选），既不列进下拉框也不进已上传列表 |
| 7 | 门户「应用」 | 把选中的门户写入 `/etc/config/zone_blacklist`（`option portal '文件或文件夹名'`），分发脚本在拉黑客户端请求时按区域识别页相同的查找规则使用它（`<名>.sh` → `<名>/theme.sh` → **`/usr/lib/opennds/cpd/blacklist/default.sh`** → `/usr/lib/opennds/cpd/default/blacklist/default.sh` 回退，中间那一步就是决策 #6 要求库里别放 `default.sh` 的原因）；不重启 openNDS。**「默认门户」这一项就是设置页「黑名单」tab 上传的那份文件**，本页只读它，不负责上传 |
| 8 | 删除门户 | 已上传列表里行内「删除」+ 二次确认；**正在被选中的门户不允许删**：点「删除」时先判断，命中就 toast（warn）「该门户正在使用中，请先在「门户选择」里换一个再删除」并**不发请求**，后端 `portal_delete` 也要拒绝（`{"ok":0,"error":"门户使用中…"}`），前后端同一口径。删其它门户才走确认框「确定删除脚本「xxx」？删除后将从已上传列表中移除。」 |
| 9 | 名称限制 | 上传的文件/文件夹名 ≤ 20 字符，不允许与现有重名 |

## 3. 页面布局（版式与交互照演示，功能与边界按本文档）

### 3.1 页头
- 品牌行「openNDS」+ 面包屑「客户端黑名单」（顶部细分割线）。

### 3.2 客户端黑名单区块
- 标题「客户端黑名单」；下方「添加」按钮（+号图标，`aria-expanded` / `aria-controls` 联动编辑器）。
- **展示态**：标签「黑名单」+ 等宽字体只读块（灰底、内阴影，`aria-live="polite"`），逐行显示已保存 MAC（**渲染时转大写**，与占位符风格一致；文件里存的是小写）；名单为空时这个块**保留、内容为空**（灰底块本身是版式的一部分，不因为没内容就整块隐藏，也不要塞「（空）」之类的占位文字），「添加」按钮始终可用。
- **编辑态**：textarea（rows=3，可拉伸，占位「例如 D8:3A:DD:41:6F:22」，关闭拼写检查），**预填当前已保存内容**；光标自动聚焦并全选；下方「取消」「应用」（primary）。
- **应用**：按行拆分 → trim → 去空 → 校验；全空 → warn toast「请先填写客户端 MAC 地址」并聚焦输入框；否则保存 + toast「已应用黑名单内容」+ 回展示态。
- **取消**：回展示态，不保存，焦点还给「添加」按钮。

### 3.3 门户区块
- 标题「门户」；工具行：「上传」按钮（图标，触发隐藏 file input）+「已上传」按钮。
- **上传**：单文件（只收 `.sh`，**文件名不能是 `default.sh`**，理由见决策 #6）；与已上传列表里某一项同名时 toast（warn）「已存在同名脚本，请改名后再上传」并且**不发请求**（决策 #9：本页不做改名映射，同名会覆盖，所以直接挡在门口）；成功后文件名插入已上传列表头部 + toast「已上传脚本：xxx」；若已上传弹窗正开着则实时刷新。
  > 本页**不提供文件夹上传**（演示的上传入口就是一个单文件选择器）。但下拉框和已上传列表
  > 要能识别/列出 `cpd/blacklist/<名>/theme.sh` 这种文件夹门户——它只可能来自手工部署
  > （scp/手工拷进去），分发脚本的查找链里有这一级，所以列表、下拉、删除都得支持，
  > 只是没有上传入口。这也解释了决策 #6 里"脚本/文件夹直接按原名存放"的"文件夹"从哪来。
- **门户选择**：标签「门户选择」+ 下拉框（列出 `/usr/lib/opennds/cpd/blacklist/` 下的门户：.sh 文件与含 theme.sh 的文件夹；无上传时只有「默认门户」），底部「应用」（primary）按钮 → toast「门户已应用：xxx」。
- **已上传弹窗**：居中浮层（max-width 460px、max-height 80vh、标题「已上传脚本」+ 右上角关闭图标按钮）；逐行：脚本名（等宽、超长省略号）+ 行尾「删除」小按钮（红字描边）；空列表「暂无已上传脚本」。
- **删除确认**：二次确认弹窗「删除脚本」+「确定删除脚本「xxx」？删除后将从已上传列表中移除。」+「取消 / 删除（danger）」；确认后移除 + toast「已删除脚本：xxx」。
- 两个浮层 ESC / 点遮罩关闭，焦点管理照演示（关闭后焦点回到触发按钮）。

### 3.4 通用组件
- toast：**底部居中、深色胶囊**样式（注意：与本插件其它页面的右下角白底卡片不同，照本页演示实现），warn 琥珀色，约 2.4 秒消失；
- 560px 断点移动端适配（按钮拉满、下拉框加高），照演示 CSS。

## 4. 数据来源映射

| 页面数据 | 来源 |
|---|---|
| 黑名单 MAC | `uci -q get zone_blacklist.main.mac`（多值多行）。出厂模板里有一条 `list mac ''`，读到空串/纯空白必须**过滤掉**再渲染，否则表格首行是个空 MAC 行 |
| 当前选中门户 | `uci -q get zone_blacklist.main.portal`（空 = 默认门户） |
| 门户列表 | 扫描 `/usr/lib/opennds/cpd/blacklist/`：`.sh` 文件与含 `theme.sh` 的子目录 |
| 上传 | **两段式**（与区域识别页同一套）：前端先 `upload_begin <id>` 建好 `/tmp/zone_up/<id>/` → 前端用 `fs.write` 把文件写到 `/tmp/zone_up/<id>/<文件名>` → 再调 `upload_store` 让后端校验并搬进 `/usr/lib/opennds/cpd/blacklist/`。**不要把文件内容塞进 exec 的 argv**：Linux 单个参数上限 128KB（`MAX_ARG_STRLEN`），512KB 的文件 base64 后 ≈683KB，`file.exec` 直接 `E2BIG`，页面上只表现成"上传失败"。只支持文本（脚本/样式/HTML），二进制明确报错，与区域识别页同限制 |
| 拉黑生效 | ① 从 `trustedmac` 摘除并 `ndsctl untrust`（即时撤掉 nft 规则）；② 从 `preemptivemac` 摘除，并删掉该 MAC 的预认证队列文件（`<mountpoint>/ndscids/preemptive_auth/<MAC去冒号>`，`mountpoint` 由 `libopennds.sh` 现探（`/tmp`、`/run`、`/var` 中第一个 tmpfs，探不到退回 `/tmp`；`option log_mountpoint` 只改日志目录、不改这条路径）；文件名里的大小写取决于当时是谁投进去的，**小写和大写各删一次**，删不到不算错）；③ `ndsctl deauth <mac>`（对 `state="Trusted"` 的会返回失败，属正常，逐个尝试、不中断；**MAC 大小写按《整包集成与打包.md》§11.4：小写失败再试大写**）；④ **本次确有新增 MAC 时**才 `/etc/init.d/opennds restart`（纯删除——解除拉黑——不重启），随后最多 15 秒轮询（30 次 × 0.5 秒），**`pidof opennds` 有值且 `ndsctl status` 能成功**才算就绪，起不来按 `{"ok":0,"error":"配置已写入，但 openNDS 未能启动，请检查日志"}` 返回（**不回滚**：名单已写入，回滚只会让用户以为没拉黑成功） |

> 第 ① ② ③ 步都不能省；**新增了 MAC 才做第 ④ 步**（被拉黑的如果是可信任客户端，deauth 对它无效，只有重启能把它清出去；纯删除不重启，`zone_blacklist` 是分发脚本每次请求现读的）。`ndsctl untrust` 会当场删掉 nft `ndsTRU` 链里那条信任规则；重启则让主进程按新的 `trustedmac` / `preemptivemac`
> 重建 nft 链，确保摘除彻底生效。但**必须多清一步队列残留**：openNDS 的预认证队列是
> 目录下的一个 MAC 一个文件（`<mountpoint>/ndscids/preemptive_auth/<MAC去冒号>`），
> `get_next_preemptive_auth` 是「读一个删一个」，摘配置前已经投进去的那条还躺在里面，
> 下一轮照样会把它认证回来。所以顺序是：
>
> **改 uci（黑名单 + 两个名单）→ commit → `ndsctl untrust` → 删除该 MAC 的队列文件
> → `ndsctl deauth` → `/etc/init.d/opennds restart`**。
>
> 只 deauth 不清理名单的后果：trusted 客户端被 deauth 会被状态机直接拒绝
> （`TRUSTED → 任何状态` 一律返回失败），根本不会掉线；preempt 客户端则会在下一轮
> 预认证里自动登录回来。两种都让黑名单变成摆设。

## 5. 后端 API 约定（`opennds-cpd-api.sh blacklist …`）

rpcd `file.exec` 调用，调用形式 `opennds-cpd-api.sh blacklist <子命令> [参数…]`（本页 page 名固定为 `blacklist`）；stdout 输出 JSON；成功 `{"ok":1,…}`、错误 `{"ok":0,"error":"…"}`（信封见《整包集成与打包.md》§12）。

| 子命令 | 参数 | 返回 | 行为 |
|---|---|---|---|
| `status` | — | `{"ok":1,"enabled":1,"macs":[MAC…],"portal":"名或空","portals":[{"name":"a.sh","kind":"file"},{"name":"x","kind":"dir"}]}` | 读 uci + 列出门户目录（每项带 `kind: file/dir`；**跳过 `default.sh` 与 `default/`**，见决策 #6）。`portals` 同时供已上传列表与门户下拉框用，前端不要再自己猜目录 |
| `save_macs` | `add` / `remove`（逗号分隔 MAC）、`clear=0\|1` | `{"ok":1,"deauthed":N,"untrusted":M,"restarted":0\|1}` 或 `{"ok":0,"error":"非法MAC: xx"}` | 校验归一化 → 读当前名单 → 按 MAC 增删（`clear=1` 才清空整个 list；本页 UI 不发送这个参数，它只供接口层显式清空）→ commit → 对新增 MAC：摘 `trustedmac`/`preemptivemac` 条目并 commit、`ndsctl untrust`、删预认证队列里该 MAC 的文件 → 对在线客户端逐个 `ndsctl deauth` → **只在确实新增了名单条目时 `/etc/init.d/opennds restart`**（`add` 里全是已经在名单里的 MAC、没有真正写进新条目，不算新增，不重启；纯删除 / 只删不增 = 解除拉黑，也不重启），返回踢掉数、撤信任数与 `restarted` |
| `save_portal` | `portal=<名>` | `{"ok":1}` | 校验该名在门户列表中存在（或空=默认）→ 写 uci → commit。**「默认门户」落盘是空串**：前端那个 `<option value="default">默认门户</option>` 的 `default` 只是界面值，后端收到 `default` 或空都归一化成 `option portal ''` 再写——`default` 在分发脚本里是"兜底门户名"（`<门户库>/default.sh`），把它当选中值存进去，等于给兜底页开了个后门（决策 #6 要堵的正是这个）。`status` 读出空串时，前端把下拉框选中「默认门户」 |
| `upload_begin` / `upload_store` | `upload_begin <id>`；`upload_store <id> <name>`（文件已由前端写在 `/tmp/zone_up/<id>/<name>`） | `{"ok":1}` 或 `{"ok":0,"error":"…"}` | 与区域识别页**同一套两段式**，但参数从五个降到两个：本页落点固定是 `/usr/lib/opennds/cpd/blacklist/`，没有 `type` / `zone`，也没有文件夹上传（所以没有 `kind`）。重名/超 20 字符/路径穿越/**文件名等于 `default.sh`** 一律拒绝（最后一条见决策 #6） |
| `portal_delete` | `name=<名>` | `{"ok":1}` 或 `{"ok":0,"error":"门户使用中…"}` | 正被 `save_portal` 选中的拒绝删除；删除文件或文件夹 |

前端交互对应：黑名单编辑器「应用」→ `save_macs`；门户「应用」→ `save_portal`；上传 → `upload_begin/upload_store`；「已上传」弹窗数据 → `status`。

## 6. 实现质量要求

- **POSIX sh / busybox**：只用 ash 兼容语法；管道内 while 是子进程、`$'\n'` 不可用、无 GNU 专有参数；含空格/中文文件名加引号处理；CRLF 兼容。
- **flock**：写 `/etc/config/zone_blacklist`、`/etc/config/opennds` 与门户目录操作，入口先抢 `/var/lock/opennds-cpd.lock`（`flock -n`，见《整包集成与打包.md》§11.3），抢不到返回 `{"ok":0,"busy":1}`。
- **安全**：文件/文件夹名一律白名单校验（`[A-Za-z0-9._-]` + 中文），拒绝 `..`、`/`；上传内容大小上限 **512KB**（与设置页、区域识别页同一口径）。
- **冒烟测试清单**（交付前用 uci/ndsctl 桩验证）：空名单时点「应用」被前端拦下（不发请求）、显式 `clear=1` 能把整份名单清空、单条/多条 MAC、非法 MAC 拒绝、大小写与短横线归一化、去重、deauth 只对在线 MAC 执行且计数正确、**有新增时触发一次 restart 且返回 `restarted:1`（纯删除不触发、只改门户不触发）**、门户上传重名拒绝、选中门户删除被拦、删除其它门户成功、编辑态预填与取消不保存。

## 7. 集成说明（与其它页面合并成完整插件）

1. **分发脚本钩子（已在 `theme_zone_detect.sh` 里实现，本页不要重复做）**：
   分发脚本第一段就是黑名单检查——`clientmac` 命中 `/etc/config/zone_blacklist`
   的 `list mac` 时，直接跳过全部区域识别逻辑，按 `option portal` 指定的名字去
   `/usr/lib/opennds/cpd/blacklist/` 找门户（`<名>.sh` → `<名>/theme.sh` →
   `/usr/lib/opennds/cpd/blacklist/default.sh`，这一步就是决策 #6 里"门户库别放
   default.sh"的原因），都没有就用 `/usr/lib/opennds/cpd/default/blacklist/default.sh`，
   再找不到才回官方 fallback。所以本页只需要**写好这份 uci 配置**，门户就会自动换掉；
   不需要自己写 nft、也不需要改分发脚本。MAC 比较已在脚本里做了大小写归一化。
2. **rpcd 模式统一**：所有页面后端都是同一个 `opennds-cpd-api.sh` + JSON（本页 page 名 `blacklist`）；菜单与 ACL 全包各只留 `luci-app-opennds-cpd.json` 一份（acl 需含 `/etc/config/zone_blacklist` 读写、`/usr/lib/opennds/cpd/blacklist` 目录 read/list/write、`opennds-cpd-api.sh` exec）。
3. **上传机制复用**：`upload_begin/upload_store` 与区域识别页同一套实现（rpcd file write 到临时目录再搬移），插件里共用一份。但**长度上限按页传入、不能写死成一个常量**：本页 20 字符（门户不做「应用改名」，不必给数字后缀留位），区域识别页 19 字符（要留一位后缀位，见《区域识别.md》§3.3）；重名处理也不同——本页拒绝重名（决策 #9），区域识别页加数字后缀继续存。共用代码里把这两项当参数，别让一页的行为跑到另一页去。
4. **「应用」语义**：本页两个应用的生效方式不同——门户选择是分发脚本每次请求现读配置，**不重启**；名单应用**新增 MAC 时必须重启**（可信任客户端靠 deauth 踢不掉，只能重启；代价是全站已认证客户端短暂断线，按 `authlog.log` 恢复），**纯删除不重启**。原因见决策表 #5 与 §4 的红字说明。
5. **与概览页联动**：概览页的「拉黑」按钮写的就是本页名单（`zone_blacklist`）+ `ndsctl deauth` +（新增时）重启，两处共用同一份「写名单 → 摘 `trustedmac`/`preemptivemac` → `ndsctl untrust`/`deauth`」实现（概览页走自己的 `overview client_action block` / `unblock` 入口，后端内部复用同一段函数，不另写一份）；本页不依赖概览页存在。
6. **保存/应用 全局红线（防"重启被动生效"漏洞）**：任何页面的「保存」都不得写入会被 openNDS 或分发脚本运行时读取的配置（`/etc/config/opennds`、`zone_blacklist`）。允许写的只有两类：① 纯暂存缓存 `zone_detect`（无运行时读取者，生效完全依赖「应用」阶段的写正式配置动作）；② 前端内存快照（不碰文件）。本页无独立「保存」，区块内「应用」即写 `zone_blacklist` + deauth + 重启——`zone_blacklist` 是分发脚本运行时读取的文件，只允许在「应用」动作里写。任何绕过「应用」直接写正式配置的路径都视为实现错误——否则用户保存后未应用就断电/重启，配置会在开机时被动生效。
