描述一致：12.5px、灰色，即 `cpd-desc`），不再是标题旁的 label 或输入框下方的
小字。各区块的说明文字（即原 label）：

- 会话超时 →「默认时间1440（分钟）」
- 空闲超时 →「默认时间120分钟」
- 未认证超时 →「默认超时30分钟」（原"超时时间（分钟）"按要求改名）
- 检查间隔 →「默认时间为15（秒）」

**空输入 = 删除对应配置**（2026-11-18 改，不是"保持原值"）：用户清空输入框后
点「保存并应用」，该 uci option 被整体删除（前端暂存一条 `uci del` 增量，
openwrt 原生 commit 落盘），openNDS 回退到内置默认值（也就是占位符显示的那个数）。
**绝不能**写成 `uci set opennds.@opennds[0].sessiontimeout=''`——openNDS 读这四个值用的是
`sscanf(…, "%u", …)`（`conf.c:248-263`），空串解析失败、变量保持结构体初值 `0`，
而 `sessiontimeout=0` 的意思是**永不超时**，与"没配置、按默认 1440 分钟"正好相反。
非空则必须是纯整数并满足上表的范围，否则整次拒绝。

"会话超时"区块额外有**"配置范围"下拉框（默认/覆盖）**，见 §3。
其余区块没有配置范围概念。

## 3. 配置范围（默认 / 覆盖）——仅"会话超时"区块

背景：openNDS 中，单独客户端的会话超时可以通过 `preemptivemac` 列表的
`sessiontimeout` 参数（以及 FAS/ndsctl 下发）设置，且**优先于配置文件的全局值**。

下拉框语义（已与需求方确认）：

- **默认**：
  - 把输入的会话超时值写入 uci 配置文件，openNDS 按配置文件正常执行；
  - 单独客户端已设置的超时（preemptivemac 条目里的 sessiontimeout）**保持不动**，
    仍然各自生效（openNDS 原生优先级行为）。
- **覆盖**：
  - 同样把输入值写入配置文件；
  - **并且取消所有单独客户端的会话超时设置**——把 uci `preemptivemac`
    各条目里的 `sessiontimeout` 参数**改成 `0`**（0 = "用全局值"，五个参数都是这个语义），
    **不是把参数删掉**。原因：openNDS 的 `preemptivemac()` 用 `eval` 逐条解析，
    某条缺 `sessiontimeout` 时不会回退全局，而是**沿用上一条客户端留下的值**；
    删参数等于让这个客户端悄悄套上别人的超时，"覆盖"就变成了"随机继承"。
    同时也要把条目改成完整的 6 参数形式，缺的其它字段一并补 `0`。
    **已经存在的其它参数（`uploadrate` / `downloadrate` / `uploadquota` / `downloadquota`）
    一律原样保留，不许一起写成 0**——那是概览页「编辑」设的限速，会话页只负责超时，
    不能顺手把别人的设置清了。也不新增条目，只改已存在的。
    条目若还带第 7 个字段 `custom=…`（openNDS 的 `preemptivemac` 支持它），**原样保留在末尾**，
    别在重排 6 个字段时把它抹掉——它是别的功能写进去的，本页不认也不该删。
  - 覆盖状态需要持久化记录，**固定写到 `/etc/config/zone_detect` 的
    `config zone_detect 'main'` 节、键名 `session_scope`**，取值 `default` /
    `override`，键缺失按 `default` 处理。**这个键只在「应用」时写，不在「保存」时写**：
    概览页编辑弹窗写 `preemptivemac` 前会读它决定 `sessiontimeout` 写 `0` 还是写数值，
    如果「保存」就把它改成 `override`，用户还没点「应用」、概览页的编辑就已经按"覆盖"
    在写了——这正是要防的"保存被动生效"。
    这个文件是插件自己的缓存配置
    （无运行时读取者，也不会被 openNDS 或分发脚本读），区域识别页同样在里面
    存它自己的 `scope` / `wireless` / `wired` 键——**键名不重叠，互不干扰**。使得后续"概览页"编辑弹窗给某客户端写 preemptivemac 时，
    若覆盖处于启用状态，**该条目的 `sessiontimeout` 写成 `0`**（同样不能跳过参数），
    保持覆盖语义。此联动规则须写入实现，并与概览页共享同一读取函数。

  > ⚠️ **只许 `uci set zone_detect.main.session_scope=…`，禁止整节重建**。
  > 不要写 `uci set zone_detect.main=zone_detect` 或 `uci -q delete` 后再建——
  > 那会把区域识别页存的 `scope` / `wireless` / `wired` 一起清空，
  > 表现为"改了会话超时，区域门户选择莫名其妙全丢了"。

下拉框提示文案（照抄演示）：scopeHint = "覆盖会覆盖单独客户端的配置"。

> ⚠️ **落盘值统一用 `default` / `override`**：演示里那个 `<option>` 的 value 写的是
> `cover`（`<option value="cover">覆盖</option>`），那只是前端内部值，**别照抄进
> `zone_detect.main.session_scope`**——概览页编辑弹窗是按 `session_scope == 'override'`
> 判断"覆盖"的（《OpenNDS概览.md》§4），写成 `cover` 两边就对不上：会话页显示"覆盖"、
> 概览页照旧按"默认"写具体数值。下拉框的**显示文字**仍是「默认 / 覆盖」。

> ⚠️ **"覆盖"是不可逆的**：它把各条目的 `sessiontimeout` 改成 `0`，之后切回"默认"**不会**
> 把原来的数值恢复回来（插件没有、也不该存一份旧值——存了就会和概览页的编辑打架）。
> 切回"默认"只表示"以后不再强改"，已有条目的 `0` 仍然表示"跟随全局"。

## 4. 保存 / 应用交互（底部操作区）

底部右侧两个按钮："保存"（普通）/"应用"（primary 蓝色）。

- **保存**：把当前表单快照存入缓存——固定写 `/etc/config/zone_detect` 的
  `config zone_detect 'main'` 节，键 `session_snapshot`（把表单序列化成
  `key=value;key=value` 一行存进去，只存不放运行期读），toast"配置已保存"。
  同样只 `uci set` 单个键，不许重建整节。**写完必须 `uci commit zone_detect`**（与
  《区域识别.md》§4 的 `save_cache` 同一口径）：不 commit 只是躺在 `/tmp/.uci` 里，
  重启就丢，`get` 返回的 `pending` 也会永远算成 0。
- **页面加载时表单取哪一份值**：`pending=1`（存了没应用）时，四个输入框 + 配置范围下拉
  **必须用 `session_snapshot` 里的五项回填**，不要用 uci 的旧值；`pending=0`（没有快照，
  或快照与 uci 一致）时才按 uci 回填。不这么定的后果很直接：一刷新表单回到 uci 旧值、
  快照却是新值，用户什么都没改，点「应用」却被同节「应用」第 1 步「存在未保存的修改」挡回去，
  而同时弹出的 warn toast 又让他去点「应用」——两句提示互相打脸，除了把值手工再敲一遍
  没有别的出路。所以 `get` 必须把快照五项一并返回（见 §5），前端据此回填。
- **"已保存但没应用"怎么让用户看见**：`get` 返回 `pending`（`0`/`1`），口径是
  「`session_snapshot` 存在，且把它拆出来的五项（四个超时值 + 范围）与当前 uci 里的实际值不完全相同」。
  为 `1` 时，页面加载完成后补一条 warn toast：「上次保存的配置尚未应用，点「应用」后生效」。
  不新加任何固定区块（版式以演示为准）。理由：表单虽然回填的是快照值（见上一条），
  但**实际生效的仍是 uci 里的旧值**，没有这条提示，用户看到自己刚改的数就在框里，
  会以为已经改好、直接关页面走人。
- **应用**：
  1. 先比对当前表单与最后一次"保存"的快照；
  2. **不一致 → 拒绝应用**，toast 警告（warn）文案照抄演示：
     "存在未保存的修改，请先保存后再应用。"
  3. 一致 → 写入 openNDS 配置（§2 表格中的选项；配置范围=覆盖时同时执行
     §3 的 preemptivemac 清理），并把 `zone_detect.main.session_scope` 写成当前下拉值
     （`default` / `override`，只 `uci set` 这一个键）→ `uci commit opennds`
     （`zone_detect` 另 `uci commit zone_detect`）→
     `/etc/init.d/opennds restart` → 最多 15 秒轮询（30 次 × 0.5 秒），**`pidof opennds` 有值且 `ndsctl status` 能成功**才算就绪
     → 起来了才 toast"配置应用完成"；超时按后端 `{"ok":0,"error":"配置已写入，但 openNDS 未能启动，请检查日志"}` 报错，**不回滚**。
- 后端负责校验数值合法性后再写入，非法输入返回错误 JSON。

## 5. 后端 API（`opennds-cpd-api.sh session …`）子命令约定

POSIX sh，输出 JSON（成功 `{"ok":1,…}` / 失败 `{"ok":0,"error":"…"}`，信封统一见《整包集成与打包.md》§12）。
调用形式：`opennds-cpd-api.sh session <子命令> [参数…]`（本页 page 名固定为 `session`）。
至少提供：

| 子命令 | 功能 |
|---|---|
| `get` | 读取四个选项当前值 + 配置范围状态 + `pending`（`0`/`1`：`session_snapshot` 存在且与当前 uci 五项不完全相同，口径与用途见 §4）+ `saved`（快照里的五项；没有快照时给空对象，前端在 `pending=1` 时用它回填表单，见 §4）+ `enabled`（openNDS 服务启停开关，键缺失按 `1`，见《整包集成与打包.md》§11.1） |
| `save <scope> <sessiontimeout> <authidletimeout> <preauthidletimeout> <checkinterval>` | 校验并写入缓存配置节：**只写 `session_snapshot`（快照里含这五个值）并 `uci commit zone_detect`，不写 `session_scope`**——`session_scope` 只在 `apply` 时落盘，否则"保存了覆盖但没应用"会影响概览页的写入 |
| `apply` | 快照比对（由前端传入保存标记亦可）→ 写 opennds 配置 → 覆盖时把 preemptivemac 各条目的 `sessiontimeout` 置 0（补齐为完整 6 参数）→ 写 `zone_detect.main.session_scope` → commit（opennds 与 zone_detect 各自 commit）→ 重启 opennds |

安全要求：数值参数严格校验（纯整数、范围），防止注入；所有参数引用加引号。

## 6. 实现质量要求

1. shell 通过 `sh -n`；JS 通过语法检查；JSON 可解析。
2. 冒烟测试：stub `uci`/`ndsctl`，覆盖 get 初值（未配置→空+占位符）、
   save 校验（非法值拒绝）、save→apply 成功链、未保存直接 apply 被拒、
   覆盖模式下 preemptivemac 每条都有 `sessiontimeout=0` 且仍是完整 6 参数
   （断言"参数没有被删掉"）、默认模式不改动条目、重启调用被执行。
3. busybox ash 坑位注意（管道子进程变量失效等），与其它页面开发时相同。
4. rpcd ACL 需放行 `opennds-cpd-api.sh` 执行及 opennds 配置读写路径。
5. **并发**：`apply` 入口先按《整包集成与打包.md》§11.3 取全局锁（`exec 9>` + `flock -n 9`），

6. 界面文案中文、样式跟随演示布局（CSS 变量、表单、按钮、toast 均照搬原型）。
7. 页面进入时从后端 get 初始化表单；无自动轮询需求（静态设置页）。

## 7. 与其它页面的集成说明

- **统一包名 `luci-app-opennds-cpd`**：本页 JS 为 `view/opennds_cpd/session.js`；
  菜单与 ACL 全包各只留 `luci-app-opennds-cpd.json` 一份。
- 后端只有**一个** `opennds-cpd-api.sh`，本页调用时第一参数固定 `session`；
  禁止另建 `session-api.sh`。
- **缓存配置节与"保存/应用"模式与区域识别页、概览页一致**，合并时共用同一
  uci 缓存文件 `zone_detect` 的 `config zone_detect 'main'` 节，键名按页面前缀区分
  （本页 `session_scope` / `session_snapshot`，区域识别页 `scope` / `wireless` / `wired`），
  各页只 `uci set` 自己的键，不重建整节。
- **与概览页的联动**：配置范围"覆盖"状态持久化后，概览页编辑弹窗写
  preemptivemac 时须把 `sessiontimeout` 写成 `0`（遵循全局），**不能省略**
  ——省略会继承上一条客户端的值。两侧共享同一状态读取函数。
- **与「设置页」的口径**：概览页编辑弹窗里那句「需要到设置页 公平使用策略 里设置限速」
  指向的是**「openNDS 设置」页的「公平使用策略」区块**（同目录 `OpenNDS设置.md`），
  不是一个独立页面——文案里说的"设置页"就是那一页。本页在菜单里是独立项
  （`admin/services/opennds-cpd/session`），不挂在设置页下面。
- **保存/应用 全局红线（防"重启被动生效"漏洞）**：任何页面的「保存」都不得写入会被 openNDS 或分发脚本运行时读取的配置（`/etc/config/opennds`、`zone_blacklist`）。允许写的只有两类：① 纯暂存缓存 `zone_detect`（无运行时读取者，生效完全依赖「应用」阶段的写正式配置动作）；② 前端内存快照（不碰文件）。本页「保存」写缓存属 ①，opennds 正式配置只在「应用」写。「应用」= 校验 → 写正式配置 → commit → 重启 openNDS（全局超时在启动时读入内存，必须重启）。任何绕过「应用」直接写正式配置的路径都视为实现错误——否则用户保存后未应用就断电/重启，配置会在开机时被动生效。
