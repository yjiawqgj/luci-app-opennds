## 0. 任务总述

为 OpenWrt 上的 openNDS 编写两样东西，打包成一个 LuCI 插件（OpenWrt 24.10+ 为 `.apk`，旧版为 `.ipk`）：

1. **分发脚本**：作为 openNDS 登录模式 3（themespec 模式）使用的门户分发脚本。
   它根据客户端所在位置（无线接口/有线）识别客户端属于哪个"网络区域"，
   并为其提供对应的认证门户脚本。
2. **LuCI 界面**：管理员用它在各个区域卡片上配置、上传、应用认证门户。

参考资料：
- openNDS 官方文档：https://opennds.readthedocs.io/en/stable/howitworks.html
  （重点：登录模式 3 = themespec 模式，openNDS source 该脚本后调用其中的
  `generate_splash_sequence` 生成门户页面；theme 脚本内可用 `title`、
  `session_length`、`quotas` 等变量）
- openNDS 自带 `libopennds.sh`、`get_client_interface.sh`（后者输入客户端 MAC，
  输出该客户端所在网络接口名，如 `phy2-ap0` 或 `br-lan`）
- 官方 theme 脚本示例（如 `theme_click-to-continue-basic.sh`）

**交付物按 LuCI 应用源码结构组织**（`usr/`、`etc/` 装到根文件系统，`htdocs/` 装到 `/www/`），结构如下：

```
luci-app-opennds-cpd/
├── usr/lib/opennds/
│   ├── theme_zone_detect.sh        # 分发脚本（themespec）
│   └── opennds-cpd-api.sh          # 全插件唯一后端脚本（rpcd file.exec 调用）
├── htdocs/luci-static/resources/view/opennds_cpd/
│   └── zone.js                     # 本页 JS 视图
├── usr/share/luci/menu.d/
│   └── luci-app-opennds-cpd.json   # LuCI 菜单（整包共用一份）
├── usr/share/rpcd/acl.d/
│   └── luci-app-opennds-cpd.json   # rpcd ACL 权限（整包共用一份）
└── etc/config/
    └── zone_detect                 # uci 缓存配置
```

**运行时门户库**（不打进安装包：`cpd/wireless`、`cpd/wired`、`cpd/blacklist` 三个业务目录由
postinst 建，`cpd/default/*` 由「openNDS 设置」页首次上传时建，各区域目录在上传/应用时
按需建，口径见《整包集成与打包.md》§2）：

```
/usr/lib/opennds/cpd/
├── wireless/<SSID>/          # 区域页无线卡片上传的门户
│   ├── a1.sh                 # 未生效的已上传文件（原名 a.sh + 1）
│   ├── 11/                   # 未生效的已上传文件夹（原名 1 + 1）
│   ├── .portal_map           # 原名 ↔ 存储名 + 当前生效项
│   └── <SSID>.sh             # 应用后生效的文件门户（由 a1.sh 改名而来）
├── wired/<接口名>/            # 同上（有线）
├── blacklist/                # 黑名单页的门户库（另一页维护，本页不碰）
└── default/                  # 设置页的三份默认门户（本页只读）
    ├── wireless/default.sh
    ├── wired/default.sh
    └── blacklist/default.sh
```

## 1. 已确认的技术决策（不要再问，直接采用）

| 决策点 | 结论 |
|---|---|
| LuCI 版本 | 现代 JS LuCI（OpenWrt 21.02+）。前端 JS 视图 + rpcd 后端，不写 Lua 控制器 |
| 后端调用方式 | 全插件只有**一个**后端脚本 `/usr/lib/opennds/opennds-cpd-api.sh`。JS 通过 rpcd `file.exec` 调用，格式固定为 `opennds-cpd-api.sh <page> <子命令> [参数…]`：第一个参数是页面名（本页固定 `zone`），第二个起是本页子命令。脚本输出 JSON |
| 页面顶部"区域"下拉框 | **可切换**，两个选项：`全局` / `区域`。**初值**：有本页缓存（`zone_detect.main.scope`）就按缓存回填；没有缓存则按实际生效模式回填（`login_option_enabled=='3'` → `区域`，否则 `全局`）——不能一律默认"全局"，否则区域模式下的用户一进页面就被摆到"全局"，手一滑点「应用」就把区域配置全停了。切「全局」→ 页面只显示「区域选择」和「未匹配」，**不再显示「默认模式」面板**（已按要求整体删除，全局模式的保存/应用走 LuCI 底部按钮）；切「区域」→ 显示「无线区域」「有线区域」两个面板。**切换下拉本身不写任何配置**，只切换下方显示内容 |
| 全局 / 区域 与 uci 的映射 | 全局 → `login_option_enabled='1'`（停用区域识别，走 openNDS 默认认证设置）；区域 → `login_option_enabled='3'` + `themespec_path='/usr/lib/opennds/theme_zone_detect.sh'`。两者互斥，以最后一次「应用」为准 |
| 模式状态显示 | **已删除**（按 2026-11-18 需求）：下拉框下方不再有「当前生效 / 已保存 / 尚未保存 / 有未保存的修改」状态行，也不再有「默认模式」面板。未保存改动统一由右上角 LuCI 原生「未保存的配置」表达 |
| 是否已接管门户 | `status` 返回 `engaged`：`login_option_enabled=='3'` **且** `themespec_path=='/usr/lib/opennds/theme_zone_detect.sh'` 才算 `1`。为 `0` 时页头下方显示 info 提示条「尚未接管门户：选好区域后点「应用」，openNDS 才会使用本插件的门户」。这是装包后最常见的问题（配置都能改但门户不生效），详见《整包集成与打包.md》§9。**不许**在 postinst 里自动改 opennds 配置来"帮用户接管" |
| 同一门户能否被多区域共用 | **不能**。同一上传门户只能被一个区域卡片选中，应用时改名归属 |
| 门户生效后的名字 | **一律改名成卡片名**：文件 → `<SSID>.sh`（有线 `<接口名>.sh`）；文件夹 → `<SSID>/`，`theme.sh` 位于 `<SSID>/<SSID>/theme.sh`。分发脚本只按固定名查找，`ndsctl` 也不参与"用户选了哪个" |
| 换门户时旧门户怎么办 | 先把 `<SSID>.sh` / `<SSID>/` 改回它在 `.portal_map` 里的存储名（如 `a1.sh`），重新出现在已上传列表与下拉框，再把新选的改名成卡片名 |
| 用户选择/标记存储 | 独立状态文件 + uci 缓存（见 §5），**不允许**直接改写分发脚本内容来存标记 |
| 保存 / 应用的语义 | 页面的「保存」「应用」只覆盖**无线区域、有线区域**两个面板（默认模式面板已删除，全局模式走 LuCI 底部按钮）。**「保存」只写 uci 暂存（右上角出现「未保存的配置」），不落地；「保存并应用」才 commit + 落地写盘**。**无线 / 有线两个面板**未保存就点「应用」，按演示文案拦截：「请先保存无线区域配置，再点击应用」/「请先保存有线区域配置，再点击应用」 |
| 应用行为 | ① 全局模式（LuCI 底部「保存并应用」，原默认模式面板行为）→ `login_option_enabled='1'`，**同时把 `zone_detect.main.scope` 写成 `global`**；② 「区域模式」应用 → `login_option_enabled='3'` + `themespec_path='/usr/lib/opennds/theme_zone_detect.sh'`，并把**该面板**下各卡片选中的门户改名生效（§3.5）；③ 两者都 `uci commit opennds` 后**重启 opennds 服务**，并按《整包集成与打包.md》§11.1 的判据等就绪（`pidof opennds` 有值 **且** `ndsctl status` 能成功，最多 15 秒 = 30 × 0.5 秒）再回「应用成功」。⚠️ 若 openNDS 处于停用状态（`enabled=0`），先按《整包集成与打包.md》§11.1 弹确认，确认后再顺手 `enabled=1` 并重启 |

## 2. 分发脚本 `theme_zone_detect.sh` 的行为规则

### 2.1 区域识别流程

输入：客户端 MAC。openNDS（`libopennds.sh`）在 source 本脚本**之前**就把 `clientmac` 等参数
解析成了全局 shell 变量（`ndsparamlist` 里的 `clientmac`，见 `libopennds.sh:2234`），
所以脚本里直接读 `$clientmac` 即可——它不是命令行参数，也没有 `export`，别写成
`$1` 或用 `env` 去找。

1. 调用 `/usr/lib/opennds/get_client_interface.sh "$clientmac"`，**只取输出的第一个
   字段**作为接口名（例如 `phy2-ap0` 或 `br-lan`）。注意这个脚本的坑：
   - 它输出的是**空格分隔的两段以内**：`<接口名>`，mesh 场景再跟一段 **mesh 节点 MAC**
     （脚本里变量叫 `clientmeshif`，值是 `iw dev <if> mpp dump` 拿到的 MAC，不是接口名）。
     脚本头部的 usage 写着"三个字段"（`local_interface` / `meshnode_mac` /
     `local_mesh_interface`），那是历史遗留，实际 `printf` 只输出前两段——
     所以永远只取第一个字段，后面那段 MAC 不要当接口名用；
   - 客户端不在 `ip neigh` 里时它会 **`exit 1` 且没有任何输出**（刚连上、
     跨网段、或网格场景都可能出现）。
   所以调用方式必须是：
   ```sh
   clientif=$(/usr/lib/opennds/get_client_interface.sh "$clientmac" 2>/dev/null | awk '{printf $1}')
   ```
   **不能**写 `clientif=$(get_client_interface.sh "$mac") || exit`，也不能把整行输出
   当接口名用。取不到时不要中断，按"区域未知"处理（见 2.5）。
2. 用 `iw dev` 输出判断该接口是否为无线接口：
   - **在 `iw dev` 接口列表里 → 无线区域**：SSID 优先用驱动直读——
     `iw dev <接口名> info` 里的 `ssid` 行（`awk '/^[ \t]*ssid[ \t]/{sub(...); print; exit}'`）。
     这条路径不受接口命名规则影响，也不受"中间某个 AP 被禁用导致序号错位"的影响。
     只有驱动读不出 SSID 时，才回退到「`phyN-apM` → radioN 的第 M 个 AP → `uci show wireless`」
     这套按序号映射的旧办法——它有两个已知缺陷：① 接口名不是 `phyN-apM`（老设备 `wlan0`、
     mesh/mgd 接口）直接解析失败；② 同一 radio 上中间某个 AP 被 `disabled` 时，netifd 不会
     重新编号，M 与实际启用顺序错位 → 取到别的 SSID 或取不到。回退路径也失败时，
     `zone_type` 要置成 `wireless`（不要留空，留空会拼出 `cpd/default//default.sh`，
     把无线类型默认门户跳过去），让「类型默认门户」兜住。
   - **不在列表里 → 有线区域**：区域名即接口名（如 `br-lan`）。
3. **先查默认标记**：把**区域名**拿去 `/usr/lib/opennds/zone_markers` 里比对（键的定义见 2.4）。
   区域名的取法就一条：无线 = **SSID**（不是接口名）；有线 = **客户端所在接口名**（通常就是 `br-lan`）。
   命中说明该区域在界面上选了"默认"，直接加载类型默认门户，不再往下找。
4. 未命中标记时，按区域名去对应门户库里查找并加载门户脚本（见 2.2 / 2.3）。
5. 门户脚本被 source 后，其中定义的 `generate_splash_sequence` 即成为
   openNDS 调用的门户生成入口。

### 2.2 门户查找优先级（无线）

总入口：`/usr/lib/opennds/cpd/wireless/<SSID>/`

按顺序尝试，命中即停：

1. **默认标记**：该客户端所在 SSID（如 `Guest`）在
   `/usr/lib/opennds/zone_markers` 里有"默认"记录时，直接使用
   `/usr/lib/opennds/cpd/default/wireless/default.sh`，**不再往下找**
   （匹配键是 SSID，不是 `phy2-ap1` 这类接口名——接口名会随 radio 重启重排）
2. `<SSID>/<SSID>.sh`（文件型门户：用户上传的 `a.sh` 在应用时已被改名为 `<SSID>.sh`）
3. `<SSID>/<SSID>/theme.sh`（文件夹型门户：用户上传的文件夹在应用时已被改名为
   `<SSID>`，`theme.sh` 位于该文件夹内）
4. `<SSID>/default/default.sh`（兼容项：早期手工部署留下的写法，正常不会出现；查找链保留它，
   是为了不把老用户的配置突然作废）
5. `/usr/lib/opennds/cpd/default/wireless/default.sh`（类型默认门户，
   由「openNDS 设置」页「无线区域」tab 上传）
6. `/usr/lib/opennds/theme_click-to-continue-basic.sh`（openNDS 官方回退，
   保证客户端永远有页面）

> 第 1 级与第 5 级指向同一个文件，差别只在优先级：选了"默认"的区域
> 即使自己目录下有 `<SSID>.sh` 也用默认；没选的才走第 2、3 级。

### 2.3 门户查找优先级（有线）

总入口：`/usr/lib/opennds/cpd/wired/<接口名>/`（正常拓扑下就是 `br-lan`），规则与无线一致：

1. 该接口有"默认"标记 → `/usr/lib/opennds/cpd/default/wired/default.sh`
2. `<接口名>/<接口名>.sh`
3. `<接口名>/<接口名>/theme.sh`
4. `<接口名>/default/default.sh`（同无线，兼容项）
5. `/usr/lib/opennds/cpd/default/wired/default.sh`（设置页「有线区域」tab 上传）
6. `theme_click-to-continue-basic.sh`

> 有线的"接口名" = **客户端所在的那个接口**（`get_client_interface.sh` 的第一个字段），
> 正常拓扑下就是 openNDS 管理的网桥（`br-lan`）。若客户端从另一个网桥接入
> （如第二条 LAN），脚本会去 `cpd/wired/<那个桥名>/` 找门户，找不到就落到"有线类型默认门户"。
> 界面上的有线卡片是按 `gatewayinterface`（管理接口）生成的，所以这种多网桥拓扑下
> 只有管理接口那张卡片配的门户会生效，其余走类型默认——这是按接口名索引的必然结果。

### 2.4 状态文件（标记）

- `/usr/lib/opennds/zone_markers`：默认标记文件，由 LuCI 插件写入，分发脚本只读。
  每行格式：`wireless|<SSID>|<接口名>|<管理接口>` 或 `wired|<接口名>|-|<管理接口>`。
  有该行即表示该区域选择了"默认"门户。
- ⚠️ **匹配键只有前两段**：分发脚本按 `|` 切分后比较 `$1 == <type> && $2 == <zone_name>`，
  无线时 `<zone_name>` 是 **SSID**，有线时是客户端所在**接口名**（通常就是管理接口 `br-lan`）。
  第三段 `<接口名>`（如 `phy2-ap1`）**只是给人看的诊断信息，绝对不能拿它做匹配**。
  实现要求：① 用 `awk -F'|'` 精确比较，**不要**用 `grep "^$type|$ssid|"`——SSID 里的 `.`、`[`、`]`、`*`
  会被 grep 当正则（`.` 误匹配其它字符、`[` 直接让 grep 报错返回 2，表现为"默认标记永远不生效"）；
  ② SSID 自身若含 `|`，切分会错位，写入前必须过滤掉该字符或拒绝写入并提示；
  ③ 写入用「先删同 `type|zone|` 的旧行、再追加新行」，保证同一区域只有一条标记。
  AP 的运行时名字会随 radio 重启、AP 增删而重排（今天是 `phy2-ap1`，明天可能变
  `phy2-ap0`），按接口名索引必然错位，导致"明明选了默认却走的区域门户"。
- 同一 SSID 有多个 AP 时，只写一行标记即可（键是 SSID，不是 AP）。
- 标记**不写入分发脚本本身**，分发脚本运行时读取该文件。

### 2.5 健壮性要求

- **区域名要当目录名用**：`cpd/wireless/<SSID>`、`cpd/wired/<接口名>` 都是用区域名
  直接拼出来的路径。SSID 是任意字节，可能含 `/`，也可能正好是 `.` 或 `..`。
  分发脚本对 `*/*`、`.`、`..` 不当区域名使用，直接退到类型默认门户；插件侧在
  建目录、改名之前必须做同一判断，命中就拒绝上传与「应用」，toast
  「该 SSID 含非法路径字符，无法建立门户目录，请改用默认门户」（只加校验，
  不改界面形态）。区域名若含 `|` 或换行，**整个区域都不许配门户**（不只是"选默认"）：
  缓存里每张卡片存成一行 `list wireless '<SSID>|<存储名>'`（§5），SSID 自身带 `|` 会让
  "SSID / 门户" 在读取时切错位；`zone_markers` 同样是 `|` 分隔。所以命中这两个字符时，
  **上传、保存、应用三处都要拦**，不能只拦"选默认"这一条路径：
  - 上传：「该 SSID 含非法路径字符，无法建立门户目录，请改用默认门户」（同 `*/*` 那条）；
  - 应用：同上，整面板拒绝（它是"写标记 / 改名"的入口）；
  - **保存**：这一处最容易漏——保存会把**该面板所有卡片**整份写进缓存（§3.5），
    带着 `|` 的那个区域会写出一条读不回来的行，下次加载时解析错位，可能把它的门户
    安到**另一个区域**上。所以保存时**把这个区域从本次写缓存的条目里剔除**，
    其余卡片照常保存，并追加一条 warn toast：「区域「<SSID>」含非法字符，未写入配置」。
- SSID 可能含空格、中文：所有路径变量必须加引号，禁止 word splitting。
- **`iw` 是硬依赖**：`get_client_interface.sh` 靠 `iw dev <if> station dump` 才能把无线客户端
  从 `br-lan` 精确到 `phyN-apM`，本脚本也靠 `iw dev` 判断接口是不是无线口、靠
  `iw dev <if> info` 读 SSID。系统里没有 `iw` 时，`get_client_interface.sh` 会把无线客户端
  一律报成 `br-lan`，本脚本随即把它整网络判成"有线"——所有无线区域门户失效，全部落到
  有线类型默认门户，而日志里只会有一行 debug。包里必须声明 `iw` 依赖，脚本启动时也可以
  先 `command -v iw` 检查、缺了就 `zone_debug` 一条 warn。
- 分发脚本必须 POSIX sh 兼容（OpenWrt busybox ash），通过 `sh -n` 语法检查。
- openNDS 会 `source` 该脚本，所以门户变量（`portal`、`zone_type`、`zone_name` 等）
  在脚本顶层设置，`generate_splash_sequence` 由被 source 的门户脚本定义。
- **区域未知时的兜底**（必做，不要让它落到官方页面）：两种缺失要分开处理，别一律当有线——
  1. **接口完全取不到**（客户端还不在 `ip neigh` / `exit 1`）：`zone_type=wired`、区域名为空，
     直接用 `/usr/lib/opennds/cpd/default/wired/default.sh`；没有这个文件才退到
     `theme_click-to-continue-basic.sh`。
  2. **是无线接口但 SSID 取不到**（AP 配置被删、mesh/mgd 接口、驱动读不出）：`zone_type` **必须置成
     `wireless`**、区域名为空，用 `/usr/lib/opennds/cpd/default/wireless/default.sh`。
     `zone_type` 留空会拼出 `cpd/default//default.sh`，等于把无线类型默认门户整个跳过去。
  这样管理员在设置页配过默认门户，任何异常客户端都还能看到自己配的页面。
- **门户文件不存在时的回退链**必须完整（缺一级都不行）：
  区域门户 → `cpd/default/<type>/default.sh` → `theme_click-to-continue-basic.sh`。
  最终如果连官方文件都没有（被用户删了），`portal` 为空时**不要 `source` 空路径**，
  也**不要 `exit`**（这个脚本是被 `libopennds.sh` source 进来的，`exit` 会把 openNDS
  的处理进程直接干掉）。正确做法是 `return 0` 安静退出，让 openNDS 自己报
  `generate_splash_sequence: not found`，至少日志里能看出问题、不会连带把服务弄挂。

## 3. LuCI 界面行为规则

### 3.1 布局（版式参考 `区域识别.html`，行为按本文档）

- **页头**：H1「网络区域识别」；描述一行
  「选择配置模式，为 Wi-Fi 区域选择认证脚本。」（演示那句后面还跟着"演示数据，不连接路由器，
  也不需要接触无线接口名称"，是演示自用，真页面只留前半句）。
- **区块骨架**：四个 `<section>`，每段一个 `h2`，顺序固定：
  `区域选择 Scope` →
  `无线区域 Wireless Zones`（下拉选「区域」时显示）→ `有线区域 Wired Zone`（同上）→
  `未匹配 Unmatched`（常显，固定在页面最下方，见 §3.6）。两个区域区块各带一句说明
  （照抄，原文重复字/错字按语病修正）：
  - 无线区域：「以下 Wi-Fi 来自路由器中已创建的无线网络，点击卡片为其配置认证脚本。」
  - 有线区域：「更改网络接口后，原网络接口配置并不会自动删除，需要到下方未匹配里手动删除；
    如果未删除，切换回来时将会使用上次配置。」
- **顶部"区域"选择行**：一行，左 `区域` 标签 + 右侧下拉框，两个选项
  `全局` / `区域`，初值按 §1 回填（缓存优先，无缓存看生效模式）。下拉框**可切换**。
  下拉框下方**没有任何状态行、也没有「默认模式」面板**——「当前生效 / 已保存 /
  尚未保存」这类状态显示已按要求整体删除。选「全局」时页面上只有「区域选择」和
  「未匹配」两个区块，全局模式的保存/应用由 LuCI 底部的「保存 / 保存并应用」按钮
  完成（行为同 §1 应用行为 ①：`login_option_enabled='1'` + `zone_detect.main.scope=global`）。
- **无线区域卡片**：卡片内容**不是固定的**，由系统无线列表动态生成——
  有哪些 SSID 就显示哪些卡片。卡片本身只是一个按钮，里面只有三样：
  SSID 名、右上角状态徽标（启用/禁用）、下面一行副标题
  （已选过脚本 →「已选择：<原名>」；没选且启用 →「点击选择认证脚本」；
  没选且禁用 →「已禁用，仍可预先配置」）。**卡片上不放下拉框、不放上传按钮**。
  卡片列表**没有空态提示**，一个无线网络都没有时它就是空的。
- **卡片下方的配置区**：点哪张卡片，配置区就显示哪张卡片的配置——工具行
  「上传」+「已上传」+「共 N 个脚本」，下面一行「认证」标签 + 认证门户下拉框
  + 一行说明（`已选择 X，仅对当前选中的 Wi-Fi 生效。` / `尚未选择脚本，选择结果仅对当前选中的 Wi-Fi 生效。`；
  该 WIFI 禁用时前面再加一句「该 Wi-Fi 当前为禁用状态，所选脚本会在启用后生效。」）。
  点卡片前配置区显示一行灰字「点击上方任意 Wi-Fi 卡片，为它选择认证脚本。」，
  上面的「保存」行此时整行隐藏。
- **有线区域卡片**：接口名称也不固定，取 openNDS 管理接口：
  先看 uci 配置（缓存），取不到则执行 `ndsctl status` 并从输出中提取
  `Managed interface:` 后面的接口名（一般是 `br-lan`）。⚠️ 这一行可能是
  `Managed interface: br-lan - IP address range: 192.168.1.0/24`（有 `gw_iprange` 时多后半截，
  见 `util.c:987-989`），只取冒号后到第一个空格为止的那段，别把整行当接口名——
  否则卡片名、`cpd/wired/<接口名>/` 目录、缓存 key 全跟着错。卡片只有接口名 + 该接口 IP；
  同样是"点卡片 → 下方配置区显示下拉框与上传"，未点时灰字
  「点击上方有线区域卡片，为它选择认证脚本。」，说明行是
  `已选择 X，仅对有线区域生效。` / `尚未选择脚本，选择结果仅对有线区域生效。`。
- **两个区域面板底部各有一组操作行，「应用」是面板级的**（不是每张卡片一个）：
  - 无线区域：上面一行「保存」+ 状态文字（**没选中任何卡片**时整行隐藏，选中一张卡片才
    出现）；下面单独一行「应用」+ 右侧提示「应用已保存的无线区域配置」，这一行常显。
  - 有线区域：「保存」「应用」+ 状态文字在同一行，**整行在没选中卡片时隐藏**（与无线的
    「保存」行同理）；两个按钮的处理函数本身也要在没选中卡片时直接 return、不弹提示
    （保存的是一张卡片的配置，没有卡片就没有可保存的对象）。
  - 一次「应用」把**该面板下所有卡片**的选择一起落地（顺序见 §3.5），所以各面板
    的「应用」不能拆成卡片级按钮。
  - **三个面板的状态文字是同一套三态**：没对这个面板保存过 → `尚未保存`；保存过、
    且当前选择（或下拉框里的模式）与保存时不同 → `有未保存的修改`（红色）；否则 `已保存`。
    各面板只认自己的那份"已保存"记录：无线看 `list wireless`、有线看 `list wired`、
    默认面板看 `zone_detect.main.scope`，别拿另一份去判。另外无线面板还有一条演示里的
    附加规则：**模式已经存成「默认」而用户切回「区域」时**，无线面板也显示
    `有未保存的修改`（`savedMode !== "zone"`）——否则一进区域面板就是"已保存"，用户以为
    不用保存就能应用。
  - ⚠️ **「应用」只落地"已保存的选择"**（无线面板右侧那句「应用已保存的无线区域配置」就是这个意思）。
    所以改了下拉框、没点「保存」就点「应用」，这次改动**不会生效**，但也不会报错——
    页面只靠状态文字「有未保存的修改」提醒。别为了"看起来聪明"让应用去读实时下拉值：
    那会和缓存里的「已保存」永久分叉（刷新后又回到旧值）。
- **未匹配区块**：**固定在页面最下方**的一个独立区块（不是页头的小徽标）。标题
  「未匹配」+ 说明「以下文件尚未关联到任何区域。」+ 一个「查看」按钮
  + 计数「共 N 个未匹配文件」；点「查看」弹出浮层列出条目。

### 3.2 卡片状态规则

- 卡片右上角状态标签：该 WIFI `disabled='1'` → 「禁用」；`disabled='0'` **或该项缺省** →
  「启用」（`wifi-iface` 的 `disabled` 默认就是 0）。
- **禁用卡仍可配置**：点击卡片照常展开配置面板，卡片副标题显示
  「已禁用，仍可预先配置」——**只有没选过脚本时才显示这句**，已经选过脚本的卡片
  副标题是「已选择：<原名>」（演示 `cardSub()` 里"已选择"优先于"已禁用"）。
  配置照常保存/应用，只是该 SSID 当前没有客户端接入。
- 同名 SSID：若存在两个同名 SSID，两张卡片都正常显示、都可配置。由于门户目录
  按 SSID 名索引（`cpd/wireless/<SSID>/`），同名 SSID 会共用同一份门户——
  这是按 SSID 索引的必然结果，界面不额外加"重名"标记、不阻断配置。
  ⚠️ 但**两张卡的选择必须是同一份**：任一张改了下拉框，其它同名卡片的草稿选择同步跟着变
  （它们本来就是同一个区域）；保存时按 SSID 去重，同一个 SSID 只写一条缓存；
  应用时同样按 SSID 去重，一个区域只做一次"还原旧门户 → 改名新门户"。
  不这么做的话，两张卡各选一个不同门户，应用阶段会先后把两个存储名改名成同一个
  `<SSID>.sh`，后一个把前一个覆盖掉，`.portal_map` 的映射也跟着错。

### 3.3 上传逻辑

- 选中无线卡片（如 Guest）后在**下方配置区**点「上传」→ 允许上传一个/多个 `.sh` 文件，或一个文件夹 →
  存放位置为 `/usr/lib/opennds/cpd/wireless/<SSID>/`（**SSID 原名，大小写照抄，不改小写**；如卡片是 `Guest`，目录就是 `Guest/`）。
- 选中有线卡片（如 br-lan）后同样在下方配置区点「上传」 → 存放位置为 `/usr/lib/opennds/cpd/wired/br-lan/`。
- **接受类型**：后缀为 `.sh` 的脚本文件，或内含 `theme.sh` 的文件夹。
  其它类型（`.py` / `.cgi` / `.lua` / 压缩包等）一律拒绝并提示
  「只接受 .sh 门户脚本，或包含 theme.sh 的文件夹」。
- **大小上限**：**单个文件 ≤ 512KB**（与「openNDS 设置」页、黑名单页同一口径，别各定一套）；
  文件夹上传时按其中**每个文件**分别校验，有任何一个超限就整条拒绝并提示
  「文件 <名> 超过 512KB，无法上传」。
  > **上传入口必须有两个**：一个选 `.sh` 文件（`accept=".sh" multiple`，
  > 照演示允许一次选多个，逐个走下面同一套改名流程），
  > 一个选文件夹（`<input type="file" webkitdirectory>`）。理由：门户查找链里有
  > `<SSID>/<SSID>/theme.sh` 这种文件夹形态，只给文件入口的话用户永远部署不了主题包。
  > 两个入口可以是两个按钮，也可以是一个按钮弹二次选择；样式沿用演示的上传按钮，
  > 不要改成拖拽区。
- **成功 toast**：一次传多个就合并成一条「已上传 N 个脚本：A、B」（照演示的拼法，
  条目显示名、顿号分隔——平时就是原名，同一卡片里重复原名时用存储名，见下条「唯一键」），
  只传一个就「已上传 1 个脚本：A」。**不要**照演示的
  「所选脚本已在上传列表中，未重复添加」——本页撞名是加数字后缀继续存（见下条），
  不存在"重复就跳过"这种情况。
  > 批量里若有一条被校验拦下（类型不对、名字超长、含非法字符），**其余条照常入列**，
  > 最后用 warn toast 列出被拒的那几条与原因，不要整批回滚。
- **名称长度**：**存储名不超过 20 个字符**。因为后面要自动加 `1`，所以
  **用户原名不得超过 19 个字符**，超长直接拒绝：
  「文件名过长（最多 19 个字符），超出后无法自动改名」。
- **名称安全**：只允许 `[A-Za-z0-9._-]` 与中文；拒绝 `/`、`\`、`..`、
  首字符为 `.`、控制字符、空名。文件夹内的 `theme.sh` 保持相对结构一起搬。
- **绝不覆盖已有的文件/文件夹**：落盘前拿**最终存储名**（原名 + 数字后缀）去试，
  撞到已存在的就顺延到下一个空位（见下条），**不是报错拒绝**。判断的是最终存储名，
  不是用户的原名——上传 `a.sh` 时已存在 `a1.sh`，它会存成 `a2.sh`，不算冲突。
- **改名与映射**：上传后自动在原名后面追加 `1` 存入卡片文件夹
  （如 `1`→`11`、`1.sh`→`11.sh`、`a.sh`→`a1.sh`），并在该卡片目录里建立
  映射记录文件 `.portal_map`（原名 ↔ 存储名）。此时上传内容**尚未生效**，
  下拉框与已上传列表都仍显示原名（重复原名的例外见下条「唯一键」）。
- ⚠️ **唯一键是"存储名"，不是"原名"**：同一个原名可以有多份（上面那条 `a.sh` → `a1.sh`，
  再传一次同一个 `a.sh` → `a2.sh`，两份的**原名都是 `a.sh`**，光看原名分不出来）。所以下面这些地方
  **一律用存储名**：下拉框 `<option>` 的 value、缓存 `list wireless` / `list wired` 里写的门户、
  `apply` 选中的那一项、`.portal_map` 的 `applied` 行、`upload_delete` 的参数。原名只用于
  **显示**；同一卡片内出现重复原名时，显示名退化成存储名（`a1.sh` / `a2.sh`），否则列表和
  下拉框里会出现两行一模一样的 `a.sh`，用户选哪个、删哪个都说不清。
  唯一用原名的地方是卡片的「已选择：<原名>」副标题与说明行文字——那里只显示，不参与匹配。
- ⚠️ **`a1.sh` 已存在时必须继续往后加**，不能覆盖：
  依次尝试 `a1.sh` → `a2.sh` → `a3.sh` … 直到找到空位（最多试到 `a99`，
  仍冲突则拒绝并提示「同名文件过多，请先清理已上传列表」）。
  `.portal_map` 里记的必须是**实际落盘的存储名**（如 `a3.sh`），
  否则后面"应用"和"删除"都会找错文件。
  文件夹同理（`a` → `a1/`，若 `a1/` 已被占用则 `a2/`）。
- ⚠️ **20 字符上限要按加完后缀之后的存储名算**。原名本身可以到 19 字符，
  加一位正好 20；如果原名已经是 20 字符，加 `1` 变 21 就超限了，
  这种必须在上传时拒绝，不能先存进去再说。
  **后缀涨到两位时（`a10` 起）同理**：`原名 + 两位后缀` 超过 20 字符就不许存，
  既不截断原名、也不突破 20 字符上限，直接按「同名文件过多，请先清理已上传列表」
  拒绝——所以 19 字符的原名只能用到一位后缀（`a1`…`a9`），撞到 `a9` 之后再撞就没位置了；
  18 字符的原名连两位后缀也放得下（`a10`…`a99` 都是 20 字符，到 `a99` 才用尽）。

### 3.4 已上传列表

- 选中卡片后在配置区点「已上传」→ 弹出居中浮层，上半部一行：计数「共 N 个脚本」+
  右上角「关闭」按钮；下面逐行列出对应卡片文件夹（如
  `/usr/lib/opennds/cpd/wireless/staff/`）里的条目，**按 `.portal_map` 反查显示原名**
  （磁盘上是 `11`/`21`，界面显示 `1`/`2`；同一卡片里有重复原名时改显示存储名，
  见 §3.3「唯一键」）。弹层标题「已上传脚本」，
  空列表一行「暂无已上传脚本」；行尾「删除」小按钮（红字描边）。
  配置区的工具行里也有同一份计数（「共 N 个脚本」），两处数字必须一致。
- ⚠️ **扫描目录时必须跳过以 `.` 开头的条目**：`.portal_map` 就躺在同一个文件夹里，
  它**不是门户**——不能出现在「已上传」列表里、不能计入「共 N 个脚本」、更不能被
  `upload_delete` 删掉（删了映射，所有原名↔存储名的对应关系连同 `applied` 一起丢，
  已生效的门户再也还原不回存储名）。列表只收 `.sh` 文件与含 `theme.sh` 的文件夹。
- **正在生效的那一份不在列表中显示**：它已被改名为 `<SSID>.sh` / `<SSID>/`
  （有线为 `<接口名>.sh` / `<接口名>/`）。用户看不到它，也就不会误删，
  因此**不设"正在使用无法删除"的提示**。选了「默认」的区域**没有生效门户**，
  原来那份已被还原成存储名（§3.5 第 1 步），会正常出现在列表里、可删。
- 列表只显示未生效的已上传门户，可删除。删除按**存储名**定位（行里带的就是存储名，
  不用再反查），并同步删掉映射记录。
- 删的是**那一条记录 + 磁盘上的存储文件/文件夹**，不是只把界面上的行抹掉；
  二次确认文案照演示：「确定删除脚本“<条目显示名>”吗？删除后，认证下拉框将不再提供该脚本。」
  （按钮「取消 / 删除」，成功后 toast「已删除脚本 <条目显示名>」；条目显示名平时是原名，
  重复原名时是存储名，见 §3.3「唯一键」）。删失败（文件已被别处删掉）
  按成功处理，别卡住界面。
- **删掉的正好是某卡片下拉框里当前选中的项**（还没保存、也没应用）时，该卡片的选择要退回
  「默认」——否则下拉框指着一个已经不存在的存储名，应用时按快照改名会找不到文件。
  照演示 `deleteScript()` 的做法：遍历各区域的草稿选择，值等于**被删的存储名**的就清空
  （草稿里存的就是存储名，别拿原名比——重复原名时会误清别的卡片）。
- **删掉「已保存、还没应用」的那个门户要拦住应用**：缓存里的选择指向一个已经不存在的
  存储名时，点"应用"必须拦下，提示「已保存的配置引用了已删除的脚本，请重新保存后再应用」
  （有线区照演示是「已保存的有线区域配置引用了已删除的脚本，请重新保存后再应用」）。否则应用阶段按快照改名会找不到文件，
  最后变成"点了应用、门户没换"却没有任何提示。

### 3.5 认证门户下拉框与"应用"

- 下拉框选项：未生效的已上传门户（`<option>` 的 value 是**存储名**，显示名是原名，
  重复原名时显示存储名，见 §3.3「唯一键」）+ "默认"项 + 当前生效项（同样以存储名为 value）。
- **每张卡片的「选择」必须回填，不能一律给「默认」**（界面只有一个下拉框 `authSel`，切到哪张卡片就显示那张卡片的初值，所以回填要按卡片做，不是在卡片上再放一个下拉框）：① 缓存 `list wireless` / `list wired` 里有这个区域 → 用它；② 缓存没有、但该区域有生效门户（`<SSID>.sh` / `<SSID>/`）→ 选当前生效项（value 用 `.portal_map` 里 `applied` 那行的存储名，显示原名）；③ 两者都没有 → 「默认」。这条是面板级「应用」的安全前提：若全部默认成「默认」，用户只在 A 卡动了手就点应用，B、C、D 卡会被当成"选了默认"逐个还原门户、写满 `zone_markers`，已生效的区域门户被整片取消，而且没有任何提示。
- 用户在下拉框选完后点"保存"→ 把**该面板所有卡片**当前的选择整份写入缓存
  `/etc/config/zone_detect`（无线写 `list wireless '<SSID>|<存储名>'`、有线写
  `list wired '<接口名>|<存储名>'`，都是一条一张卡片；SSID 含 `|` 或换行的那条跳过并 warn，见 §2.5）。
  **选「默认」的卡片存成 `<SSID>|`（后半段空串）**，不要写字面量 `default`——`default`
  在分发脚本里是"兜底门户"的保留名（`portal_from_name` 的 `""|default` 分支），
  混进存储名会被当成"去找一个叫 default 的门户"，和"选默认"语义不同；
  读缓存时后半段为空 = 该区域选了「默认」。
  **不是只写刚动的那一张**——只写当前卡片的话，"先配 A 卡保存、再配 B 卡保存"
  会把 A 的选择丢掉。缓存里没有其它运行时读取者，写它既不影响 openNDS、
  也不会让未应用的门户生效；**不做任何改名**。写完要 `uci commit zone_detect`——
  只 set 不 commit 的话配置躺在 `/tmp/.uci` 里，重启就丢。
- 点"**应用**"→ 才执行落地操作。**应用前必须先保存，这是硬拦截**：无线面板点应用时，缓存里还没有
  `list wireless`（页面全程没点过「保存」）→ toast（warn）「请先保存无线区域配置，再点击应用」并**不发请求**；
  有线面板同理，文案「请先保存有线区域配置，再点击应用」。
  两个面板的**应用只认"已保存的选择"（缓存 `list wireless` / `list wired`），不读当前下拉框的实时值**——
  否则用户改完下拉框直接点应用，文件改名与 `zone_markers` 都按新值落地，而缓存里还是旧的：
  刷新后「已保存」显示旧值、卡片回填旧选择，实际生效的却是新门户，两边对不上。
  所以页面加载时，缓存里已有该面板的 list 就视为"已保存"基线（可以直接点应用）；
  缓存里没有这个 list（新装机器、或从没保存过）就是"尚未保存"，必须先点「保存」。
  页面上的保存状态文字与这条拦截同源，别各算一套。
  **两道守卫的先后固定**：先判"有没有保存过"（本节），再判"保存的配置是否引用了已删除的脚本"（§3.4 末条）——
  顺序反了会让新装机器点应用时收到"引用了已删除脚本"这种莫名其妙的提示。
- 通过上面这道守卫后，顺序固定：
  1. **先还原旧门户**：若该卡片已有生效门户（`<SSID>.sh` 或 `<SSID>/`），
     按 `.portal_map` 里记录的"当前生效项"把它改回存储名（如 `<SSID>.sh` →
     `a1.sh`），让它重新出现在已上传列表和下拉框里。
     **该卡片这次的选择就是当前生效项时，跳过第 1、2 步的改名动作**（先把文件改回存储名、
     再改名回去，只会平白多两次中途失败的机会，失败一次门户就从分发路径上消失了）。
     注意跳过的只是**改名**：第 3 步的标记校正照做——选「默认」就把标记补齐/保留，
     选具体门户就删掉标记，否则"从没应用过的区域选了默认"会一个标记都不写。
     ⚠️ **有生效门户、但 `.portal_map` 里查不到 `applied` 记录**（门户是手工拷进库里的，
     不是本插件应用的）：**不许直接 `mv` 覆盖**——先把现有的 `<SSID>.sh` / `<SSID>/`
     挪成不冲突的存储名（`manual1.sh` / `manual1/` 起往后找空位，规则同 §3.3 的"绝不覆盖"）
     并补一条映射，再执行本次改名；补不进映射就**跳过这张卡片**、其余卡片照常应用，
     最后附一条 warn toast 说明哪张卡片被跳过。手工部署的页子正是 §2.2 第 4 级兼容项
     要照顾的老用户，覆盖掉就等于把人家正在用的门户悄悄删了。
  2. **再应用新选择**：缓存里这一条的选中值就是存储名（界面显示原名）。存储名 `11` → 改名为 `<SSID>`
     （文件夹门户，`theme.sh` 随之位于 `<SSID>/<SSID>/theme.sh`）；
     存储名 `11.sh` → 改名为 `<SSID>.sh`；有线则把 `<SSID>` 换成
     `<接口名>`。选了"默认" → 写 `zone_markers`，同时把旧门户还原。
     下拉框停在「默认」而用户从没主动选过的卡片**也是这一档**（演示里空值就是「默认」，
     没有独立的"未选择"状态），所以一次面板级应用会给这些卡片一并写标记；
     不要自己发明第三种"未选择"取值。
  3. **标记与生效门户不能并存**：选的是具体门户（不是"默认"）时，必须**删掉
     `zone_markers` 里该区域的那一行**（按 `type|zone|` 前缀删）。只改名不删标记的话，
     分发脚本仍然先命中标记、直接跳类型默认门户，用户会看到"明明应用了门户，客户端还是
     类型默认页"。反过来选"默认"时也只保留一行标记，不留下任何 `<SSID>.sh`。
  4. **更新映射**：`.portal_map` 的 `applied` 行记为本次选中的**存储名**；
     该项从已上传列表隐藏。**选了"默认"时必须把 `applied` 这一行删掉**——
     上一步已经把旧门户还原成存储名、磁盘上不再有 `<SSID>.sh`，若 `applied` 还留着，
     已上传列表会继续把它当成"生效中"隐藏起来，用户既看不到也删不掉。
  5. 写 openNDS 配置：区域面板的「应用」只可能出现在「区域」模式下面板里（§1：下拉切
     「全局」时只显示默认模式面板，无线/有线面板根本不渲染），所以这一步**固定**写
     `login_option_enabled="3"` + `themespec_path='/usr/lib/opennds/theme_zone_detect.sh'`。
     写 `1` 只发生在默认模式面板的「应用」，与本步无关——不要在这里按"当前下拉值"分支
     （那个分支永远走不到，写了也没人测）。然后 `uci commit opennds`，再执行
     `/etc/init.d/opennds restart`。
- 三组面板的成功 toast 照演示：点「保存」→「保存成功」，点「应用」→「应用成功」
  （默认模式面板同样，且它没有"请先保存"的拦截，见 §1）。

### 3.6 未匹配列表

- 若用户删除了某 WIFI 或更改了 openNDS 管理的网络接口，导致门户库里的
  文件夹不再对应任何现有区域（如 `/usr/lib/opennds/cpd/wireless/staff/` 的 staff
  已无对应 SSID；或 `/usr/lib/opennds/cpd/wired/br-lan/` 的 br-lan 已不是管理接口），
  这些条目显示在"未匹配"列表里，让用户选择删除。
- 扫描范围只有 `cpd/wireless/` 与 `cpd/wired/` 两个目录；
  `cpd/default/` 是设置页维护的默认门户，**不在扫描范围内，不得出现在未匹配列表**。
- 未匹配列表支持删除操作，并做路径安全校验。二次确认文案照演示：
  「确定删除文件“<名>”吗？删除后将不再出现在未匹配列表中。」，成功后 toast
  「已删除文件 <名>」；空列表显示「暂无未匹配文件」，计数文案「共 N 个未匹配文件」。

## 4. 后端 API（`opennds-cpd-api.sh zone …`）子命令约定

POSIX sh 实现，输出 JSON（成功 `{"ok":1,...}` / 失败 `{"ok":0,"error":"..."}`，信封统一见《整包集成与打包.md》§12）。
调用形式：`opennds-cpd-api.sh zone <子命令> [参数…]`（本页 page 名固定为 `zone`）。
至少提供以下子命令：

| 子命令 | 功能 |
|---|---|
| `status` | 返回登录模式、`engaged`（门户是否已由本插件接管，判定见 §1，为 `0` 时页头挂 info 提示条）、区域 scope、`enabled`（openNDS 服务启停开关，键缺失按 `1`，见《整包集成与打包.md》§11.1）、无线列表（SSID/section/device/disabled/dup/**已保存选择**/**当前生效项**）、有线管理接口及 IP、未匹配数量。**"当前生效项"必须一并返回**（每个区域读 `.portal_map` 的 `applied` 行、给**存储名**，没有就是空串）——卡片下拉框的初值要靠它回填（§3.5），只给"已保存选择"的话，缓存丢过一次之后就再也显示不出正在生效的门户 |
| `uploaded <type> <zone>` | 列出某区域**未生效**的已上传门户。每条必须同时给 **`store`（存储名，唯一键）** 与 `label`（显示名：原名；同一卡片内出现重复原名时给存储名，见 §3.3「唯一键」），另带类型（文件/文件夹）与原名。生效中的那份不列出 |
| `upload_begin <id>` | 在 `/tmp/zone_up/<id>` 建临时上传目录 |
| `upload_mkdir <type> <zone> <id> <name>` | 上传文件夹 |
| `upload_store <type> <zone> <id> <kind> <name>` | 从临时目录正式存入区域文件夹（改名加 `1`、写映射、查重、限长校验） |
| `upload_delete <type> <zone> <store>` | 按**存储名**删除未生效的已上传门户（行里带的就是存储名，不用再反查原名），同步删映射 |
| `save_cache <scope> <pairs...>` | 保存用户选择到 `/etc/config/zone_detect`（仅缓存），**写完必须 `uci commit zone_detect`**——不 commit 只是写进 `/tmp/.uci`，重启就没了，"已保存"会退回「无」、各卡片的选择也一起丢。`<pairs...>` 只属于**一个** list：无线面板传 `wireless` 的 `SSID\|存储名`、有线面板传 `wired` 的 `接口名\|存储名`（存存储名，不存原名——原名可能重名，见 §3.3「唯一键」）。**每条按 `\|` 切分必须正好两段**，切不出两段（SSID 自带 `\|`、空字段）的那条**跳过不写**，别把半截数据塞进缓存（前端已按 §2.5 剔除，这里再挡一次）。**后半段允许为空**（= 该区域选了「默认」，见 §3.5），不许因此当成非法条目丢掉。**只 `delete` + 重建本次要写的那个 list，另一个 list 原样保留**——否则"先保存无线、再保存有线"会把无线的选择清空。`scope` 由面板决定（`全局`→`global`，无线/有线面板→`zone`） |
| `apply <panel>` | `panel` ∈ `global` / `wireless` / `wired`，三组面板各调各的，不能共用一个无参入口。`global`：写 `login_option_enabled='1'` + 写 `zone_detect.main.scope='global'` → `uci commit opennds` + `uci commit zone_detect` → 重启，不碰门户文件、不写 `zone_markers`。`wireless` / `wired`：**只处理该面板**下的卡片（还原旧门户 → 改名新门户 → 更新映射生效项 → 写/删 `zone_markers`），再写 `login_option_enabled='3'` + `themespec_path` → `uci commit opennds` → 重启（这两个 panel 不写 `zone_detect`，用户选择在「保存」时已经落盘并 commit） |
| `unmatched_list` | 列出未匹配条目 |
| `unmatched_delete <type> <name>` | 删除未匹配条目 |

参数口径（表里没展开的那几个）：`type` ∈ `wireless` / `wired`；`zone` 是无线 SSID 或
有线接口名（大小写照配置里原文，路径拼接待用）；`kind` ∈ `file` / `dir`（`upload_mkdir`
固定传 `dir`，文件上传传 `file`；`name` 是用户原名，含后缀）。`id` **由前端生成**：取毫秒时间戳 + 4 位随机字符，
只用 `[A-Za-z0-9]`（插件里其它页（设置页 / 黑名单页）复用同一套 `upload_begin`，
所以这个格式是全包约定，别在一页里改成别的字符集）；后端只认这个字符集，
且**只在该 id 的临时目录里找文件**，绝不接受前端传来的路径。

安全要求：所有名称参数做 `bad_name` 校验（禁止 `../`、`/`、空字节等路径穿越）。

## 5. 状态与配置文件约定

| 文件 | 作用 |
|---|---|
| `/usr/lib/opennds/zone_markers` | 默认门户标记，LuCI 写、分发脚本读；两种行格式 `wireless\|<SSID>\|<接口名>\|<管理接口>` 与 `wired\|<接口名>\|-\|<管理接口>`（各段的含义见 §2.4，匹配只用前两段） |
| `/usr/lib/opennds/cpd/wireless/<SSID>/.portal_map` | 卡片目录内的上传改名映射：`原名 ↔ 存储名`（**1 个原名可以对应多条存储名**，存储名才是唯一键，见 §3.3），并额外一行标记 `applied <存储名>` 表示当前生效项。**这是"哪个门户在生效"的唯一记录**，不要再另存一份全局记录文件（两份记录必然不同步，排查时会互相打脸） |
| `/usr/lib/opennds/cpd/wired/<接口名>/.portal_map` | 同上（有线） |
| `/usr/lib/opennds/cpd/default/{wireless,wired,blacklist}/default.sh` | 类型默认门户，由「openNDS 设置」页维护，本页只读 |
| `/etc/config/zone_detect` | uci 缓存：`config zone_detect 'main'` 一节。本页用 `option scope`（`global`/`zone`）+ `list wireless 'SSID\|门户'` + `list wired '接口名\|门户'`；**「客户端会话管理」页在同一节里用 `session_scope` / `session_snapshot` 两个键**。两边键名不重叠，各自只 `uci set` 自己的键，**禁止整节重建**（否则会把对方的键清空） |
| `/tmp/zone_up/<id>/` | 上传临时目录 |

## 6. 实现质量要求

1. 全部 shell 通过 `sh -n` 语法检查；JS 通过语法检查；JSON 文件可被解析。
2. 交付前必须做功能级冒烟测试：搭 stub 沙箱（stub `uci`/`iw`/`ndsctl`/`ip`/
   `get_client_interface.sh`），覆盖：status、上传改名/重名/超长拦截、保存缓存、
   应用（还原旧门户 → 改名新门户 → 更新映射 → 写标记 → openNDS 配置 → 重启）、
   切回默认（旧门户恢复存储名）、已上传列表隐藏生效项、未匹配检测与删除、
   分发脚本七种门户路径（已应用 `<SSID>.sh` / `<SSID>/<SSID>/theme.sh` /
   `<SSID>/default/default.sh` 兼容项 / 标记默认 / 类型默认 `cpd/default/...` /
   官方回退 / 未知接口回退）、含空格 SSID。
3. 注意 busybox ash 的坑：管道里的 while 是子进程（变量累积失效）、
   `tr` 不支持 `\x01` 转义、名称长度按字节计。
4. rpcd ACL 需放行 `opennds-cpd-api.sh` 执行、上传临时目录写入、
   `/usr/lib/opennds/`、`/etc/config/zone_detect` 等通配路径（具体的 ACL 条目以
   《整包集成与打包.md》§4 那份为准，不要另加一套）。
5. **并发**：`apply` / `upload_mkdir` / `upload_store` / `upload_delete` / `unmatched_delete`
   入口都先按《整包集成与打包.md》§11.3 取全局锁（`exec 9>` + `flock -n 9`），抢不到返回
   `{"ok":0,"busy":1}`；`status` / `uploaded` / `unmatched_list` 是只读接口，不加锁。
   `upload_begin` 只建 `/tmp/zone_up/<id>/`、`save_cache` 只写 `zone_detect`，
   两者都不碰 `cpd/` 下的门户文件，按《整包集成与打包.md》§11.3 第 6 条**不加锁**。
   （`upload_mkdir` 会往区域目录里建文件夹、搬 `theme.sh`，属于"写门户文件"，
   漏了它就会出现"一边在上传文件夹、一边在应用改名"的抢占。）
6. 界面文案中文；主题配色跟随演示布局（区域识别.html）。

## 7. 与其它页面的集成说明

本页是完整插件的一个页面。整合到完整插件时：

- **统一包名 `luci-app-opennds-cpd`**，所有页面的 JS 都在
  `htdocs/luci-static/resources/view/opennds_cpd/` 下（本页 `zone.js`），
  菜单与 ACL 全包只留 `luci-app-opennds-cpd.json` 各一份。
- 后端统一走**同一个** `opennds-cpd-api.sh`：第一参数是页面名，本页为 `zone`；
  其它页面为 `overview` / `session` / `exempt` / `blacklist` / `router` /
  `walledgarden` / `settings`。禁止另建 `xxx-api.sh`。
- 插件自有的 uci 配置只有两个，**名字写死，不许另起**：
  `/etc/config/zone_detect`（纯缓存，见 §5 文件表）与 `/etc/config/zone_blacklist`
  （黑名单名单）。其余配置一律写进 openNDS 原生的 `/etc/config/opennds`，
  不要为每个页面各建一个配置文件。
- openNDS 登录模式由本页"区域"概念主导：其它页面若依赖登录模式，
  以 `uci get opennds.@opennds[0].login_option_enabled` 为准（1=全局、3=区域）。
- **保存/应用 全局红线（防"重启被动生效"漏洞）**：任何页面的「保存」都不得写入会被 openNDS 或分发脚本运行时读取的配置（`/etc/config/opennds`、`zone_blacklist`）。允许写的只有两类：① 纯暂存缓存 `zone_detect`（无运行时读取者，生效完全依赖「应用」阶段的写正式配置动作）；② 前端内存快照（不碰文件）。本页「保存」写缓存属 ①。「应用」= 校验 → 写正式配置 → commit → 重启 openNDS（`login_option_enabled` / `themespec_path` 都是启动时读入的，必须重启）。任何绕过「应用」直接写正式配置的路径都视为实现错误——否则用户保存后未应用就断电/重启，配置会在开机时被动生效。
