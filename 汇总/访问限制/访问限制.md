## 1. 任务总述与页面定位

本页管理 openNDS 的 **Block List**：拦**已认证**客户端访问指定的域名 / IP / 端口。页面两个区块对应 openNDS 的两条实现路径：

1. **手动阻止**：维护 `list authenticated_users 'block … to …'`。规则由 openNDS 启动时逐条建成 `ndsAUT` 链上的 nft 规则（`libopennds.sh:1882-1886` 把 `authenticated_users` 映射到 `ndsAUT`），**不需要任何额外依赖**；代价是规则里的域名由 nft 在插入时自己解析，多 IP 域名只覆盖其中一个地址。
2. **自动阻止**：维护 `list blocklist_fqdn_list` + `list blocklist_port_list`。域名解析出的**所有** IP 由 dnsmasq 动态灌进 `blocklist` nft 集合，域名换 IP 也跟得上；依赖 **dnsmasq-full（支持 nftset）**，OpenWrt 22.03 及更早还需要 `ipset`。

**与相邻两页的分工（别写混）**：

| 页面 | 管什么 | 生效对象 | 背后的 openNDS 机制 |
|---|---|---|---|
| 客户端黑名单 | 哪些**设备**不让上网 | 按 MAC | `zone_blacklist` + 分发脚本换门户 + 摘 `trustedmac`/`preemptivemac` |
| WalledGarden | 未认证设备**可以**访问什么 | Preauthenticated | `preauthenticated_users` / `walledgarden_*_list` |
| **本页** | 已认证设备**不可以**访问什么 | Authenticated | `authenticated_users 'block …'` / `blocklist_*_list` |

**「已认证和预授权」口径**：官方文档写明 *"Blocklist only applies to authenticated users"*；预授权登录（`preemptivemac` 里的设备自动登录）成功后状态**同样是 Authenticated**，所以两者本来就都在本页管辖范围内，**只写 `authenticated_users` 一份名单即可**，不要去碰 `preauthenticated_users`——那份名单由 WalledGarden 页独占。

**上游依据**：

- 官方 `docs/source/config_access.rst`「Block Access For Authenticated Users (Block Lists)」：
  - 手动：「An fqdn can be used in place of an ip address (but the fqdn must have only one possible ip address)」；*"If an FQDN resolves to multiple ip addresses, the rule will **NOT** be added."*
  - 自动：「If blocklist_port_list is NOT specified, then blocklist access is denied for all protocols (tcp, udp, icmp) on ALL ports for each fqdn specified in blocklist_fqdn_list.」；填了端口表时「Specified port numbers apply to ALL FQDN's」「Blocklist only applies to authenticated users.」
- 随包配置模板 `opennds` L727-747（手动示例 + "block 规则是最终裁决"）、L855-900（autonomous 说明与三条 Note）。
- `libopennds.sh` 的 `create_client_ruleset()`（1774-1948）与 `nft_set()`（1393-1596）。

**四条必须先记住的实现事实**（页面文案与校验都建立在这上面）：

1. **手动规则进 `ndsAUT`**（`libopennds.sh:1883`），只有"已认证"流量会走到这条链；可信任客户端在 `ndsNET` 里就被 accept 放行了，根本到不了 `ndsAUT`——**手动规则不影响可信任客户端**。
2. **自动规则插在 `ndsNET` 链顶**：`libopennds.sh:1506`/`1515` 用的是 `nft insert`（不是 `add`），链里原有的规则（`ct state invalid` drop、FAS 放行、之后的各段）都落在它后面。**实现必须保持 `insert`**——换成 `add`，规则会落到链尾、排在那条收尾的 `counter reject` 之后，等于永远不命中，界面上却"看着配上了"。
3. **自动集合的元素只有一个来源：dnsmasq 按 `blocklist_fqdn_list` 里的域名解析**（`libopennds.sh:1470-1491` 读列表 → 1527-1534 / 1538-1552 写 dnsmasq 配置；`dnsconfig.sh:35` 的 `ipset_to_nftset` 只是把 dnsmasq 填好的 ipset 搬进 nft）。**域名列表为空 → 集合永远空 → `ip daddr @blocklist …` 规则永不命中**。
4. **自动区填了端口就只拦 TCP**：`nft_set()` 的端口分支写死 `tcp dport {"$ports"}`（`libopennds.sh:1515`），UDP 不放行——界面文案已写明"只能拦 TCP"。

**本页只允许碰 `opennds.@opennds[0]` 的三个键**：`authenticated_users`（只增删其中的 `block` 条目）、`blocklist_fqdn_list`、`blocklist_port_list`。不得新建 section、不得重写整个配置文件。

**交付文件**（包名 `luci-app-opennds-cpd`，全插件共用一个后端脚本）：

```
htdocs/luci-static/resources/view/opennds_cpd/access.js   # 本页 JS 视图
usr/lib/opennds/opennds-cpd-api.sh                          # 全插件唯一后端脚本（rpcd file.exec，输出 JSON）
```

## 2. 已确认决策表（不要再问，直接照做）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 配置位置 | 直接写 `/etc/config/opennds` 的 `@opennds[0]`，三键见 §1；不新建插件自有 config |
| 2 | 手动区 ↔ uci | 每行 = `[协议] [端口] 目标`，按 §5.2 展开成 `block [tcp\|udp] [port N] to 目标`。**绝不允许把用户原文直接 `add_list`**：`80 192.168.1.20` 这种"端口在前"的写法在 openNDS 里会退化成**无条件 `counter drop`（已认证客户端全体断网）**，红线见 §5.2 |
| 3 | 协议位 | 只认 `tcp` / `udp` / `tcp/udp`（大小写不敏感）。本页**接受** `tcp/udp` 字面量（演示占位符第一行就是它，含义"两个协议各一条"），与 WalledGarden 页"`tcp/udp` 是说明性写法、输入即报错"**故意不同**——两页的占位符就是这么定的，别互相统一。`all` / `both` / `tcp,udp` / `icmp` 一律拒绝 |
| 4 | 目标 | 域名、点分四段 IPv4、IPv4 CIDR（`1.2.3.0/24`，上游模板示例就是 CIDR）。拒绝端口段、`*.域名` 通配符、IPv6、`http://` 前缀、路径、带空格的域名 |
| 5 | 只写目标 | **合法**，生成 `block to 目标`（拦该目标的所有协议、所有端口）。这点与 `allow` 不同：`allow to X` 会退化成"全放行"，`block to X` 只是"全拦 X"，没有放大风险，所以本页必须支持它 |
| 6 | 自动区文本 | **一行一个域名**（根域名、子域名都行，如 `example.com`、`www.example.com`），只接受域名。**不接受端口行、协议前缀、IP 字面量**：端口只能填在下方端口框（openNDS 的端口表对所有域名统一生效，不存在"只对某个域名生效的端口"，域名框里也没法表达）；IP 永远进不了集合（集合靠 DNS 解析域名填充） |
| 7 | **只填端口不填域名 → 无法保存** | 底部「保存」「应用」都拦下并 toast「只填端口不写域名无法保存：没有域名，拦截列表为空，规则不会生效」；后端 `validate`/`apply` 同样拒绝（`{"ok":0,"error":"port_only"}`），前后端同一口径。依据见 §5.3：域名空 → dnsmasq 配置里一条 `domain` 都没有 → 集合空 → 规则永不命中。端口只有端口框一个来源；**域名文本与端口框都空**才算"清空配置"，允许保存 |
| 8 | 端口框 | 英文逗号分隔，1-65535，不支持范围（`-`）、不支持中文逗号/分号。去前导零、数值去重后写入 `blocklist_port_list`（一端口一条 list） |
| 9 | 端口只拦 TCP | 自动区填了端口只拦 TCP（源码事实）。界面文案已写明，实现不再额外提示、也不再造"UDP 也拦"的规则 |
| 10 | 保存 / 应用 | **「保存」= 前端内存快照，不碰任何文件**；「应用」= 校验 → 写三键 → commit → 重启 openNDS。全局红线见 §8 第 6 条 |
| 11 | 快照守卫 | 照演示：编辑中点保存/应用 → 拦截；应用时当前内容 ≠ 最后保存的快照 → 拦截「当前配置尚未保存，请先保存后再应用」；页面加载时快照 = 当前 uci 内容 |
| 12 | 校验时机 | 编辑器里的「保存」只做本区格式校验（手动区：每行必须含域名/IP、不支持端口范围；自动区：每行必须是一个域名，一行一个），**不请求后端**；底部「保存」只校验端口框与决策 #7 那道门；**「应用」时后端整体校验**，任何非法行整次拒绝（一个键都不写），toast 报「第 N 行：原因」 |
| 13 | 反解析 | 手动区把 `authenticated_users` 里的 **`block` 条目**反解析成简写；**非 `block` 条目（`allow …` / `passthrough …`）不显示、也不动**（应用时原样保留在 uci 里，见 §5.6） |
| 14 | 写回顺序 | 新的 `block` 条目必须放在 list **最前面**。`create_client_ruleset()` 对 `authenticated_users` 先**把整份 list 倒序**（`libopennds.sh:1794-1797`），再逐条 `nft insert … index 2`（1925）——两步正好抵消，**链内顺序 = list 顺序，先写的在上**。`allow all` 只要排在 block 前面，block 就永远匹配不到（包里同时有这两类条目时这不是理论问题，是默认配置就会踩的坑）。`uci add_list` 只能往后追加，所以写回必须「读出全部条目 → 新 block 在前 → 原有 `allow` / `passthrough` 按原顺序跟在后面 → 整份重建」，不能追加到末尾 |
| 15 | dnsmasq 依赖探测 | 打开页面时按 §6.4 探测，`status` 返回 `bl_mode`：`nftset` 可用 / `ipset` 旧式回退可用 / `none` 不可用。只有 `none` 才在自动区挂警告条，`ipset` 挂轻警告；**仍可编辑保存** |
| 16 | 应用 = 重启 | 两类规则都是 openNDS 启动时读取（手动建 `ndsAUT` 链、自动写 dnsmasq 配置 + 建 nftset），应用必须重启 openNDS 才生效 |
| 17 | 编辑器按钮文案 | 列表编辑态是「取消」「**保存**」（照演示；WalledGarden 页是「完成」，不要统一）；底部操作区是「保存」「应用」 |
| 18 | 传输编码 | 两个 textarea 内容走 base64（各限 64KB），端口框明文且只允许 `[0-9, 空格]`（§6.1） |

## 3. 页面布局（版式与交互照演示，功能与边界按本文档）

### 3.1 页头
- H1「阻止访问」+ 灰字 `openNDS`；下方描述照抄演示（**一字不改**）：
  「只针对已认证和预授权客户端生效，可信任客户端不受此限制。」
  这是页面上给用户看的口径：本页只作用于「已认证 / 预授权登录」这一类客户端，可信任客户端按 openNDS 既有语义视为不受本页管辖。实现上不需要为此做任何特殊判断——规则怎么建由 openNDS 自己决定，页面不去推断、也不去改写链顺序。

### 3.2 手动阻止区块
- H2「手动阻止」+ 两条说明，照抄：
  1.「填写域名需要确保域名只有一个IP地址，否则添加规则后将不会生效。」
  2.「每行必须有一个域名或者一个IP地址，域名或者IP地址可以搭配访问协议，即：tcp/udp；也可以搭配端口号，但不支持端口范围。」
- 「编辑」按钮（铅笔图标，`aria-expanded` / `aria-controls` 联动编辑器）。
- **编辑态**：`textarea`（rows=6、可拉伸、等宽字体、`spellcheck="false"`、自动聚焦并定位到末尾），预填当前文本；占位符两行照抄：
  ```
  tcp/udp 443 example.com
  80 192.168.1.20
  ```
  按钮行「取消」「保存（primary）」。
  - 「保存」= 校验本区格式 → 回填展示区 + toast（ok）「手动阻止规则已保存」（照演示文案）。**这里不写后端**，只是把编辑结果落进页面状态。
  - 「取消」= 丢弃本次编辑回展示态，焦点还给「编辑」。
- **展示态**：标签「已保存规则」+ 只读展示区（灰底、内阴影、等宽 13.5px、`white-space:pre-wrap`、`aria-live="polite"`），逐行显示当前文本。

### 3.3 自动阻止区块
- H2「自动阻止」+ 两条说明，照抄：
  1.「域名和端口为全匹配模式：端口对所有域名生效，不能按域名分别设置。」
  2.「只写域名不写端口，会阻止这些域名的所有协议、所有端口；填了端口就只拦这些端口，且只能拦 TCP。只写端口不写域名无法保存——拦截列表靠域名解析填充，没有域名这条规则不会生效。」
- **依赖警告条**（决策 #15）：`bl_mode = "none"` 时在本区说明下方插一条警告（红/琥珀描边）「自动阻止不可用：需安装 dnsmasq-full（支持 nftset）。安装后本区配置才会生效。」`"ipset"` 时给轻警告「当前走旧式 ipset 回退，建议升级 dnsmasq-full」。只提示，不影响编辑。
- 「编辑」按钮 + 展示/编辑两态，标签「已保存规则」，逻辑与手动区一致；编辑框 label 是「**域名**」，占位符两行照抄（一行一个，一个根域名一个子域名）：
  ```
  example.com
  www.example.com
  ```
  框里**只放域名**——端口不在这写，统一填下面的端口框（理由见决策 #6：端口表对所有域名统一生效，写在域名旁边会让人以为只对这个域名生效）。
  编辑态「保存」校验：每行必须是一个合法域名，出现空格、端口、协议、IP 一律 toast（warn）「第 N 行：只能填域名，一行一个」，不落状态。
- **端口输入框**（编辑态与展示态都显示，不随列表编辑态切换）：label「端口」+ 说明「多个端口号使用英文逗号分隔，不支持端口范围。」照抄 + `input`（placeholder `80,443`）。修改即时进前端 state，随底部「保存」进快照。
- **保存/应用前必须过的门（决策 #7）**：自动区域名文本框为空、而端口框有值 → toast（warn）「只填端口不写域名无法保存：没有域名，拦截列表为空，规则不会生效」并**展开自动区编辑器**把光标交给用户，**不发请求**。域名与端口都空 = 清空配置，放行。

### 3.4 底部操作
- 「保存」：
  - 编辑中 → toast（warn）「请先保存或取消正在编辑的规则」，不执行；
  - 自动区只填端口没域名 → 按 §3.3 拦下；
  - 端口框格式错 → toast（warn）具体原因并聚焦端口框；
  - 否则更新快照 + toast（ok）「配置已保存（尚未应用）」（演示原文是「配置已保存（演示，尚未应用）」，只去掉"演示，"三个字）；
- 「应用」：
  - 编辑中 → 同上拦截；
  - 自动区只填端口没域名 → 同上；
  - 端口框格式错 → 同上；
  - 当前内容 ≠ 快照 → toast（warn）「当前配置尚未保存，请先保存后再应用」，不执行；
  - 否则发 `apply`：校验失败 → toast（err）逐条「第 N 行：原因」，不写任何东西；成功 → toast（ok）「配置已应用」（照演示原文，去掉"（演示）"字样，不要自己加"已重启"）；返回 `warnings` 时逐条追加 warn toast，成功 toast 照常显示（口径见《整包集成与打包.md》§12）。

### 3.5 toast
- **底部居中、深色胶囊**（与客户端黑名单页同款，`pointer-events:none`），warn 琥珀、ok 深绿，约 2.4 秒消失，容器 `aria-live="polite"`。**不要**套用 WalledGarden / 路由器访问页的右下角白底卡片。

### 3.6 移动端
- 520px 断点：页面内边距收窄、`.action-bar` 改纵向（按钮占满、`column-reverse`），照演示 CSS。

## 5. 解析 / 生成规格（本页核心，必须严格照做）

### 5.1 手动区输入语法（逐行；大小写不敏感；多空格/Tab 视为一个分隔符）

```
line       := target                        # 整站拦：block to target
            | portlist SP target            # 每个端口 tcp + udp 各一条
            | proto SP portlist SP target   # 指定协议：每个端口一条
proto      := "tcp" | "udp" | "tcp/udp"     # 本页 tcp/udp 是真实语法（= 两个协议各一条）
portlist   := port ("," port)*              # 逗号分隔，中间不许有空格
port       := 1..65535 的十进制整数（去前导零后比较）
target     := 域名 | 点分四段 IPv4 | IPv4 CIDR
```

- 空行忽略；行首尾 trim；`\r\n` 接受。
- 只写目标**合法**（决策 #5）：`example.com` → `block to example.com`。
- **协议必须带端口**：`tcp example.com` / `udp 1.2.3.4` 一律报错。原因不是"难看"，而是 openNDS 在没端口时会把协议一起清掉（§5.2 红线二），写进去等于"拦所有协议"——想拦所有协议就直接写目标，别用一个会被悄悄丢掉的协议位。
- 域名转小写后校验；单段 ≤63、总长 ≤253；不允许 `*` `/` `:` `http://` 路径。
- IP 只允许 `[0-9.]`，四段各 0–255；CIDR 掩码 0–32。

### 5.2 手动区展开规则（简写 → uci 条目）

| 输入 | 展开 |
|---|---|
| `example.com` | `block to example.com`（**一条**，全协议全端口） |
| `80 192.168.1.20` | `block tcp port 80 to 192.168.1.20`<br>`block udp port 80 to 192.168.1.20`（**两条**） |
| `80,443 192.168.1.20` | 四条：tcp 80、udp 80、tcp 443、udp 443（按书写顺序逐端口展开） |
| `tcp 80,443 example.com` | `block tcp port 80 to example.com`<br>`block tcp port 443 to example.com`（**两条**，只 tcp） |
| `udp 53 192.168.1.1` | `block udp port 53 to 192.168.1.1` |
| `tcp/udp 443 example.com` | 同 `443 example.com`：tcp + udp 两条 |
| `1.2.3.0/24` | `block to 1.2.3.0/24` |
| `tcp example.com` | ❌ 报错：协议必须跟端口（理由见红线二） |

- 🔴 **红线一：绝不把"端口在前"的原文写进 uci**。`create_client_ruleset()`
  （`libopennds.sh:1811-1880`）是逐词读的，第一个词不是 `allow`/`block` 就走
  `*) verdict="drop"`（1819）；后面的 `80`、`192.168.1.20` 因为没出现过 `port` / `to`
  关键字，既进不了 `portnum` 也进不了 `ipaddr`。最终落到 nft 上的是
  `nft insert rule ip nds_filter ndsAUT index 2 counter drop`——**没有目标、没有端口，
  已认证客户端的所有上网流量全被丢掉**。所以插件必须自己把 `80 192.168.1.20` 展开成
  `block tcp port 80 to …` + `block udp port 80 to …` 两条。
- 🔴 **红线二：绝不生成 `block port N to X`（无协议带端口）**：
  ```sh
  if [ "$proto" = "all" ] || [ -z "$proto" ] || [ "$port" != "port" ]; then
      proto=""; sdport=""; portnum=""
  fi                       # libopennds.sh:1888-1892
  ```
  协议为空时端口被一并清空，`block port 80 to X` 变成 `ip daddr X counter drop`——
  **从"只拦 80"变成"拦 X 的所有端口"**，比用户要的宽。所以"两个协议都要"只能拆成
  tcp + udp 两条。
- 🔴 **红线三：协议位必须白名单校验后小写化，绝不原样透传**：`count=1` 分支是
  **严格区分大小写的 `case`**（1822-1832），`TCP` 落到 `*) ;;` 被静默忽略，`proto`
  保持空 → 又踩中上面的清理分支；更糟的是指针跟着错位，`block TCP 443 X` 里 `443`
  因为 `$port` 不是 `"port"` 而不赋给 `portnum`、`X` 因为 `to_from` 一直是空而不赋给
  `ipaddr`，最终生成**裸 `counter drop`（全断网）**。前端必须只接受归一化后的
  `tcp` / `udp` / `tcp/udp`。
- 顺序：uci 按输入行顺序 `add_list`，反解析也按 uci 顺序读回，两边一致。运行时链内
  顺序同样是**正序**：`authenticated_users` 在建规则前会被整份倒序（`libopennds.sh:1794-1797`），
  而每条又是 `insert … index 2`，两步抵消，先写的在上。因此**先写的规则优先命中**——
  这也是决策 #14 要求把 block 放在 list 最前面的原因（放后面会被前面的 `allow all` 抢先）。
- 去重在展开之后按精确匹配合并：`80 example.com` 与 `tcp 80 example.com` 会得到重复的
  tcp 条目，只留一条。

### 5.3 自动区输入语法与"只填端口不能保存"

```
line    := domain              # 一行一个域名，就这一种形态
domain  := 合法域名（小写化后校验，单段 ≤63、总长 ≤253，不含 `*` `/` `:` 与空格）
```

- 框里**只有域名**。端口全部来自下方的端口框，合并成一份全局端口表——openNDS 的 `blocklist_port_list` 对所有域名统一生效，不存在"只对某个域名生效的端口"。页面文案里的"全匹配"说的就是这件事。
- **端口行写成 `443`、`443 域名`、`tcp 443 域名` 一律按非法行报错**：这几种写法在这个框里没有意义（端口是全局的，写在哪一行都一样；协议前缀会被丢掉），留着只会让人以为它对某一行生效。提示「第 N 行：只能填域名，一行一个」。
- **不接受 IP 字面量**（`1.2.3.4` / `1.2.3.0/24` → 报错「自动阻止只接受域名；IP 请填到手动阻止」）：集合靠 dnsmasq 解析域名填充，IP 写进去永远进不了集合。
- 🔴 **只填端口、没有任何域名 → 无法保存**（决策 #7）。依据是代码路径，不是偏好：
  1. 集合建成时是空的：`nft add set ip nds_filter blocklist { type ipv4_addr; size 128; }`（`libopennds.sh:1455`）；
  2. 规则照建：端口非空就 `nft insert rule ip nds_filter ndsNET counter ip daddr @blocklist tcp dport {"80,443"} reject`（1515）；
  3. 集合的**唯一**填充者是 dnsmasq，域名只从 `blocklist_fqdn_list` 取（1470-1491），写进 dnsmasq 的 `domain` 项也只来自它（1527-1534 / 1538-1552）；
  4. 域名空 → 一个 `domain` 都写不出来 → 集合永远是空的 → 规则**一个包都不命中**。
  这四步用真实函数干跑就能复现：空域名时 uci 只写 `set dhcp.nds_blocklist='ipset'` + `name` + `table` + `table_family` 四条，没有一条 `add_list …domain=`；填了域名才有。
- 官方文档的 autonomous 示例 3（`list blocklist_port_list '443 80'` 单独列出）在本版实现里**不成立**，以上面的代码路径为准；不要在文档或注释里引用那个示例当"端口可以单独配"的依据。
- **域名文本与端口框都空** = 清空配置（删掉两个 blocklist 列表），允许保存。

### 5.4 校验与错误文案（应用时整次拒绝，返回全部错误行，前端展示第一条并定位）

| 情况 | 提示（手动区拼成「第 N 行：…」） |
|---|---|
| 分词段数超过 3 / 段位无法识别 | 「格式不正确，支持 `域名或IP`、`端口 域名或IP`、`协议 端口 域名或IP`」 |

| 端口段（`8000-8100`） | 「不支持端口范围，请逐个端口写」 |
| 多个端口用空格分开（`80 443 example.com`） | 「多个端口之间用英文逗号分隔，如 `80,443`」 |

### 5.5 去重与归一化
- 手动区展开后按整条精确匹配去重（保留首次出现），不要做子串去重；域名统一小写；端口去前导零后数值比较（ash `$((0443))` 会按八进制算成 291，别用前导零直接进算术）。
- 同一行内重复端口（`80,80`、`80,080`）只展开一次。
- 自动区：域名小写去重；端口框去前导零、数值去重，按输入顺序写 `blocklist_port_list`（一端口一条 list）。
- `blocklist_fqdn_list` 一域名一条 list 与上游示例的 `list … 'a.com b.com'` **等价**：`get_list_from_config()`（`libopennds.sh:1077`）把全部元素用空格拼成一串再按空格切。本页统一「一条一个」，便于增删与按行反解析。

### 5.6 反解析（uci 原生条目 → 简写，用于页面首次加载）

**手动区**（只看 `block` 开头的条目，按 list 顺序）：

1. `block tcp port N to T` → `tcp N T`；`block udp port N to T` → `udp N T`。
2. **相邻一对**同 N 同 T 的 `block tcp port N to T` + `block udp port N to T` → 合并成一行 `N T`；不成对的保持单协议写法，不要瞎合并。
3. `block to T` / `block all to T` → `T`（两者语义相同：拦 T 的所有协议端口）。
4. `block port N to T`（无协议带端口，历史遗留/手写配置）→ 输出 `tcp N T` 与 `udp N T` 两行。**必须纠正**：这条规则在 openNDS 里实际跑的是"拦 T 的所有端口"，用户看到 `N T` 会以为只拦了 N。下次「应用」写回时它就变成两条正确规则，隐患自动消失。
5. 其它 `block` 写法（`block from …`、缺 `to`、含未知关键字）→ **原样作为一行输出**，应用时按 §5.4 报错并给行号，由用户改对或删掉。
6. 非 `block` 条目（`allow …`、`passthrough …`）→ **不显示、不动**。本页只认领 `block` 条目，应用时后端读出现有 list、原样保留这些条目（§5.7），避免用户在本页"看不见的东西"被顺手清掉。

**自动区**：`blocklist_fqdn_list` 逐条一行填回域名框；`blocklist_port_list` 全部端口逗号连接填进端口框。两个框各管一件事，**域名框里绝不回填端口**——否则同一份端口在两处各存一份，改一处另一处立刻过期。

### 5.7 应用时的写回

```
# 手动区：读出全部条目 → 分类 → 整份重建（block 在前，其余按原顺序在后）
existing=$(uci -q get opennds.@opennds[0].authenticated_users)   # 先原样留一份
uci delete opennds.@opennds[0].authenticated_users
# 1) 按文本顺序逐条 add_list 本次展开出的 block 条目
# 2) 再把 existing 里非 block 的条目（allow … / passthrough …）按原顺序逐条 add_list

# 自动区：两个 list 全插件只有本页写，整份重写
uci delete opennds.@opennds[0].blocklist_fqdn_list
uci delete opennds.@opennds[0].blocklist_port_list
# 逐条 add_list 域名；端口非空时逐条 add_list 端口

uci commit opennds
```

- **禁止** `uci set` 一把写 list（会降级成单值、静默丢规则）。
- **block 必须排在前面**（决策 #14）：`authenticated_users` 在 `create_client_ruleset()` 里先被整份倒序、再逐条 `insert … index 2`，两步抵消，**链内顺序就是 list 顺序**。追加到末尾等于把 block 排到 `allow all` 后面，规则永远不会命中。
- **重建前先把原有条目完整读出来**（`uci -q get` 一次取全），非 `block` 条目按原顺序原样写回——本页只认领 `block`，用户手写的 `allow` / `passthrough` 一个都不许丢、也不许换位置。
- 手动区文本为空时，写入结果里没有 block 条目，`allow` 条目仍原样保留——本页不提供"清空整个 authenticated_users"的能力，那会把用户的放行规则一起抹掉。
- 任一键写入失败 → 按 §6.2 整体回滚，不留部分结果。

## 6. 后端 API 约定（`opennds-cpd-api.sh access …`）

rpcd `file.exec` 调用，形式 `opennds-cpd-api.sh access <子命令> [参数…]`（本页 page 名固定为 `access`）；stdout 只输出一行 JSON（日志走 stderr / `logger`）；错误统一 `{"ok":0,"error":"…"}`（信封见《整包集成与打包.md》§12）。

| 子命令 | 参数 | 返回 | 行为 |
|---|---|---|---|
| `status` | — | `{"ok":1,"enabled":1,"manual":"example.com\ntcp 443 a.com","auto":"a.com\nb.com","ports":"80,443","bl_mode":"nftset"}` | 读 uci + §5.6 反解析 + §6.4 探测 |
| `validate` | `manual_b64=<base64> auto_b64=<base64> ports=<明文>`（三个独立参数，不要拼成 `a=…&b=…`，口径见《整包集成与打包.md》§12） | `{"ok":1,"manual_rules":[…],"fqdns":[…],"ports":[…],"port_only":0}` 或 `{"ok":0,"errors":[{"line":2,"msg":"…"}]}` 或 `{"ok":0,"error":"port_only"}` | §5.1-§5.5 全部校验，不写任何东西；`port_only=1` 表示"只有端口没有域名"（前端应已被拦，后端兜底） |
| `apply` | 同 validate | `{"ok":1,"restarted":1,"warnings":[]}` 或 `{"ok":0,"errors":[…]}` / `{"ok":0,"error":"port_only"}` / `{"ok":0,"error":"…"}` | validate（有错直接返回，不落盘）→ 备份 → 写三键 → commit → 重启 → 校验进程 |

### 6.1 传输编码
两个 textarea 内容统一前端 `btoa(unescape(encodeURIComponent(text)))` → 后端 base64 解码（无 `base64` 工具时依次尝试 `openssl base64 -d`、`uudecode`，都无则 `{"ok":0,"error":"缺少 base64 工具"}`）。解码后各限 64KB。`ports` 明文，仅允许 `[0-9, 空格]`。

### 6.2 写配置与失败处理
与 WalledGarden / 路由器访问页同一套：
1. `mkdir -p /tmp/zone-router`；按《整包集成与打包.md》§11.3 取锁（`exec 9>锁文件` + `flock -n 9`，**不是** `flock -n /path/to/lock`）。
2. `cp /etc/config/opennds /tmp/zone-router/opennds.bak`。
3. 写 uci；任一步非 0 → **先 `uci revert opennds`** 丢掉本次暂存增量 → 再 `cp` 备份回原位 → **不要再 `uci commit`** → `{"ok":0,"error":"写入配置失败，已回滚"}`。
4. `/etc/init.d/opennds restart`；最多 15 秒轮询（30 次 × 0.5 秒），**`pidof opennds` 有值且 `ndsctl status` 成功**才算就绪。
5. 重启失败 → `{"ok":0,"error":"配置已写入，但 openNDS 未能启动，请检查日志"}`（**不回滚**）。

### 6.3 并发
- 全插件共用 `/var/lock/opennds-cpd.lock`（`flock -n` 非阻塞）：抢不到立即返回 `{"ok":0,"busy":1,"page":"access"}`，前端提示「等待上一步完成，请稍候重试」，不排队。
- `status` / `validate` 是只读接口，**不抢锁**；`apply` 必须抢。

### 6.4 dnsmasq 能力探测（照上游的判法，别自己发明）
```
dnsmasq --version | grep -q ' nftset '   # 支持 nft 集合
dnsmasq --version | grep -q ' ipset '    # 支持旧式 ipset
command -v ipset >/dev/null              # ipset 工具在不在
```
- 有 `nftset` → `"nftset"`；只有 `ipset` 且 `ipset` 工具在 → `"ipset"`（openNDS 会退到旧式 ipset，日志 warn "deprecated legacy ipset"）；都不通 / 命令失败 → `"none"`。
- 每次现算，不缓存到 uci。**不要**用 `dnsmasq --test` 造临时配置探测（nftset 语法是 `/(6|4)#family#table#set`，写错会让页面永远报"不可用"）。

### 6.5 环境兼容
- `uci` 不存在或 openNDS 配置缺失 → `{"ok":0,"error":"未找到 openNDS 配置"}`；`@opennds[0]` 不存在 → 同样报错，**不要**自动创建 section。

## 7. 实现质量要求

- **POSIX sh / busybox**：只用 ash 兼容语法；管道内 `while` 是子 shell（计数/拼串用 `$(…)` 或临时文件回传）；`$'\n'` 不可用。
- **端口校验**：先字符白名单再比较大小；去前导零后再十进制比较。
- **安全**：不 `eval` 拼接用户输入；`add_list` 前转义单引号；域名/IP 严格字符白名单；base64 解码前先查长度。
- **规范**：`uci` 调用带 `-q` 并逐条判断 `$?`；只碰 §1 的三个键。
- **冒烟测试清单**（交付前用 uci/dnsmasq/ndsctl 桩 + 假 `init.d/opennds` 验证）：
  1. `80 192.168.1.20` → 断言 uci 里是 `block tcp port 80 to 192.168.1.20` + `block udp port 80 to …`，**绝不会出现**首词是数字的裸规则（红线一：那会变成 `counter drop` 全断网）；
  2. `tcp/udp 443 example.com` → tcp + udp 两条；`tcp 80,443 a.com` → 两条 tcp；`TCP 443 a.com`（大写）→ 归一化小写后两条，uci 里不出现 `TCP`（红线三）；
  3. `block port N to T` 这种写法**永远不生成**（红线二）；反解析遇到历史遗留的 `block port N to T` 要输出两行并纠正；
  4. `tcp example.com` / `icmp 443 a.com` / `8000-8100` / `*.a.com` / `1.2.3.4/33` 全部整次拒绝且 `line` 正确；
  5. **域名框为空、端口框有值** → 前端保存/应用被拦（无网络请求）；后端 `validate` 返回 `{"ok":0,"error":"port_only"}`；断言此时 uci 里 `blocklist_port_list` **没有被单独写入**；
  6. 域名框 `example.com` + 端口框 `80,443` → `blocklist_fqdn_list` 一条域名、`blocklist_port_list` 两条端口；重启后 `nft list chain ip nds_filter ndsNET` 里能看到 `ip daddr @blocklist tcp dport {80,443} reject`；
  7. **集合非空**：客户端访问过该域名后 `nft list set ip nds_filter blocklist` 必须出现解析结果；为空但规则在 = 永不命中；
  8. **链顶**：`nft list chain ip nds_filter ndsNET` 里 blocklist 的 reject 必须在链首（`nft insert` 的结果），不能落到链尾的 `counter reject` 之后——那等于规则不存在。翻成 `nft add rule` 就一定会掉到链尾，冒烟要专门验这一条；
  9. 域名框里写 `443` / `443 example.com` / `tcp 443 example.com` → 三种都按行拒绝，`line` 正确，且断言 uci 没被写入；
  10. 反解析 round-trip：成对的 tcp/udp 合并成 `N T`；`block to T` → `T`；`allow tcp port 443` 不出现在页面文本里；应用后 `allow` 条目仍在 uci 中且顺序未乱；
  11. **block 优先**：先手工 `list authenticated_users 'allow all'`，再用本页加一条 block，应用后断言 uci 里 block 条目排在 `allow all` **之前**，且 `nft list chain ip nds_filter ndsAUT` 里那条 `counter drop` 在 `counter accept`（allow all）**之前**——排在后面等于没配（决策 #14）；
  12. 空文本 + 空端口 → 只删 `block` 条目、两个 blocklist 列表清空、`allow` 条目保留；
  13. uci 写入失败 → 回滚后配置逐字节一致；重启后 `pidof opennds` 有值**且** `ndsctl status` 成功才返回 ok；
  14. 能力探测桩：`dnsmasq --version` 含 `nftset` → `nftset`；只含 `ipset` 且 ipset 在 → `ipset`；都不含 → `none`；
  15. `enabled=0` 时点应用 → 按《整包集成与打包.md》§11.1 弹确认，取消则整单中止、uci 一个字节不动。

## 8. 集成说明（与其它页面合并成完整插件）

1. **rpcd 模式统一**：所有页面后端都是同一个 `opennds-cpd-api.sh` + JSON（本页 page 名 `access`）；菜单与 ACL 全包各只有一份。
2. **菜单 / ACL**：本页作为「访问限制」菜单项并入（`admin/services/opennds-cpd/access`，排在 Walled Garden 之后、openNDS 设置之前）。ACL **不需要新增条目**——本页只写 `/etc/config/opennds`，已在 ACL 的 uci / file 段覆盖范围内。
3. **uci 键归属**：本页独占 `authenticated_users` 的 `block` 条目、`blocklist_fqdn_list`、`blocklist_port_list`；`authenticated_users` 里的 `allow` / `passthrough` 条目不归本页，读写时原样保留（§5.6 第 6 条、§5.7）。与 WalledGarden（`preauthenticated_users` / `walledgarden_*`）、路由器访问（`users_to_router*`）、豁免页（`trustedmac` / `preemptivemac`）、区域识别（`login_option_enabled` / `themespec_path`）互不重叠。
4. **与 WalledGarden 的语法口径**：两页都是"域名 + 端口"的简写，但**协议位处理故意不同**——本页接受 `tcp/udp`（演示占位符就是这么写的），WalledGarden 页拒绝它。共用解析器时必须把这一条做成参数，别让一页的规则跑到另一页去。
5. **与分发脚本无关**：本页由 openNDS 自身防火墙（`ndsAUT` 链 / `blocklist` nftset）实现，`theme_zone_detect.sh` 读不到也不需要读这些配置，不要加钩子。
6. **保存 / 应用全局红线**：任何页面的「保存」都不得写入会被 openNDS 或分发脚本运行时读取的配置（`/etc/config/opennds`、`zone_blacklist`）。允许写的只有：① 纯暂存缓存 `zone_detect`（无运行时读取者）；② 前端内存快照。本页「保存」= 内存快照（②）；「应用」= 校验 → 写三键 → commit → 重启。
7. **「应用」必须重启**：`authenticated_users` 只在启动时用来建 `ndsAUT` 链，`blocklist_*` 只在启动时生成 dnsmasq 的 ipset 段并建 nftset（`main.c:966`），运行时不重读。⚠️ `enabled=0` 时先按《整包集成与打包.md》§11.1 弹确认，确认后顺手 `enabled=1` 再重启（否则轮询 `pidof` 会白等 15 秒报失败，而配置其实已写入）。
8. **与客户端黑名单的关系**：被拉黑的设备停在门户、从不进入已认证状态，本页规则对它没有意义；反过来，本页也拦不住未认证设备——两者管的是不同阶段的流量，不要写跨页联动。
