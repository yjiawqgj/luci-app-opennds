# 客户端豁免管理 · LuCI 页面开发提示词

> 本文档是 openNDS LuCI 插件中「客户端豁免管理」页面的完整开发规格。同目录 `客户端豁免管理.html` 是**界面事实源**：界面形态（有哪些控件、按钮、文案怎么写）以它为准；功能行为、数据来源、边界条件、异常处理以本文档为准，演示里的模拟数据不代表真实取值。


> 与《区域识别.md》《OpenNDS概览.md》《客户端会话管理.md》同属一个插件包，后续把所有提示词 + 演示 HTML 一起交给开发者整包开发。合并开发时的公共约定见文末「集成说明」。

## 1. 任务总述与页面定位

开发「客户端豁免管理」页面，让管理员对 openNDS 的两条**原生豁免通道**做批量配置期管理：

| 通道 | openNDS 配置 | 机制 | 适用场景 |
|---|---|---|---|
| 信任客户端 | `list trustedmac`（`/etc/config/opennds` 的 `@opennds[0]` 下，可多条） | 客户端**完全跳过认证流程**：启动时直接进防火墙放行规则（`ndsTRU` 链），不弹门户、不统计流量、不受配额/限速/会话约束；openNDS 仍认得它——在客户端列表里给它一个独立状态 `Trusted`（`ndsctl json` 里 `state="Trusted"`），但**不算** `Authenticated` | 打印机、服务器、管理员设备 |
| 授权客户端 | `list preemptivemac`（可多条） | 客户端接入即**自动预认证**，看不到门户页；但仍被 openNDS 管理——流量照常统计、配额/限速/会话时长照常生效 | 员工设备免门户但要统计 |
| 自动预授权开关 | `option allow_preemptive_authentication`（`0`/`1`，缺省 `1`） | openNDS 的"自动预授权许可"开关，但作用范围**只有一个**：客户端**还不在客户端列表里**时，是否允许按 MAC 直接授权（源码 `client_auth()` 里的 `if (!id && config->allow_preemptive_authentication == 1)`）。已经在客户端列表里的客户端不受它影响——`preemptivemac` + 预认证队列每轮 `checkinterval` 都会照常跑、照常消费。本页提供滑块读写它，**不与名单绑定**：关掉不清名单、不删条目、不做备份。其它页面不读、不写它，也不因它改按钮或计数 | —— |

要点：
- **开关和名单是两件事**。名单回答"给谁"，开关回答"客户端还没进客户端列表时允不允许按 MAC 直接授权"。本页只做两件独立的事：读写名单、读写开关。二者在界面上放在一起只是位置关系，代码里不要互相触发——不要因为名单非空就把开关置 `1`，也不要因为开关是 `0` 就清空/隐藏/备份名单。
- `allow_preemptive_authentication` 只在 openNDS 启动时读进内存，**改它必须重启 openNDS**才生效；增删名单不需要重启，但**写完并不等于生效**：主进程每轮调的是 `preemptivemac quiet`，随包的 10.x `libopennds.sh` 只判 `[ -z "$1" ]`，`quiet` 会被当成一个 MAC 名（11.0.0 才修），名单不会被重读——所以本页 `save` 在 commit 后要**主动执行一次不带参数的 `/usr/lib/opennds/libopennds.sh preemptivemac`**，把在线的客户端当场投进预认证队列。
- `preemptivemac` 条目支持带参格式 `mac=AA:BB:CC:DD:EE:FF;sessiontimeout=60;uploadrate=500;…`（单独客户端会话参数）。**本页只增删 MAC，条目里已携带的参数必须原样保留**（参数由概览页的"编辑"功能写入）。
- ⚠️ **新增一条时必须把 6 个参数写全**：
  `mac=<MAC>;sessiontimeout=0;uploadrate=0;downloadrate=0;uploadquota=0;downloadquota=0`。
  因为 openNDS 的 `preemptivemac()` 是 `eval` 逐条解析的，某条缺字段不会按"用全局"处理，
  而是**沿用上一条客户端留下的值**——只写 `mac=XX` 会让这个新客户端莫名其妙套上
  别人的限速/配额/会话时长。写 `0` 才是"用全局/默认值"：`sessiontimeout=0` 回落到
  全局会话超时，四个速率/配额 0 也会在认证时被 `auth_change_state()` 补成全局值
  （`if (client->upload_rate == 0) client->upload_rate = config->upload_rate;`，四个同形）。
  全局这四项出厂都是 0（不限速不限量），所以写 0 等于"跟全局、通常就是不限制"；
  管理员若给全局设了值，写 0 的客户端就会拿到那个全局值，不是单独解限
  （口径见《OpenNDS概览.md》§3.2 的"0 的真实含义"）。
- **两条名单互斥**：同一客户端只允许待在一个列表里（决策 #12）。万一历史配置里已经同时存在（手工改过配置、或别的页面写进去的），openNDS 侧 `trustedmac` 优先、完全跳过认证，界面按「可信任」展示；但下次在本页点「应用」时会报重复并拒绝，逼用户删掉一边。
- 本页与概览页管理**同一组名单**：概览页运行期对单客户端做信任/免认证操作、本页配置期对名单做批量增删，互相可见对方的结果。开关不参与这层同步。

**交付文件**（包名 `luci-app-opennds-cpd`，全插件共用一个后端脚本）：

```
htdocs/luci-static/resources/view/opennds_cpd/exempt.js   # 本页 JS 视图
usr/lib/opennds/opennds-cpd-api.sh                          # 全插件唯一后端脚本（rpcd file.exec，输出 JSON）
```

## 2. 已确认决策表（不要再问，直接照做）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 名单存放 | **openNDS 原生列表**：只读写 `/etc/config/opennds` 的 `trustedmac` / `preemptivemac` / `allow_preemptive_authentication`，不建插件自有配置文件 |
| 2 | 客户端列表数据源 | 只显示 openNDS 配置名单里的 MAC；主机名/IP/网络区域三列在客户端**在线时实时补全**（ndsctl/DHCP 租约/接口反查），离线显示「—」 |
| 3 | 应用行为 | 点「应用」= 校验 → 写 uci + commit。**开关变了必须重启 openNDS**（该选项启动时读进内存）；只增删名单**不必重启**：`trustedmac` 配 `ndsctl trust/untrust` 即时生效；`preemptivemac` 在 commit 后**自己调一次不带参数的 `libopennds.sh preemptivemac`** 立即投递（别指望主进程——它每轮调的是 `preemptivemac quiet`，10.x 脚本把 `quiet` 当 MAC 处理，11.0.0 才修）。⚠️ 需要重启时若 openNDS 处于停用状态（`enabled=0`），先按《整包集成与打包.md》§11.1 弹确认，确认后再顺手 `enabled=1`；只增删名单不重启、也就不必问。真的重启了就按《整包集成与打包.md》§11.1 的判据等就绪（`pidof opennds` 有值 **且** `ndsctl status` 能成功，最多 15 秒 = 30 × 0.5 秒）再返回 `restarted:1` |
| 4 | 行内移除 | **保留行内删除按钮** + 二次确认弹窗（演示里的 `removeClient()`、确认框、`btn tiny danger` 样式已存在）。信任区文字为「移除」，授权区为「删除」 |
| 5 | MAC 编辑方式 | 照演示：平时只显示「添加」按钮，点开进 textarea（每行一个 MAC、批量粘贴），保存/取消；**已保存的名单不在编辑区重复展示，统一看下方表格** |
| 6 | MAC 校验与归一化 | 保存时逐行校验，非法 MAC 拒绝并报错；大小写不敏感，**保存统一为小写冒号分隔**（`preemptivemac()` 的 `dhcp_check` 拿 MAC 去 `grep -w` 比 DHCP 租约，租约里是小写，写成大写这条永远进不了预认证队列）；列表内去重；空白行忽略 |
| 7 | 开关关闭 | 只把 `allow_preemptive_authentication` 写成 `0`。**名单原样保留：不清空、不备份、不删除、不隐藏**；配置区照常显示、照常可编辑；开关下方显示提示「当前未启用自动预授权：尚未出现在客户端列表里的设备不会被自动放行」；toast「授权客户端已关闭，配置已保留」。⚠️ **真实作用要写准**（不要吹成"名单总开关"）：关闭后 `preemptivemac` 与预认证队列照常每轮跑、照常消费，**已经在客户端列表里的设备仍然会被自动登录**；只有还没产生过流量、不在 `ip neigh` / 客户端列表里的设备，才会因为这条限制等自己发一次请求再放行。想真正停用名单只能清空名单本身 |
| 8 | 保存粒度 | 页面内的「保存」（MAC 编辑态）只改前端暂存；只有底部「应用」才写 uci，并按 §2 决策 #3 决定是否重启 |
| 9 | 新增 preempt 条目格式 | **6 参数写全**：`mac=<MAC>;sessiontimeout=0;uploadrate=0;downloadrate=0;uploadquota=0;downloadquota=0`（五个 `0` 都是"跟随全局/默认值"）。绝不允许只写 `mac=XX`（缺字段会继承上一条客户端的参数，见 §1） |
| 10 | 与黑名单互斥 | 本页把某 MAC 加进 `trustedmac` / `preemptivemac` 时，若它同时出现在 `zone_blacklist` 名单里，**整单拒绝、一个字都不写**，返回 `{"ok":0,"error":"blacklisted","macs":[…]}`，前端报「以下客户端在黑名单中，请先到「客户端黑名单」页移除后再添加」并在提示里点出这些 MAC（表格本身不加高亮样式）。**本页不写 `zone_blacklist`**——《整包集成与打包.md》§11.2 规定该名单只由黑名单页与概览页写，三个写入方必然互相踩，所以这里只检测、不修改 |
| 11 | 开关初值 | 页面加载时读 `uci -q get opennds.@opennds[0].allow_preemptive_authentication`：返回 `0` → 显示「已关闭」；返回 `1` → 显示「已启用」；**返回空（键不存在）→ 按 openNDS 官方默认值 `1` 显示「已启用」**。绝不硬编码成关闭——openNDS 出厂默认就是允许自动预授权，用户也可能在装插件前就已经配过免认证名单 |
| 12 | 两个名单互斥（本页内） | 同一个 MAC **只能属于一个列表**：在 `trustedmac` 里就不能在 `preemptivemac` 里，反之亦然。点「应用」时若发现交集：**整单拒绝，一个字节都不写**（不 commit、不重启，也不改开关），把重复的 MAC 全部列出来并在提示里点出这些 MAC（表格本身不加高亮样式），提示「`<MAC>` 同时出现在信任列表和授权列表，一个客户端只能属于一个列表，请删除其中一个后再应用」。由用户决定删哪一边（信任不计流量、免认证计流量，语义不同，插件不替用户选）。前端在发请求前先本地查一遍交集，直接拦下；后端 `save` 也必须有同样的校验，防绕过。**与概览页的区别**：概览页是单点操作（点【可信任客户端】意图明确、结果确定），后端会顺手摘掉该 MAC 的免认证条目；本页是批量编辑，出现重复多为误操作，所以拒绝并让用户自己选，**不静默删任何一边** |

## 3. 页面布局（版式与交互照演示，功能与边界按本文档）

### 3.1 页头
- 标题「客户端豁免管理」+ 小字 `openNDS · LuCI`
- 描述照抄演示：「为指定客户端提供信任或预先授权：可绕过正常认证，或跳过门户认证但保留流量统计与管理。」

### 3.2 信任客户端区块（无开关）
- 标题「信任客户端 Trusted Clients」，描述照抄演示：
  「允许指定客户端绕过 openNDS 的正常认证和客户端流量管理机制，获得无条件访问权限。」
- **MAC 地址列表**（只剩一个入口，不再有灰底展示块）：
  - 平时只显示「MAC 地址列表」小标题 + 「添加」按钮；
  - 点「添加」进编辑态：textarea（占位 `AA:BB:CC:DD:EE:FF`，提示「每行一个 MAC 地址，支持一次输入多个；格式示例 AA:BB:CC:DD:EE:FF」），下方「取消」「保存」；保存成功 toast「MAC 地址列表已保存」；光标自动定位到文本末尾；
  - **已保存的名单不再用灰块重复展示，统一看下面的表格**。两处必须是同一份数据：保存后表格立即按新的暂存名单重渲染（不额外加「未应用」类标记，见 §3.4）。
- **信任客户端列表**（可折叠表格，默认收起）：
  - 「展开列表 / 收起列表」按钮 + 箭头旋转动画 + `aria-expanded` / `aria-controls`；
  - 标题「信任客户端列表」+「共 N 条」，N = **名单条数**，不是在线客户端数；
  - 5 列表格，列宽 26% / 22% / 24% / 16% / 12%（主机名 / IP 地址 / MAC 地址 / 网络区域 / 操作）；MAC 列等宽字体；
  - **一行 = 一条名单记录**：MAC 一定来自 `trustedmac`；主机名/IP/区域是在线时才补得出来的信息，离线三列一律「—」，**不能拿在线客户端列表当行源**（否则名单里 3 条、表格冒出 30 行）；
  - 空表行「暂无客户端记录」（colspan=5）；
  - 每行行尾「移除」按钮（`btn tiny danger`，实心红小按钮）→ 二次确认：「确定要移除客户端「主机名」吗？移除后该客户端将不再享受对应豁免。」（主机名为空时用 MAC 代替）；确认按钮「确认移除」；移除 = **从暂存名单里删掉这一条**（不是只删表格行）→ 重渲染 → toast「客户端已移除」；
  - 分页：每页选项**顺序照演示** `全部 / 10 / 20 / 30 / 50 / 100`（下拉，默认 `10`）；页码条（≤7 页全显，>7 页 = 首页 + 当前±2 + 尾页 + 省略号，当前页高亮 + `aria-current="page"`）；「‹ 上一页 / 下一页 ›」；底注「共 N 条 · 第 x/y 页」；换每页条数回第 1 页。

### 3.3 授权客户端区块（带开关）
- 标题「授权客户端 Pre-emptive Clients」，描述照抄演示：
  「允许指定客户端跳过门户认证，自动获得预先授权，同时保留 openNDS 对客户端的流量统计、配额、速度和会话时长管理。」
- **电源开关**（滑块样式，开=绿色）：标签「已启用 / 已关闭」+ 等宽小字 `allow_preemptive_authentication`；点击翻转 + toast「授权客户端已启用」/「授权客户端已关闭，配置已保留」。
  **点击只改前端暂存**（与两个 MAC 编辑区同一份暂存），真正写 uci 在底部「应用」——
  决策 #8 的"保存只改前端、应用才写盘"对开关同样适用；不要在 toggle 时偷偷写配置，
  否则用户点两下开关、再点取消离开，配置已经被改了。
  - 开关初值按 §2 决策 #11 从配置读，**不许写死**。
  - 它只是 `allow_preemptive_authentication` 这一个 uci 值的读写控件：**关掉不清名单、不删条目、不做备份、不碰其它页面**。
  - 关闭时开关下方显示一行提示：「当前未启用自动预授权：尚未出现在客户端列表里的设备不会被自动放行」。开启时不显示。
    （这句只说真实作用范围；不要写成"下列名单不会生效"——名单对已经在线的设备照常生效，见决策 #7。）
- **下方配置区与信任区完全一致（标题「授权客户端列表」），且不受开关影响：关着也照常显示、照常可添加/删除**。理由：名单是"给谁授权"的清单，开关是"允不允许授权"的许可，关闭只是暂停许可，清单本身仍然可维护。
- 授权区的行内按钮文字是「删除」（不是「移除」），确认文案同步用「删除」/「确认删除」/「客户端已删除」。

### 3.4 底部「应用」
- 表格渲染的**始终是暂存名单**（§3.2 点「保存」后立刻按新名单重渲染），点「保存」就等于把改动记进了暂存，点「应用」才写进 uci；页面上不额外加「未应用」之类的徽标或角标——有没有写盘由「保存 / 应用」这两个动作本身表达，版式照演示保持 5 列。
- 右对齐主按钮；**任一区块**处于 MAC 编辑态（含已关闭的授权区）→ toast「请先保存或取消 MAC 地址编辑」（warn），不执行。关着的授权区也要拦：它的名单在应用时照样会写（§3.3 的配置区不受开关影响），编辑框里没保存的草稿却不在暂存名单里，放过去等于把用户刚敲的那几行悄悄丢掉；
- **应用前先查交集（决策 #12）**：本地比对两个暂存名单，只要有一个 MAC 同时存在，就**不弹任何"已应用"提示、不发请求**，直接拦下并提示：

  > `aa:bb:cc:dd:ee:ff` 同时出现在信任列表和授权列表，一个客户端只能属于一个列表，请删除其中一个后再应用。

  - 多条重复时全部列出（超过 3 条显示前 3 条 + 「等 N 条」）；
  - 不为它新增行内高亮、彩色边框这类视觉状态，表格本身不改样；用户按提示里的 MAC 在两张表里逐行比对即可；
  - 提示用 err（红）色 toast，停留到用户手动关闭或下一次点击（这一条不能 3 秒自动消失，否则用户来不及看是哪条）；
  - 用户删掉任意一边后再次点「应用」，交集消失即正常走 §5。
- 后端 `save` 必须做同样的校验（前端可绕过）：有交集返回 `{"ok":0,"error":"duplicate","duplicates":["aa:bb:…",…]}`，不写任何配置；
- 通过校验后执行 §5 应用流程，成功 toast「配置已应用」。

### 3.5 通用组件与细节
- toast 右下角，ok（绿）/warn（琥珀）/err（红）左边框色，3 秒自动消失；
- 确认弹窗：ESC、点遮罩关闭，焦点样式齐全；
- 640px 断点移动端适配、`prefers-reduced-motion`，照演示 CSS；
- 去掉演示的 foot-note（「前端交互演示…」），真实页面不需要。

## 4. 数据来源映射

| 页面数据 | 来源 |
|---|---|
| 信任名单 MAC（表格行源） | `uci -q get opennds.@opennds[0].trustedmac`（多值多行），一行一条 |
| 授权名单 MAC（表格行源） | `uci -q get opennds.@opennds[0].preemptivemac`，条目是 `mac=XX;sessiontimeout=…;…` 格式时，表格 MAC 列只显示 `mac=` 到第一个 `;` 之间的值，**整条原文必须原样保留**供写回/删除匹配 |
| 自动预授权开关 | `uci -q get opennds.@opennds[0].allow_preemptive_authentication`；**返回空按 `1`**（openNDS 官方默认值） |
| 主机名 | `/tmp/dhcp.leases`（`租约时间 MAC IP 主机名 clientid`）按 MAC 反查，比较前统一转小写 |
| IP 地址 | `ndsctl json` 的 `clients` 里按 MAC 反查（**可信任客户端也在里面**，`state=="Trusted"`）；名单里配了但当前不在线、json 里没有的，用 `ip -4 neigh` 兜底 |
| 网络区域 | 在线客户端：`get_client_interface.sh <mac>` 拿真实接口 → `iw dev` 判定无线 → uci wireless 反查 SSID；有线显示 openNDS 管理接口名（uci `gatewayinterface`，取不到用 `ndsctl status` 的 `Managed interface:`，**只取冒号后到第一个空格那段**——这行可能带 ` - IP address range: …` 后缀）。与区域识别页/概览页**共用同一套接口→区域反查逻辑**，不要各写一份：`get_client_interface.sh` 拿真实接口 → `iw dev` 判无线 → **`iw dev <if> info` 直读 SSID**，读不到才回退 `phyN-apM` 序号映射。`ndsctl json` 的 `clientif` 就是同一个脚本的输出（openNDS 在 C 里调它），可直接用；**它是原样输出、没有编码**（`get_client_interface()` 内部走的 `execute_ret_url_encoded()` 只是历史命名，函数体就是 `popen` + `fread`），mesh 场景带两段（`phy2-ap0 <mesh节点MAC>`），**按空格取第一段**即可；取不到时是空串，退回管理接口按有线处理 |
| 在线判定 | MAC 出现在 `ndsctl json` 的 `clients` 里即为在线（可信任是 `state="Trusted"`，免认证是 `state="Authenticated"`/`AuthBlocked` 且 MAC 在 `preemptivemac` 名单里）。**不要用 `client_type` 判定**——它只在"客户端还没进列表、由预认证流程新建条目"时才是 `preemptive`，正常运行时先被 15 秒扫描收进列表的一律是 `cpd_can`。json 里没有的再用 `ip -4 neigh` 兜底 |

注意：ndsctl 没有名单编辑命令，名单增删全部走 uci；`ndsctl json` 只用于补全在线信息。**开关只由本页读写，不用它去推断名单是否生效，也不要拿名单去反推开关注定值。**其它页面（含概览页）不读它：写 `preemptivemac` 时只判断有没有 DHCP 租约，不看这个开关。

## 5. 后端 API 约定（`opennds-cpd-api.sh exempt …`）

rpcd `file.exec` 调用，调用形式 `opennds-cpd-api.sh exempt <子命令> [参数…]`（本页 page 名固定为 `exempt`）；stdout 输出 JSON；成功 `{"ok":1,…}`、失败 `{"ok":0,"error":"…"}`（信封统一见《整包集成与打包.md》§12，前端 api() 封装负责把 `ok:0` 转 toast）。所有 MAC 出入口都做归一化（**小写冒号分隔**）与格式校验。

| 子命令 | 参数 | 返回 | 行为 |
|---|---|---|---|
| `status` | — | `{"ok":1,"enabled":1,"trusted":[MAC…],"preempt":[条目原文…],"preempt_enabled":0\|1}` | 读 uci 原样返回；preempt 条目保留整条原文（含参数）；`preempt_enabled` 键不存在时返回 `1`（官方默认值）。**`enabled` 是 openNDS 服务的启停开关**（`uci -q get opennds.@opennds[0].enabled`，键缺失按 `1`，口径见《整包集成与打包.md》§11.1），**不是上面那个自动预授权开关**——两者同页出现，字段名只差前缀，实现时别接错：本页只有在"开关值变化需要重启"时才用 `enabled` 判要不要弹《整包集成与打包.md》§11.1 的确认框，`preempt_enabled` 只给界面滑块用 |
| `save` | `trusted_add` / `trusted_remove`（逗号分隔 MAC）、`preempt_add` / `preempt_remove`（逗号分隔 MAC）、`preempt_clear=0\|1`、`preempt_enabled=0\|1` | `{"ok":1,"restarted":0\|1,"added":N,"removed":M}` 或 `{"ok":0,"error":"duplicate","duplicates":["aa:bb:…",…]}` 或 `{"ok":0,"error":"非法MAC: xx"}` | ① 校验 MAC 格式；② **按本次增删算出应用后的两个名单，取交集，非空立即返回 `duplicate` 且不写任何配置**（决策 #12）；②′ 再查 `zone_blacklist.main.mac`，本次要 `added` 的 MAC 只要有命中就返回 `blacklisted` 且不写任何配置（决策 #10）；③ 读当前 uci 列表 → `preempt_clear=1` 时**先**清空整个 `preemptivemac` list（此时忽略本次 `preempt_add`/`preempt_remove`）→ `removed` 里的 MAC **按 MAC 删整条**（不看原文，别页改过参数也删得掉）→ `added` 里的 MAC 若不存在则追加一条 6 参数写全的条目（五个参数全写 `0` = 跟随全局；已存在则跳过，绝不覆盖参数）→ `uci commit opennds` → **运行时同步（这些都不能省，否则界面改了、实际没改）**：`trusted_add` 的每个 MAC 调 `ndsctl trust <mac>`；`trusted_remove` 的每个 MAC 调 `ndsctl untrust <mac>` 再 `ndsctl deauth <mac>`；`preempt_remove` 与 `preempt_clear` 涉及的每个 MAC **先删预认证队列文件、再**调 `ndsctl deauth <mac>`——条目里的 `sessiontimeout=0` 意思是"跟随全局会话超时"（默认 1440 分钟），不是立即失效；只删配置不 deauth 的话，该客户端会一直挂着已认证状态、最多还能上网一整天，用户以为豁免已取消、实际没有；队列文件不删的话，`get_next_preemptive_auth` 下一轮仍会把它投进预认证队列、把它重新认证回来（路径与大小写处理同《OpenNDS概览.md》§3.2）。所有 `ndsctl` 调用**逐个执行、失败只记日志不中断**（客户端不在线、或状态是 `Trusted` 时 deauth 本来就会返回失败，属正常现象）；**`ndsctl` 的 MAC 大小写不能想当然**——uci 里存的是小写（`preemptivemac()` 的 `dhcp_check` 用 `grep -w` 比 `/tmp/dhcp.leases`，租约是小写），但主进程客户端表的 key 不一定同格式，所以每条 `ndsctl trust/untrust/deauth` 要「先用小写、失败再转大写试一次」，两个都失败才记日志。少了这一步会表现成"名单删了、客户端还在线" → **仅当 `preempt_enabled` 与当前值不同时才** `/etc/init.d/opennds restart`，返回 `restarted` 标志。任一 MAC 非法则整体拒绝、不写一半。**开关与名单互不触发**：即使名单为空也不改开关，即使开关为 `0` 也不动名单 |
| `info` | — | 在线补全数据：`{"ok":1,"clients":{"AA:BB:…":{"host":"…","ip":"…","zone":"…","online":1}}}` | 供表格三列补全；查询失败的字段返回空串，前端显示「—」 |

前端在「应用」时**不送最终名单**，而是算两个差集：`added` = 当前集合 − 页面加载时的集合，`removed` = 加载时的集合 − 当前集合。这样别的页面在期间新增或改参的条目不会被本页冲掉（规则见《整包集成与打包.md》§11.2）。暂存名单被整体删空时（用户在编辑区里删空并保存，演示里就是删空整份名单）额外传 `preempt_clear=1`——本页没有独立的「清空」按钮。`info` 在展开列表/刷新时调用。

## 6. 实现质量要求

- **POSIX sh / busybox**：后端脚本只用 busybox ash 兼容语法；注意管道内 while 是子进程（变量累积不能用）、`$'\n'` 不可用、GNU 专有 grep/awk 参数不可用。
- **读-改-写（只动自己改的那几条）**：写之前必须重新读当前 uci，只对本次 `added` / `removed` 提到的 MAC 生效，其它条目和它们的参数一律不动。带参数的 preemptivemac 条目绝不能截断成纯 MAC，也**不能整体重写整个列表**——那样会把概览页刚设的限速/时长冲回 0（规则见《整包集成与打包.md》§11.2）。
- **并发**：`save` 入口先抢全局锁 `/var/lock/opennds-cpd.lock`（`flock -n`，见《整包集成与打包.md》§11.3），抢不到返回 `{"ok":0,"busy":1}`，防止与其它页面后端同时改 `/etc/config/opennds`。
- **健壮性**：uci 值可能含空格/中文（SSID 场景），一律加引号处理；配置文件可能是 CRLF（老版本 luci 写入），解析时去掉 `\r`。
- **冒烟测试清单**（交付前用 uci/ndsctl/iw/ip 桩验证）：空名单、单条/多条 MAC、非法 MAC 拒绝、大小写与短横线归一化（统一小写）、带参 preempt 条目增删后参数保留、**开关初值三态（空→开、1→开、0→关）**、**关闭开关后名单原样保留**、开关值未变时不重启、离线客户端显示「—」、**表格行数 = 名单条数（在线客户端多出来不能进表）**、行内删除同步暂存名单、trusted 客户端 neigh 兜底判定在线、编辑态未保存时应用被拦截、**删除一条被别页改过参数的条目仍能删掉（按 MAC 匹配，不按原文）**、**应用只动本次增删的 MAC，其它条目参数不变**、**两个名单有交集时整单拒绝并返回 `duplicates`（uci 一个字节不动）、删掉一边后可正常应用**、**`trusted_add` 调了 `ndsctl trust`、`trusted_remove` 调了 `untrust` + `deauth`**、**`preempt_remove` / `preempt_clear` 对涉及 MAC 都删了预认证队列文件（大小写各一次）并调了 `deauth`（`sessiontimeout=0` = 跟随全局超时，默认还有 1440 分钟，不 deauth 就一直在线）**。

## 7. 集成说明（与其它页面合并成完整插件）

1. **共享逻辑**：接口→区域反查（`get_client_interface.sh` + `iw dev` + uci wireless）、MAC 归一化校验、ndsctl 状态读取，与区域识别页/概览页共用同一份实现，插件包里只放一份。
2. **rpcd 模式统一**：所有页面后端都是同一个 `opennds-cpd-api.sh` + JSON 输出（本页 page 名 `exempt`）；菜单与 ACL 全包各只留 `luci-app-opennds-cpd.json` 一份（acl 需含 `/etc/config/opennds` 读写、`opennds-cpd-api.sh` exec、`/usr/lib/opennds/cpd/` 目录 read/list——锁文件不需要 ACL，见《整包集成与打包.md》§4）。
3. **「应用」语义**：各页点应用 = 写配置 + commit，**是否重启按操作类型决定**（重启会踢掉全站在线客户端，能免则免）。本页三类数据分三种待遇：`allow_preemptive_authentication` **改了必须重启**（启动时读进内存）；`trustedmac` 增删靠 `ndsctl trust/untrust` 即时生效、不必重启；`preemptivemac` commit 后自己调一次不带参数的 `libopennds.sh preemptivemac` 立即投递（主进程那轮 `preemptivemac quiet` 在 10.x 脚本里不解析名单）、不必重启，但**删除条目必须配合「删预认证队列文件 + `ndsctl deauth`」**（条目默认 `sessiontimeout=0` = 跟随全局会话超时、默认 1440 分钟，不会立刻掉线；队列文件是上一轮已经投进去的，`get_next_preemptive_auth` 不核对名单现况，不删就会在下一轮把客户端又认证回来，路径与大小写处理见《OpenNDS概览.md》§3.2 的口径：`<mountpoint>/ndscids/preemptive_auth/<MAC去冒号>`，大小写各删一次）。各页独立触发，不做全局合并应用。
4. **与概览页的数据一致性（仅限名单）**：本页保存的名单变化会体现在概览页（取消信任后该客户端不会从列表消失，而是 `state` 从 `Trusted` 变回 `Preauthenticated`）；概览页对单客户端的信任/免认证操作会出现在本页列表——两页都展示实时 uci 值，无需额外同步机制。**`allow_preemptive_authentication` 不在此列**：它是本页的开关，概览页既不写也不读它、不因它改变任何卡片计数或按钮可用性；本页也不拿它去限制名单的增删。
5. **uci 键名不冲突**：本页只使用 openNDS 配置的既有选项，不新增配置节；插件自有配置（如区域识别页的缓存）命名空间与本页无关。
6. **保存/应用 全局红线（防"重启被动生效"漏洞）**：任何页面的「保存」都不得写入会被 openNDS 或分发脚本运行时读取的配置（`/etc/config/opennds`、`zone_blacklist`）。允许写的只有两类：① 纯暂存缓存 `zone_detect`（无运行时读取者，生效完全依赖「应用」阶段的写正式配置动作）；② 前端内存快照（不碰文件）。本页「保存」只改前端状态属 ②；`trustedmac` / `preemptivemac` / `allow_preemptive_authentication` 都会被 openNDS 运行时读取，**只在「应用」里写**。三者生效时机不同，实现时别一刀切：`allow_preemptive_authentication` 是启动时读进内存的，**改了必须重启**；`trustedmac` 的 nft 规则在启动时建，改 uci 后要么重启、要么逐条调 `ndsctl trust/untrust` 即时生效；`preemptivemac` 在 commit 后由后端**主动调一次不带参数的 `libopennds.sh preemptivemac`** 立即投递、**无需重启**（主进程每轮调的是 `preemptivemac quiet`，10.x 脚本只判 `[ -z "$1" ]`，`quiet` 被当成 MAC 名，别指望它自动刷）。「应用」= 校验 → 写正式配置 → commit → **仅当 `allow_preemptive_authentication` 的值发生变化时才重启 openNDS**；只增删名单一律不重启（`trustedmac` 可逐条 `ndsctl trust/untrust` 即时同步，`preemptivemac` 靠自己调一次 `libopennds.sh preemptivemac` 立即投递）。任何绕过「应用」直接写正式配置的路径都视为实现错误——否则用户保存后未应用就断电/重启，配置会在开机时被动生效。
