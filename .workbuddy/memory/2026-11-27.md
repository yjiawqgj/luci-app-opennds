## 查证：认证后关停 NDS 几小时，重启会不会判中断超时（用户问，纯查证未改码）
- 结论：**不会因为关停本身判超时弹门户**，官方有 auth_restore 自动恢复机制。
- 链路（v11.2.0 官方源码/脚本）：
  - `main.c termination_handler()`：正常停服先 `auth_client_deauth_all()` 再 `iptables_fw_destroy()`。
  - `src/auth.c auth_client_deauth_all()`：对每个客户端 `auth_change_state(..., FW_MARK_PREAUTHENTICATED, "shutdown_deauth")`；BinAuth 收到 reason=`shutdown_deauth`，在 binauthlog 写一条 deauth 记录，**不删 authlog 的认证行**。
  - `main.c main_loop()` 启动即执行 `/usr/lib/opennds/libopennds.sh auth_restore &`。
  - `libopennds.sh auth_restore()`：遍历 authlog，`session_left = session_end - now`；`sessiontimeout = session_left/60`，若 session_left<0 置空；查 binauthlog 该 mac 最后一条：普通 deauth→不恢复，但若是 **shutdown_deauth→reauth=1**，写 preemptive_auth 文件让 openNDS 恢复认证。
  - `src/auth.c client_auth()`：seconds=60*全局 sessiontimeout；arg3(恢复文件的分钟)>0 才覆盖；空/0/负数都用全局默认。恢复后 session_end=now+seconds，idle 计时由 counter update 重置（停机几小时不算 idle）。
- 复现（/tmp/repro_restore.sh）：原到期12:53，10:00重开→剩余173分钟按原到期恢复；13:30重开(已过原到期)→空→用全局1440重新计满。
- 插件关停走 `NDS_INIT stop`（官方正常停服，触发 shutdown_deauth），purge_client_logs 只在 ndsctl deauth 时调用——单纯开关机不清 authlog，故恢复可行。
- 与手机9:42那件事的关系：若期间确实关过 NDS，重启后应按 shutdown_deauth 自动恢复、不会因关停弹门户；9:42 弹门户更可能是 idle_deauth（夜里闲置>2h）。

- **最终机制定位（最新结论，取代上面的候选）**：openNDS 的 auth_restore 是**一次性纸条**机制：
  - `libopennds.sh auth_restore()` 遍历 authlog，把要恢复的 mac 写成一个文件到 `$mountpoint/ndscids/preemptive_auth/<mac去冒号>`，内容 `mac,sessiontimeout,rate...,base64(auth_restore)`，且只在 NDS 启动时跑一次，不重试。
  - `get_next_preemptive_auth`：cat 文件后 **rm -f**（取走即删）。
  - `src/auth.c client_auth()` 消费时先 `client_list_find_by_any(arg2)`；找不到时只有 `allow_preemptive_authentication==1` 才走 `libopennds.sh clientaddress "$mac"` 查 IP/MAC；返回 "-" 表示客户端不在线 → id=0 → 恢复失败。而纸条已被删，永久丢失。
  - `DEFAULT_ALLOW_PREEMPTIVE_AUTHENTICATION=1`（conf.h）默认开。
  - 所以：昨晚关机时手机已离线（20:52那条 shutdown_deauth 的 client_zone 是空的 `LocalZone:`，是佐证），今早 NDS 启动、手机还没连 WiFi → 纸条被取走时查不到手机 → 恢复失败且不再重试 → 9:42 手机上线被拦到门户 → ndsctl_auth 重新认证。
  - 对比昨晚13:37/13:56/15:50 三次都成功：那时手机在线（preemptive_auth 记录存在），纸条当场被消费成功。今早10:29关→13:03开那次手机在线也成功。
  - `/tmp/repro_preemptive_once.sh` 复现了"纸条取走即删 + 离线查不到 → 恢复失败不重试"。
- 结论：这是 openNDS 官方机制（恢复依赖客户端在恢复窗口内在线），非插件 bug、非 idle_deauth、非会话到期、非人为解除认证。用户说"暂时不要管二次认证"，本次只给分析，未改代码。
