
## 2026-11-25 概览页四开关改版（演示阶段）
- 用户要求：服务、休眠改开关样式；新增「启用」开关对应 `option enabled '1'`；四区顺序改为 运行状态 → 休眠 → 启用 → 服务。标题随开关：休眠开=已唤醒/关=已休眠；启用开=启用/关=未启用。明确「启用」不是运行状态。先出演示、确认后再改代码。
- 产出：`演示/概览开关样式演示.html`（新建，不碰 `汇总/*/*.html` 用户手改文件）。四个独立开关 + 模拟配置镜像 + 其余区块占位。
- 查证结论（本次确认）：
  - openNDS 11.2.0 `conf.c:196` `set_option_str("auto_run", DEFAULT_AUTO_RUN, "0")`，`wait_while_dormant()` 在 auto_run≠1 时不设防火墙/不出门户/dnsmasq 不改 → 进程在跑但流量直通。
  - 插件后端 `nds_autorun()` 缺键回退 1（为兼容 10.3.1），与 11.2.0 官方默认 0 相反 → UI 显示「已唤醒」且按钮不可点、配置里却没有 auto_run，正是用户看到的「未认证却能上网」根因。待改代码时按 11.2.0 口径缺键回退 0。
  - 首次安装不清配置：Makefile postinst 只 chmod/mkdir + 清 LuCI 缓存；root 下无 uci-defaults；`ensure_opennds_conf` 只在缺文件/缺节时补建，所有写入都是逐键增量。该要求当前代码已满足。
  - 待用户确认的设计点：现有「运行状态」开关 doToggle 会写 `enabled` 并配 pending_run 启停；新增「启用」开关也写 `enabled`，两处重复。演示稿按两者独立处理（运行状态=进程、启用=配置键），等用户拍板再动代码。

## 2026-11-25 概览页四开关改版（已落地，用户回复「可以」后实施）
- 前端 `overview.js`：控制区换成 `.ovd-ctrl-grid` 四张卡片，顺序 运行状态 → 休眠 → 启用 → 服务；服务/休眠由双按钮改为绿色滑块；新增启用滑块。标题联动：运行/未运行、已唤醒/已休眠、启用/未启用、已开启/已关闭。重启按钮改为卡内 `.ovd-mini-btn`（保留未运行禁用的旧口径）。
- 运行状态开关不再写 `enabled`：只暂存 `zone_detect.main.pending_run=<want>-<token>`，由 apply_worker 启停进程；`restart_exec()` 也删掉「enabled=0 时偷偷改回 1」的旧逻辑。启用开关走新后端 `overview enabled_set`，只写/回读 `option enabled`，不调 init、不重启；休眠开关改用已有的 `overview autorun_set`（直接写 auto_run，无需刷新页面）。服务仍走 `boot_set`。
- 后端 `nds_autorun()` 缺键回退由 1 改为 0，对齐 11.2.0 官方 `DEFAULT_AUTO_RUN`；这样首次安装未写 auto_run 时页面如实显示「已休眠」，不会再谎称已唤醒（也解释了未认证客户端直通上网）。首次安装不清配置的结论不变，新增写入仍是逐键增量。
- 测试：t19 断言改回退 0；t18 静态断言改查四卡片；新增 `tests/t20_overview_switches.sh` 覆盖回退值、enabled_set 只改一个键且保留原有配置/不调 init、前后端不再写 enabled、四卡片顺序与文案。`sh tests/run.sh` 全量通过（含静态自检，0 失败）。
- 坑：LuCI view 的 `var CSS = '\...'` 是行续字符串，新加的 CSS 注释行也必须带行尾 `\`，否则 `node --check` 失败；已修。
