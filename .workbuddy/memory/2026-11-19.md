## 第71轮（用户六部分反馈：等待流程/改名/特权客户端区域/暂存对接/黑名单 tab）

- **保存并应用后 NDS 变未运行的根因**：原生 `ui.changes.apply()` 在 uci-applied 之后只等 `L.env.apply_display`（5s）就刷新页面，而 post_apply 里的重启+等就绪要十几秒 → 请求变成没人等的孤儿，被 rpcd 约 30s 超时 SIGKILL 在重启中途，服务停在停止态；页面同时卡 busy，概览/区域页出现「等待上一步完成」横幅。**修法不在后端加等待，而在前端接管刷新时机**：common.js 新增 APPLY 控制器（start/show/finish/waitRunning/runDetached/onApplied），点保存并应用时把 `L.env.apply_display` 改成 60，原生弹窗文案持续覆盖成「正在等待 openNDS 完成重启…」，post_apply 返回且 `run_state` 轮询确认在跑才刷新。**要点：`L.env.apply_display` 必须在 uci-applied 事件监听里同步改**（原生紧接着读它），异步改就晚了。
- 后端 `sys_post_apply` 输出 `was_running`/`running`：**应用前本来就停着的不主动拉起、也不要求它运行**（was_running=0 直接成功）。`service_restart` 加 stop→delete_chains→start 兜底；`wait_ready_n n` 让轮数可调，避免撑爆 rpcd 30s。
- **特权客户端区域不显示的根因**：可信任/免认证客户端根本不过门户，ndsctl 里没有会话，旧逻辑只按 ndsctl 记区域 → 只有个别显示。新增 `ex_zone_listed`：关联表→SSID；邻居表且 dev==管理接口→`br-lan（有线）`；WAN 侧/FAILED 邻居不算。
- **右上角「未保存的配置」不出现的根因**：编辑框「确定」/勾选/下拉 change 只改内存。统一改为立即 stageUci/stageListEdit/stageRules/stageExempt。凡"点确定只改内存、等保存并应用才写"的地方都会触发这个反馈。
- 设置页黑名单 tab 是 commit `a66834a`（改官方 blockedmac 机制）时被连带删掉的，本轮恢复；blacklist 门户库映射到 `/usr/lib/opennds/cpd/blacklist/`（与黑名单页共用），无线/有线仍各自 `cpd/default/<型>/`，上传时 blacklist 不做互斥清理。
- 改名落地：menu.d + js 页头 → 网络区域识别 / 特权客户端 / 设置。
- 测试：新增 t14（特权客户端区域判定 6 组），t11 补黑名单 tab，t6 补 was_running/running。commit 681e31c，PKG_RELEASE 5。

## 第72轮（用户五部分反馈：NDS 变停止/原生弹窗/黑名单恢复/全局门户）

- **NDS 变停止的真根因（定案）**：`/etc/init.d/opennds restart` 是 stop+start 两步，procd stop 异步，旧实例十几秒退不干净时 start 已注册新实例 → 两个 opennds 抢端口/链 → respawn 失败停机。上一轮 stop→等3秒→start 兜底反而加剧竞态。**修法：service_restart 顺序化**——stop → 循环等 nds_running 真退出（CPD_STOP_WAIT 默认 45s，超时 kill+再等 5s）→ libopennds delete_chains → start → wait_ready_n(CPD_READY_WAIT=24)。查证依据：rc.common/procd.sh/opennds init（respawn 360 20 15、term_timeout 90）。
- **XHR request timed out**：LuCI ubus HTTP 默认 20s（rpctimeout），rpcd file exec 默认 120s 且只 SIGKILL 直接子进程。修法：post_apply 秒回（dedup/pending_deauth/blockedmac 同步内联），重活丢后台 apply_worker（`sh "$SELF_PATH" apply_worker` 双 fork 孤儿 + flock 单飞 + /tmp/opennds_cpd_apply.state 状态文件），前端每秒轮 `sys apply_state` 到 done:1。
- **弹窗回归原生**：删掉自定义「正在等待 openNDS 完成重启…」全部文案；uci-applied 里把 apply_display=120 防原生 1.5s 刷新抢跑；worker 终态 was_running=1 且 running≠1 才报「未能启动」。**教训：apply_worker 抢锁失败绝不能写 busy:1**——会把运行中 worker 的 done:0 覆盖成完成。
- **黑名单恢复（用户选 A）**：设置页黑名单 tab 回归独立 `cpd/default/blacklist/`（键 portal_blacklist，互斥覆盖，无下拉）；黑名单页改键 `portal_blacklist_sel`（库 cpd/blacklist/）；theme 兜底链 = 页选 → 兼容旧键 → type_default_portal(blacklist) → stock。
- **全局门户**：`cpd/global/`（设置页第 4 tab，互为覆盖，键 portal_global）；区域识别页全局模式改写 login_option_enabled=3 + themespec_path + scope=global；theme 新增 scope=global 分支（portal_global → cpd/global/default.sh → fallback），黑名单客户端仍优先黑名单分支。**修掉一个真 bug：全局分支选出的 portal 被后面 `portal=$(type_default_portal "$zone_type")` 覆盖清空落到 fallback**（无 zone_name 时要 `[ -z "$portal" ] &&`）。
- **CI 教训（执行位）**：api 脚本 git 里 100644，Linux 上 cp 后无执行位，`"$SELF_PATH" apply_worker` Permission denied → worker 不跑、t6 挂。修：git 补 100755（rpcd exec 本就要求）+ 派生改 `sh "$SELF_PATH"`。**Windows 本地 exec 位无意义，本地过 ≠ CI 过**。
- 测试：t6 重写（后台链路 10 例含 NDS_INIT 桩验证 stop start 顺序），t10 加全局 5 例+兜底链 3 例，t11 黑名单回归+全局门户用例，t8 改新键。全部通过 + selfcheck/doc_chk/node --check/dash -n 全过。commit eb93371（含 CI 修复 ad2cc4e），PKG_RELEASE 6。
