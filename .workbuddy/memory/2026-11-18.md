## 关键事实
- AP 卡片全 0 的真根因：openNDS `clientif` 来自官方 `get_client_interface.sh`，**没装 iw 时退回 `ip -4 neigh` 的设备列（br-lan）**，永远对不上 ubus 的 `phyN-apM`。上一轮修的 read 错位只是另一个 bug。权威修法：`ubus call hostapd.<ifname> get_clients` 拿关联终端按 MAC 数。
- 客户端 SSID 同理：先按 MAC 反查关联表（`ws_sta_map`），查不到再退 clientif。
- LuCI `uci.set(conf,sid,opt,null)` 暂存的就是删除增量（run.sh 的 uci.js 链路已验证 del），`CPD.stageUci(...,'opt','')` 即可表达"删配置"。
- hostapd get_clients 的 JSON：MAC 是 clients 对象的键、值是 `{...}`；`"address":"<mac>"` 是值不是键——awk 提取时要看键后是否跟 `{`。

## 第63轮（用户定调：在线客户端以路由器为准，不经过 openNDS）

- 用户定调：「在线 = 正在连接着的客户端」，信任/已认证/预授权都算，数据读路由器、不读 ndsctl。
- 根因确认：ndsctl json 会把客户端留到空闲超时才清，人走了记录还在；openNDS 停了记录为空。按记录算在线要么偏大要么归零。
- 实现：
  - ov_conn 建 CONN_ON（在线 MAC 小写清单）：无线=hostapd 关联表 STA_MAP；有线=clientif==管理接口 且 ip neigh（剔 FAILED）有它；关联表整体拿不到 → 退回按 openNDS 记录算（旧行为）。
  - ov_rows：ndsctl 行按 CONN_ON 判 online；关联表里有、ndsctl 没记录的设备补行（未认证，IP/主机名/接入点照常补）→ openNDS 停了也能看在线。
  - ov_counts：已认证/未认证/免认证只数在线的；可信任仍以 trustedmac 名单为准（离线也数）。
  - 前端 inFilter：online 卡 = online && !blocked（含门户外设备）。
- **大坑**：ndsctl json 的 MAC 键是大写，STA_MAP/前端都是小写——比对前必须 mac_lower。兜底场景就是栽在这（CONN_ON 大写、行小写，grep -qFx 永不命中）。
- t9 重写：断言改为路由器口径；新增场景：离线客户端（记录在人不在）、有线客户端（br-lan+邻居表）、门户外设备（hostapd 有 ndsctl 无）、openNDS 停止（NDS_RUNNING=0，在线=关联表非黑名单数）。

## 第66轮（真机材料回流，抓到两条硬结论）

- 真机材料（Athena）关键点：
  1. `opkg: not found` → 固件是 **apk** 体系（snapshot），要装 CI 的 apk 产物。
  2. `sh /usr/lib/opennds/opennds-cpd-api.sh` → **no such file**：设备上根本没有当前版本的脚本，装的包不是当前构建（解释了"改了几轮没变化"）。
  3. `iw dev phy2-ap0 info` 的 SSID 是 **`ssid \xe4\xba\x92\xe8\x81\x94\xe7\xbd\x91`**（iw 把非 ASCII 字节转义成 \xNN）。拿去和 uci 的「互联网」比永不相等 → AP 卡片匹配不到接口、接入点列退回接口名。**这是真 bug，t12 之前夹具用明文中文所以没暴露。**
  4. hostapd get_clients 键是 **小写 MAC**，值里带大量嵌套对象/数组（rrm、capabilities…），我们的 awk 只认"键后跟 {"，安全。
  5. `iw dev` 用 `phy#2` / `phy#1`，我们的 `^phy#[0-9]+$` + `substr($0,5)` 正确得到 radio2/radio1。
- 修复：`ssid_unescape()`（printf %b，先把 % 转义），`iface_raw_ssid` 统一解码；t12 iw 夹具改成真机原样转义格式（`$'\tssid \\xe4\\xba\\x92...'`）。
- 用户口径补充：**在线只在 openNDS 开启时显示**，关闭时不显示 → `ov_conn` 开头 `[ CPD_RUNNING = 1 ] || return 0`（计数本来就 gated，这样更明确）。
- 文档：《OpenNDS概览》§2.4 增加 iw \xNN 转义条目。
- 教训：测试夹具必须抄真机原样输出（含转义、大小写、嵌套层），"看着一样"的明文格式会漏掉真机 bug。
- commit a43d5bf。
- CI run 44287519367（a43d5bf）离线自检失败：`printf %b` 对 `\xNN` 各 shell 不一致（Ubuntu dash 不当转义、MSYS dash 还会重编码成 UTF-8 双字节；本机 /bin/sh=bash 所以本地全绿）。改为 awk 把 `\xNN` 换算成 POSIX 八进制 `\0OOO` 再 printf %b；t12 iw 桩同时去掉 `$'...'`（同样非 POSIX）。

## 第67轮（CI 红了三次，根因是 awk 方括号字符类）

- CI 失败链：a43d5bf 离线自检红 → 日志要仓库权限取不到 → 给 CI 加 `::error` 注解（注解公开可读），拿到具体失败断言：t12 的 AP iface 为空、计数 0，SSID（来自 uci）正常。
- **真根因**：`[ \t]` 在 awk 方括号里只有 **gawk** 当制表符；Ubuntu 默认 awk=mawk、OpenWrt=busybox awk，都把 `\t` 当字面的反斜杠和 t。iw/ubus 输出全是 tab 缩进 → `^[ \t]*type [ \t]*AP` 永远不匹配 → 运行时接口名推不出来 → `ubus call hostapd.<iface>` 查空 → AP 卡全 0、接入点列退回接口名。**这解释了两轮"真机全 0"。**
- 修：API 31 处 `[ \t]`→`[[:space:]]`；theme_zone_detect.sh 的 ssid_from_if 同样问题 + 补 ssid_unescape；_selfcheck.py 新增静态规则（再写就报错）。
- 另一处坑（上一提交）：`printf %b` 对 `\xNN` 各 shell 不一致 → 改 awk 换八进制 `\0OOO`。t12 的 iw 桩去掉 `$'...'`（非 POSIX）。
- 方法论：**CI 日志拿不到就把失败写进注解**；本地 sh=bash、awk=gawk，跑全绿不代表 CI（dash+mawk）绿灯，shell/awk 可移植性必须用 POSIX 写法。
- commit 8b27514。
- **更正 67 轮结论**：真正让 CI 红的是 **t12 自建桩缺可执行位**（cat 出来的文件在 MSYS 自动带 x、Linux 是 644 → PATH 里找不到 iw/ubus → ap_meta 全 "-" → AP 卡 0）。selfcheck 注解里 tools.ubus=0 / iw 解析到 tests/mock/bin/iw 是铁证，已补 `chmod +x "$S/bin/"*`。
- `[[:space:]]` 替换与 `printf %b` 八进制替换仍然保留（真机 mawk/busybox 的可移植性隐患），但本轮 CI 红不是它们引起的。
- 排障方法论固化：给 CI 失败加 `::error` 注解 + 用例里打印 DEBUG selfcheck，一次就能拿到"哪层为空"。
