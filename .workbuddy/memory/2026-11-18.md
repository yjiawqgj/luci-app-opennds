## 关键事实
- AP 卡片全 0 的真根因：openNDS `clientif` 来自官方 `get_client_interface.sh`，**没装 iw 时退回 `ip -4 neigh` 的设备列（br-lan）**，永远对不上 ubus 的 `phyN-apM`。上一轮修的 read 错位只是另一个 bug。权威修法：`ubus call hostapd.<ifname> get_clients` 拿关联终端按 MAC 数。
- 客户端 SSID 同理：先按 MAC 反查关联表（`ws_sta_map`），查不到再退 clientif。
- LuCI `uci.set(conf,sid,opt,null)` 暂存的就是删除增量（run.sh 的 uci.js 链路已验证 del），`CPD.stageUci(...,'opt','')` 即可表达"删配置"。
- hostapd get_clients 的 JSON：MAC 是 clients 对象的键、值是 `{...}`；`"address":"<mac>"` 是值不是键——awk 提取时要看键后是否跟 `{`。

## 第63轮（用户定调：在线客户端以路由器为准，不经过 openNDS）

- 用户定调：「在线 = 正在连接着的客户端」，信任/已认证/预授权都算，数据读路由器、不读 ndsctl。
- 根因确认：ndsctl json 会把客户端留到空闲超时才清，人走了记录还在；openNDS 停了记录为空。按记录算在线要么偏大要么归零。
- 实现：
  - ov_conn 建 CONN_ON（在线 MAC 小写清单）：无线=hostapd 关联表 STA_MAP；有线=clientif==管理接口 且 ip neigh（剔 FAILED）有它；关联表整体拿不到 → 退回按 openNDS 记录算（旧行为）。
  - ov_rows：ndsctl 行按 CONN_ON 判 online；关联表里有、ndsctl 没记录的设备补行（未认证，IP/主机名/接入点照常补）→ openNDS 停了也能看在线。
  - ov_counts：已认证/未认证/免认证只数在线的；可信任仍以 trustedmac 名单为准（离线也数）。
  - 前端 inFilter：online 卡 = online && !blocked（含门户外设备）。
- **大坑**：ndsctl json 的 MAC 键是大写，STA_MAP/前端都是小写——比对前必须 mac_lower。兜底场景就是栽在这（CONN_ON 大写、行小写，grep -qFx 永不命中）。
- t9 重写：断言改为路由器口径；新增场景：离线客户端（记录在人不在）、有线客户端（br-lan+邻居表）、门户外设备（hostapd 有 ndsctl 无）、openNDS 停止（NDS_RUNNING=0，在线=关联表非黑名单数）。
- 文档 §2.2/未运行时/在线与分类关系/§6 数据来源 同步。演示 HTML 的 counts() 里 online:b.length 是旧口径，需用户手改。
