## 重要更正：区分"NDS 一直开着"与"NDS 关过再开"（用户 08:49 反例）
- 用户反例：NDS 全程开着，手机A 断开5分钟再连，按"只在开机恢复"说法也应重新认证——**用户是对的，之前说法太笼统**。
- 源码（`src/auth.c fw_refresh_client_list()`完整版）确认两种机制不同：
  - **NDS 一直开着**：认证状态留在内存 client list，判断在线只看 `counters.last_updated`（有无流量），不看 WiFi 连接/ARP。断开几分钟远小于 `authidletimeout`(120min) → 记录不删、状态仍 AUTHENTICATED → 连回来 `client_list_find` 查到已认证 → 直接放行，不弹门户。用户推断正确。
  - **NDS 关过再开**：关停把内存 client list 清空（且 auth_client_deauth_all 写 shutdown_deauth）；开机后表空，只有 `auth_restore` 那一次照 authlog 重建；开机时手机A 离线 → 重建失败 → 表一直无A → 切回来弹门户。
- 移除内存记录的超时（非 grace period）：preauth_idle_timeout 直接 client_list_delete；authidletimeout / session_end / quota deauth 经 auth_change_state→client_list_delete。无"客户端短暂消失"宽限。
- 准确表述：**没关 NDS=断几分钟连回照样放行；关过 NDS=只有开机一次重建机会、错过就没**。代码全程未改。

  - 结论：**意外断电 → /tmp 全部清空 → authlog/binauthlog/preemptive_auth 全丢 → 开机 auth_restore 读到空账本 → 无任何客户端可恢复，全部要重新认证**。且断电没走正常 shutdown_deauth，但这已无所谓（账本本身都没了）。
  - 唯一例外：设置了 `log_mountpoint` 指向非 tmpfs（如 /etc 或挂载存储）时日志能留存——但 preemptive_auth 目录仍在 $mountpoint（tmpfs），且官方默认不设此项。
- 复现脚本 /tmp/repro_powercut.sh：graceful 有账本→可恢复；powercut 清空/tmp→账本空→全部重新认证，与源码一致。
- 代码未改。此结论与"正常关NDS再开"的区别：正常关停账本还在、可恢复在线设备；断电账本整个没了、谁都恢复不了。
- 补充（用户09:28问"断电重启和路由器重启是否一样"）：Linux 内核文档确认 tmpfs 内容全在虚拟内存、卸载即丢；系统 reboot 时 tmpfs 重新挂载清空。故**意外断电重启 = 软件 reboot 重启系统**：两者都清空 /tmp、账本全丢、所有客户端重新认证。真正分界是"有没有重启整个系统"，不是"怎么重启"。只有"仅关 NDS 服务、不重启系统"才保留 /tmp 账本、可恢复在线设备。

- 结论：问题分两半——①断电丢账本=设 log_mountpoint 到外接存储；②开机时人不在=客户端上线后补一次 ndsctl auth（需上线检测：DHCP hotplug 或定时轮询）。两者都做才完整。方案未定，按"提问一个一个来"先问用户外接存储前提，代码未改。

- **为什么比轮询/DHCP 钩子好**：客户端发第一个请求→openNDS 同步 add_client(状态 Preauthenticated)→调 header()→主题脚本此刻判据+放行，正好卡在"门户将弹未弹"的点，无竞态、门户根本不弹。客户端请求门户时已在内存表且处于 Preauthenticated，ndsctl auth 直接命中，可靠。
