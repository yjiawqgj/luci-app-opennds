## 会话过期重登后关停卡黄灯 / 红横幅不消失（用户新 BUG，已修）
- 用户现象：浏览器放着到 LuCI 会话过期 → 重登 → 点关闭 → 长时间黄灯 → 红横幅「openNDS 未能完全停止」→ 短暂绿「运行」→ 再变「未运行」，横幅不消失。
- 查证：LuCI `luci.js:notifySessionExpiry` 会话过期弹窗点「Log in…」会整页跳同一 URL（page reload）；`rpc.js` 的 sessionid 在模块加载时固定。根因不是关不掉，而是三段判定：
  1. 后端 `ov_run_set`/`ov_run_state` 只凭状态文件 `done:0` + 300s 时间戳判「忙」。worker 若中途消失（会话过期/rpcd 重启等），残留文件让新点击被当成旧任务、不再派 worker；
  2. 前端 `pollRunState` 只等 `busy=1`，最长 60s 后按当时旧状态弹失败，即使进程后来才停；
  3. `CPD.notify` 走 `ui.addNotification` 常驻横幅，没有节点引用，状态改正后无法撤销。
- 后端修法：新增 `run_state_read()`，`done:0` 之外还要 `pid` 活着（`kill -0`）；刚派发 `pid=0` 给 10s 缓冲。`run_state_write()` 写 worker 自己的 `$$`。`ov_run_state` 与 `ov_run_set` 共用该判定：残留忙碌直接当完成并重新派发 worker；真忙才保留旧目标。
- 前端修法：`pollRunState` 改为以 `j.running === (want === '1')` 为准，连续两次到位（或 `j.done===1`）即收尾；`j.done===1` 或 60s 仍未到位才报失败。`CPD.notify` 返回横幅节点、新增 `CPD.dismissNotice`；概览记住 `runNotice`，新一轮操作先撤旧横幅，`refresh()`/offTimer 复核到状态已到位时自动撤横幅。过渡态跨刷新保留从 90s 缩短到 45s。
- 测试：新增 `tests/t25_run_stale.sh`（残留 done:0 不忙并重新派发、活 pid 仍忙、前端口径静态断言），另加 `tests/sim_runpoll.js` 直接抽取 overview.js 的 finishRun/pollRunState 仿真两种时序（停透无横幅 / 失败可见且可撤），均 PASS。全量 `bash tests/run.sh` EXIT=0「全部通过」（t1~t25，30m38s）。

## 一小时关停再出问题：官方源码查证后的真正根因（用户要求不许猜）
- 用户复现：首次安装运行一小时 → 点关闭一直黄灯 → 红横幅「未能完全停止」→ 开关变绿运行 → 几秒后未运行 → 横幅自己消失。用户明确要求按官方源码/文档改，并可配合测试。
- 官方查证：`modules/luci-base/root/etc/config/luci:12` `option sessiontime '3600'`（正好一小时）；`luci.js:2688-2705 notifySessionExpiry()` 弹登录框并 `raise('SessionError', 'Login session is expired')`；`luci.js:2309-2326 raise()` 给 error 设 `name`；`fs.js:296-304 fs.exec()` 走 rpc `file.exec`；rpcd `file.c:1101-1192` fork+exec 后由管道 EOF 判定结束，超时只 `kill(c->process.pid)` 直接子进程；openNDS 官方 `etc/init.d/opennds` 有 `respawn 360 20 15` 与 `term_timeout 90`，`service_stopped()` 自己等 `pidof` 最多 10 秒再清链。
- 真正根因：`CPD.api` 把 LuCI 的 `SessionError` 压成普通 `{error:'...'}`，丢掉 `name`；一小时会话在 `run_state` 轮询途中过期后，前端按"网络抖动"重试 60 秒，再拿旧 `state.running=true` 弹「未能完全停止」，而 worker 其实已把 NDS 停掉——所以随后变未运行、横幅被自身逻辑清掉。
- 修法：`CPD.api` rejection 保留 `name`；概览新增 `isSessionError()/sessionInterrupted()`，`doToggle`、`pollRunState`、`refresh` 的失败路径遇到 `SessionError` 一律撤黄灯、停轮询、解锁、不弹任何横幅，交给 LuCI 自带登录弹窗，登录后整页重建按真实状态显示。
- 会话时长四选项：设置页 `sessionChanged()` 比较 snapshot 的 `sessiontimeout`，变了才 `askSessionApply()`（原生 `ui.showModal` 遮罩，四行原文案 + 更改/直接应用/全局直接应用/取消）。`stageSessionMode()` 写一次性 `zone_detect.main.session_apply_mode/token`；后端 `session_apply_deauth()` 在 `sys_post_apply` 配置摘要比较前执行：apply 踢 AUTH_CACHE + preemptivemac 中未单独设 sessiontimeout 的；global 连单独设的也改回 `sessiontimeout=0` 再踢；处理完删待办并提交。
