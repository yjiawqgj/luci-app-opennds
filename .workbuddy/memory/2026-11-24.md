## 解除认证失效 —— 根因已定位并脚本复现（待确认后修）
- 现象：运行时对已认证客户端解除认证+保存应用后仍显示已认证；再点解除认证，确认后右上角无「未保存的配置」提示，保存并应用无反应；刷新后短暂未认证又变回已认证。
- 根因（前端 `overview.js` stageAction deauth/untrust/unpreauth 共用 `zone_detect.main.pending_deauth` 这个「应用后即删」的瞬态键，却套用持久名单的去重 `if (arr.indexOf(lm)>=0) return null`）：一旦 post_apply 未消费掉该键（worker 抢锁失败/请求被刷新掐断，common.js 的 onApplied 失败静默吞），键残留 → 第二次对该 MAC 的三段 stageListEdit 全返回 null → 零增量 → 右上角无提示、保存应用 nochange。而 performAction 不检查是否真写增量就 setLocalIdentity 登记「未认证」→ 制造假象。对照 pending_run 用了 `0/1-<时间戳>` 一次性令牌，无此问题。
- 复现：`tests/_tmp_deauth_repro.sh`（已删）用 uci 桩证明 fn('',mac) 产生增量、fn([mac],mac) 返回 null；post_apply 正常会删键；残留时第三次操作零增量。
- 待修清单（子代理全面排查 + 复核）：C1 deauth/untrust/unpreauth 瞬态键去令牌；C2 重启 `pending_restart=1` 固定值同样残留失效（改 `1-<时间戳>`，后端 pending_restart_take 放宽前缀）；C3 ACTION_IDENTITY 缺 authorized 字段导致解除后在线/未认证筛选自相矛盾；C4 exempt 页移除信任/免认证不写 pending_deauth（移除后仍能上网）；C5 common.js onApplied 失败静默吞（无重试无提示）；疑似 S1 未运行时重启按钮实为启动。
- 用户口径要求：改一处必须全链条查关联（卡片在 NDS 开/关两态、标签、无线接入点变化），不能只改被点名的地方。
